## §3 연구 질문

**사용자:** 이 문서를 한 스텝씩 같이 논의하면서 해설해줄 수 있음? 연구 배경과 문제 정의는 넘어가고
3. 연구 질문 파트부터 하나씩 차례대로 시작.

**해설:**

§3 원문은 세 층 구조.
- RQ1 (핵심): 지식 주입(C1/C_kb/C_kb+C1)이 무주입(C0) 대비 방언 품질을 올리나? 특히 RAG 검색이
  few-shot을 넘는 추가 이득을 주나?
- RQ1-보조 (원인 분해): RAG 이득이 거의 없다면 원인이 자원 품질? 주입 방식? 모델 능력?
- Future: 어휘 vs 문법 기여 분해, 상용 API 대비 비용·품질. (본 논문 밖)

RQ1을 두 조각으로 읽어야 함:
1. 주입이 무주입을 이기나? (C1/C_kb/C_kb+C1 vs C0) — 쉬운 질문. 예상대로 "그렇다".
2. RAG가 few-shot을 넘나? (C_kb vs C1, C_kb+C1 vs C1) — 진짜 질문. 논문의 승부처.

우리 결과(§10.1) 대입:
- 질문1: 주입 > 무주입 확인됨.
- 질문2: RAG는 few-shot 못 넘음 (S1 c1≈c_kb_c1, S2는 오히려 하락). "추가 이득 ≈ 0".

비판적 포인트: RQ1 문장이 "RAG가 이기는 것"을 은근히 기대하도록 쓰여 있음. 결과가 반대로 나왔으니
논문에서는 RQ1을 중립적으로 다시 써야 함 — "넘어서는가?"(우열 프레임) → "어떻게 다른가?"(비교 프레임).
결과가 negative여도 질문 자체는 valid해지고 §9 정직성 원칙과 일관됨.

RQ1-보조의 의미: RAG가 진 이유를 네 갈래(자원 품질/주입 방식/모델 능력/검색)로 미리 쪼개 둔 것.
negative 결과가 나왔을 때 "왜?"에 답할 틀. 실제로 §10.2 주입 활용률이 부분 답을 줌(병목=모델 능력).
단, RQ1-보조를 완전히 분리 검증하진 못함 — 자원 품질(RAG DB 미검수)은 confound로 남음(§8 명시).

→ 결정: RQ1을 "넘어서는가" → "어떻게 다른가"로 중립화. (사용자 동의)

## 병목의 의미

**사용자:** 병목이 뭐야? 내가 한 연구는 '모델 능력 = 단편 지식 조합, 적용'을 안한 연구라는 거야?

**해설:**

오해 교정: "조합·적용을 안 한 건 너(연구)가 아니라 모델(Qwen)". 네 연구는 오히려 그걸 측정해낸 것.

병목(bottleneck) = 전체 성능을 제일 크게 제약하는 한 지점.
RAG 파이프라인: [검색] 지식을 찾아 프롬프트에 넣음 → [생성] 모델이 그 지식을 써서 대화 만듦.
병목이 검색 쪽이냐 생성 쪽이냐를 §10.2 주입 활용률로 확인.

측정 결과(C_kb): 어휘 활용률 21%(79% 무시), 규칙 활용률 11%(89% 무시).
→ 검색 쪽 병목 아님(지식은 충분히 넣어줌). 생성 쪽 병목(모델이 넣어준 지식을 안 씀).

"모델이 조합·적용을 못 한다"의 뜻: 준 건 조각 지식(규칙 하나, 단어 하나). 이걸 자연스러운 대화
문장에 엮어 넣는 능력이 Qwen에 약함. 반대로 few-shot(C1)은 완결 대화를 통째로 보여주니 표면 모방만
하면 됨 → few-shot이 이긴 이유.

정리: 병목 = 생성 단계, 모델이 조각 지식을 조합·적용하지 않음. 이건 결함이 아니라 발견 —
"RAG가 왜 졌나?"에 추측이 아니라 숫자로 답한 것(21%/11%).

## 활용률 계산 알고리즘

**사용자:** 실제로 우리가 구한 저 어휘/규칙 활용률 수식은 어떻게 구한거야? 어떤 기준으로 활용률을
정량적인 수치로 뽑을 수 있었음?

**해설:** (`src/eval/injection_utilization.py`)

활용률은 "넣은 형태가 출력에 글자로 나타났나"를 세는 방식. 5단계(시나리오마다):

1. 주입 목록 재현(`injected_forms`): 검색은 결정적이라 저장된 쿼리(smell_type + 위치)로 그때 넣었던
   걸 그대로 다시 검색해 복원. 어휘형 set, 규칙형 set 추출.
2. 형태 정규화(`norm_forms`): "-어예/어여" → `/`,`,`로 쪼개고 → 한글 아닌 문자 제거 → 한글 2자
   이상만. (2자 미만 버림: 1자는 우연 매칭)
3. 출력 텍스트: c_kb 생성 대화에서 민원인 턴만 이어붙임(상담원 제외).
4. 등장 판정(`used`): `{f for f in forms if f in text}` — 주입형이 출력에 부분문자열로 포함되면 "썼다".
5. 비율(micro-average):
   어휘 활용률 = Σ(등장한 어휘형) / Σ(주입한 어휘형).  규칙도 동일.

귀속률(attribution): c_kb엔 등장 & 같은 시나리오 c0엔 없음 / 주입 형태 수. 활용률만 보면 모델이
원래 쓸 단어까지 세므로, c0에 이미 있던 형태를 빼서 "순수 주입 덕분"을 근사.

한계: substring 매칭이라 느슨함(2자+ 필터로 완화). 그래서 이 숫자는 정밀 측정이 아니라 "대략 이만큼도
안 쓴다"는 하한 감각. 과대추정이면 실제 활용은 더 낮아 → 결론이 오히려 더 강해짐.

## substring이란

**사용자:** 이해안되는데? substring이 뭔데? 주입된 문자열 그대로 '공백, 문자' 전부 똑같이 나온 걸
말하는거야?

**해설:**

substring = 부분문자열. "그 글자 조각이 텍스트 어딘가에 연속으로 들어 있나"만 봄. 전체가 똑같아야
하는 게 아님.

```python
form = "어예"
text = "냄새가 나가 미치겠어예 진짜예"
"어예" in text   # True — "미치겠어예" 안에 '어예'가 들어있음
```

- 공백·앞뒤 글자 상관없음(단독 단어일 필요 없음).
- 연속이어야 함("어X예"처럼 중간에 딴 글자 끼면 False).
- 전체 문장이 같은 게 아니라, 작은 조각이 큰 문장 안에 박혀 있나.

활용률에서 `in`을 쓰는 이유: 주입한 건 "어예" 같은 어미 조각인데 출력은 "미치겠어예" 같은 완결 단어로
나옴. 완전일치로 보면 절대 안 걸림 → 조각이 단어 속에 들어갔는지를 봐야 "썼다"를 잡음.

## §3-1 수학적 모델링

**사용자:** 이해했음. 일단 다음 단계로 넘어가줘.

**해설:** (세 덩어리)

① 생성 정의: ŷ = LLM(입력, K_r). 조건별로 K만 달라짐. C0=∅, C1=F_r(고정 few-shot),
C_kb=R(x,K_r)(검색), C_kb+C1=F_r ∪ R. R(x,K_r)의 x가 쿼리 — S1은 x=키워드(사실상 고정주입),
S2는 x=생성된 표준문(진짜 검색). = injection vs retrieval.

② 방언성 지표 D:
```
D = (내 권역 마커 수 − 타권역 마커 누수 수) ÷ 어절 수
```
- M_r+ = 권역 r 방언 마커, M_r- = 타권역 마커(누수 감지).
- 1[m∈ŷ] = 지시함수(마커가 출력에 있으면 1, 없으면 0). ∈는 substring 판정.
- |ŷ| = 어절 수. 길이로 나눠 밀도로 정규화.
- 수식은 +,−를 묶었지만 구현은 방언율(+파트)과 누수율(−파트)을 따로 보고.

③ RQ1 검정: 조건 간 D를 시나리오 짝지은 부트스트랩으로 유의성 판정.
A단계 신뢰성: Sensitivity = (D(ŷ) − D(ỹ)) / D(ŷ). ỹ=교란문(독립 모델이 표준어화·타권역화).
표준어화하면 D가 떨어져야 정상, 떨어진 비율이 민감도(실측 0.872).

## mathcal / 수식 표기 / paired bootstrap / 지시함수·정규화

**사용자:** 1. mathcal이 뭔 뜻이야? mathcal{R}, mathcal{K}가 뭐가 달라? 2. 너가 쓴 수식이 너무
{}, 역슬래쉬, _ 이런걸로 표현되어있어서 사실 읽기가 어렵다... 3. bootstrap은 얼추 이해했었는데,
paired bootstrap은 뭐야? 부트스트랩은 실험 결과가 우연이 아니라는 걸 증명하기 위해 반복실험한다는
의미 아니었어? 4. 지시함수, 정규화 개념 아직 헷갈려

**해설:**

1. mathcal은 꾸민 대문자(폰트). 의미 차이는 글자에 있음. K(지식베이스) = 권역 r의 전체 방언 지식
   창고(어휘+문법 전부). R(검색 결과) = 창고 K에서 쿼리 x로 뽑아낸 일부. R(x,K) = "K에서 x로 검색".
   비유: K=도서관 전체, R=검색해서 빌린 책 몇 권.

2. (이후 LaTeX 대신 평문으로 표기)

4. 지시함수 = 예/아니오를 1/0으로 바꾸는 스위치. 마커가 있으면 1, 없으면 0. 다 더하면 개수.
   정규화 = 길이로 나눠 공정 비교. 대화 A: 마커 5개/100어절 = 0.05, 대화 B: 5개/20어절 = 0.25 →
   B가 방언 진함. 개수는 같아도 밀도로 봐야 보임.

3. 부트스트랩 오해 교정: 실험을 다시 돌리는 게 아님. 이미 가진 데이터(점수 100개)를 복원추출로
   재사용해 "재실험하면 얼마나 흔들릴까"를 컴퓨터 안에서 흉내내는 것.
   paired: C1과 C_kb를 같은 100개 시나리오로 비교. 시나리오별 차이를 먼저 구함
   (시나리오1: C1 0.6 − C_kb 0.5 = +0.1, ...) → 이 차이값 100개에 부트스트랩.
   "paired"의 핵심: 재추출할 때 시나리오 단위로 통째 뽑음(짝 유지). 효과: 시나리오 난이도 차이가
   양쪽에 똑같이 작용해 차이에서 상쇄 → 순수 조건 효과만 남음.

## 시나리오별 차이가 어떤 값인가

**사용자:** 시나리오 별로 차이를 구한다는게 정확히 어떤 값의 차이를 구한다는거야?

**해설:**

각 시나리오의 방언율 점수(D)의 차이. 시나리오 = 입력 슬롯 한 세트. 한 시나리오를 조건마다 각각 생성:
```
시나리오3 (경상) → C1으로 생성한 대화  → 방언율 D = 0.7
                 → C_kb으로 생성한 대화 → 방언율 D = 0.3
차이 = D(C1) − D(C_kb) = 0.7 − 0.3 = +0.4
```
100개 시나리오 전부 하면 "차이" 값 100개. 이게 paired bootstrap 재료.
- 차이가 대체로 양수 → C1이 방언율 높음(few-shot 우세)
- 차이 평균 0 근처 + CI가 0 포함 → 둘 차이 없음

## 방언율 수식

**사용자:** 방언율의 차이를 말하는거네. 방언율 수식은 뭐야?

**해설:** (`eval_conditions.py`)

```
방언율 = 마커+ 적중 수 ÷ 총 어절 수
누수율 = 마커− 적중 수 ÷ 총 어절 수
```
`plus / max(total_words, 1)` (분모 0 방지). D의 +파트=방언율, −파트=누수율. 안 빼고 따로 보고.

"마커+ 적중" 세는 법(S1, `score_surface`): 어절 단위 + 접미(꼬리) 매칭.
1. 민원인 턴을 어절로 쪼갬 → 총 어절 수 = 분모.
2. 각 어절의 꼬리(어미)를 봄.
3. 꼬리가 내 권역 마커면 plus +1, 타권역 마커면 minus +1.
예: "냄새가 나가 미치겠어예" → 어절 3개, "미치겠어예" 꼬리 "어예" 경상 마커 → plus +1 → 방언율 1/3.

S1(`score_surface`) = 생성문 표면의 어절 꼬리만 봄. S2(`score_pairs`) = 표준↔방언 정렬쌍에서 표준
꼬리가 방언 꼬리로 바뀌었나 확인, 분모=쌍 개수.
마커 = AI-Hub 코퍼스에서 뽑은 287개 어미 표지(외부 유래라 조작 불가 → 믿을 수 있는 주 지표).

## §4 과제 정의

**사용자:** §4로 가자. 차례대로

**해설:** (표 빠른 정리 후 두 반전)

반전① S1/S2 역할 뒤집힘: 원래 "S2가 RAG 핵심 경로, S1은 baseline"이었으나 실측이 반박 —
(a) S1이 표면 방언 품질·저누수 우세, (b) RAG는 S2에서 방언율을 오히려 낮춤(S2 c1 .199 > c_kb_c1 .112).
→ S1을 주력, S2를 대조로 재배치. 분석 축 = "품질(S1) vs 검색 정당성(S2) 트레이드오프".

반전② C_kb는 "검색"이 아니라 "고정 규칙 주입": retriever가 종결/조사/경어/높임 어미 규칙을 쿼리와
무관하게 항상 주입(BM25 우회). 고정 규칙 11~26개가 주입 상한(cap≈10)을 채워 BM25 검색분이 잘려나감.
→ 문법 어미는 쿼리가 뭐든 동일하게 고정 주입, 쿼리 기반 검색은 어휘 채널에만 작용.
우리 지표는 어미를 재므로 C_kb의 방언율 효과 = "고정 어미 규칙 주입" 효과이지 retrieval이 아님.
S1의 C_kb를 "RAG retrieval"로 주장하면 과장 → "지식 주입(injection)"으로 서술.

## BM25와 "우회"

**사용자:** 'BM25'로 검색을 우회했다는게 정확히 무슨 말이야? 원래 RAG 검색이 BM25 방식 기반으로
이루어지는데, 우리는 제일 top-k 문서로 이미 고정된 정보를 상위 문서에 둬서...

**해설:** (`kb_retriever.py`)

BM25 = 키워드 기반 검색 랭킹. 쿼리 단어가 문서에 많이 들어있을수록 점수↑, 흔한 단어는 가중치↓(IDF),
길이 보정, 점수순 top-k. 우리는 규칙(어미) 검색에만 BM25(어휘는 정확매칭).

"우회"의 두 겹:
- 1겹: 종결/조사/경어/높임 어미는 존댓말 민원이면 어디에나 쓰이는 일반 규칙 + "요"처럼 초고빈도라
  BM25 점수 바닥(검색 안 걸림). 그런데 항상 넣고 싶음 → BM25 안 거치고 따로 저장(`fixed_rules`),
  검색 시 무조건 먼저 붙임. retrieve 결과 = [고정규칙들] + [BM25 검색결과].
- 2겹(네 직관 맞음): 주입 상한(cap≈10)이 있는데 고정 규칙만 이미 11~26개 → 상한을 혼자 다 채움 →
  뒤에 붙는 BM25 검색분은 잘려나감.
결론: 규칙(어미) 채널에선 쿼리 기반 검색이 실질적으로 죽어 있음. 진짜 검색이 살아있는 건 어휘 채널뿐.

## 연구의 모순? — 지표(어미)와 검색(어휘)의 엇갈림

**사용자:** 우리는 RAG의 기여도를 보려고 했는데, 평가 지표(방언율)는 '어미' 기반이고, RAG 검색은
'문법'과 '어휘'로 나눴는데, '문법'은 어미 변형을 고정 주입으로 주고 '어휘'만 실제 RAG 검색을 수행함.
그럼 평가 지표는 우리가 넣은 고정 주입을 항상 똑같이 판단하는거 아님? RAG라고 볼 수 있는건가?
뭔가 연구의 모순이 있는 것 같은데? '고정 주입'을 하는게 맞는걸까?

**해설:**

정확한 관찰. 두 축이 대각선으로 엇갈림:
| 채널 | 검색 종류 | 지표(어미)가 보나? |
| 문법(어미) | 고정주입(retrieval 아님) | 봄 |
| 어휘 | 진짜 검색(retrieval) | 못 봄 |
검색인 건(어휘) 안 재고, 재는 건(어미) 검색이 아님.

모순이냐 — 주장에 달림:
- "RAG 검색의 기여를 측정했고 도움 된다/안 된다"고 하면 → 모순·과장.
- "지식 공급 방식을 비교했다. 어미축에선 few-shot 지배, 검색 채널(어휘)에선 견고한 효과 확인 못 함"
  → 모순 아님, 정직한 기술. 우리가 §9·§10.3에서 튼 재정립이 바로 이 모순을 피한 것.

"이게 RAG냐?" — 하이브리드. 어휘 채널=진짜 retrieval, 어미 채널=injection. 뭉뚱그려 "RAG"라 하면
느슨함. 정확한 이름 = "검색 요소(어휘)를 포함한 지식 주입".

"고정주입 맞나?" — 엔지니어링으론 맞음(어미는 내용 무관 항상 필요 + 고빈도 기능어라 BM25 검색 불가).
대가: 어미 채널이 injection이 돼 지표가 재는 축에서 retrieval 기여를 귀속 못 함.

기회(구조적 불일치 해석, 강도 (b)로 채택): 방언에서 가장 신뢰 가능한 신호(어미)는 쿼리와 무관한
기능어라 검색 대상이 아니고, 검색 가능한 내용어(어휘)는 방언 실현 기여가 약하고 희소하다.
→ RAG(쿼리 조건부 검색)는 방언 생성과 구조적으로 잘 안 맞는다. §10.1 negative에 구조적 이유 부여.
"해석"으로 명시, 어휘축 견고성 한계 병기. (사용자: (b)로 넣어줘)

## 방언율 수식을 바꿔야 하나 — 검증 추가로

**사용자:** (b)로 넣어줘. 근데 방언율 수식을 이대로 가도 괜찮을지 모르겠어. '방언율' 수식의 한계가
있어서 llm judge를 넣었지만 그래도 우리가 설계한 성능 평가 방식도 최대한 신뢰할만하게 만들고 싶었거든.

**해설:**

결론: 방언율 수식은 바꾸지 마.
1. 결과 본 뒤 수식을 "더 좋게" 고치면 metric shopping 재발. 단순·reference-free·코퍼스 유래(조작
   불가)가 최대 미덕인데 복잡하게 하면 잃음.
2. 지표 신뢰성은 수식이 아니라 검증으로 얻음. 이미 A단계 검증 있음(민감도 .872/특이도 .93).

신뢰성은 앙상블+검증에서: 어미 방언율(표면 밀도, 객관·A단계 검증) + LLM judge(holistic) + 사람평가
(anchor). 서로 다른 걸 재는 셋이 같은 방향을 가리키면 그게 신뢰성(convergent validity). 실제로
§10.2d에서 어미·어휘·judge가 다 같은 방향으로 수렴.

진짜 할 일 = 수식 수정이 아니라 검증 추가: §10.6 사람평가에서 "어미 방언율이 높은 쪽을 사람도 더
자연스럽다고 골랐나?"(방언율↔사람 상관) 계산 = 지표의 criterion/construct validity.

→ 결정: 수식 그대로, §10.6에 "어미 방언율 ↔ 사람 판단 상관" 목표 추가. (사용자 동의, 문서 반영)

파라미터. 모델별 프롬프트 최적화 금지. 시드 고정. → "방언율 차이 = 지식 공급 방식 차이"로 말하려면
다른 건 다 고정해야 confound 제거.

## confound와 C1 대조의 한계

**사용자:** C1 대조가 깨끗하지 않다는게 무슨 얘기지? C1과 C_kb 예문의 텍스트 종류가 다르다고?
'confound'가 무슨 뜻이야? 암튼 이 문제를 해결할 방법이 없어서 우리는 그냥 한계점으로 두고
넘어가려고 했던거야?

**해설:**

confound(교란변수) = 내가 보려는 원인 말고 그것과 같이 움직이는 딴 변수 때문에 진짜 원인을 못 가르는
상황. 예: 아이스크림 판매와 익사가 함께 늘지만 진짜 원인은 더위(confound).

우리 케이스: C_kb − C1로 "검색 지식 vs few-shot"만 보고 싶은데, 두 조건은 최소 세 겹이 다름 —
① 지식 출처(원한 변수), ② 텍스트 종류(완결 대화 vs 단어·규칙 조각), ③ 형태/분량. C1이 이겼을 때
"few-shot 지식이 더 좋아서"냐 "완결 대화가 흉내내기 쉬운 형태라서"냐 엉킴 = confound.

단, reframe이 흡수: 우리 주장은 "few-shot 내용이 본질적으로 우월"이 아니라 "지식 공급 방식(완결 예시는
표면 모방 쉬움, 단편 지식은 조합 필요)". 이 프레임에선 형태 차이가 오염이 아니라 발견하려는 메커니즘.
완전 해결(형태·분량 통제)은 인위적이라, reframe으로 대부분 흡수 + 잔여는 한계로 명시.
→ "해결 못 해서 방치"가 아니라 "주장을 정확히 좁혀 confound를 무력화, 남는 건 밝힌다".

## LLM judge 방식·수치

**사용자:** llm judge 실험은 어떻게 진행했다고 했지? llm judge 결과는 수치적으로? 수식적으로?
어떻게 보여짐?

**해설:** (`judge_conditions.py`, `judge_reliability.py`)

진행: 각 시나리오에서 두 조건의 민원인 발화만 뽑아 블라인드 쌍대 제시.
프롬프트 = "어느 쪽이 더 자연스러운 {region} 방언? 종결어미·어휘가 더 잘 살아있는 쪽. '1' 또는 '2'로만
답하세요." → 점수 없음, 이유 없음, 택1. 순서 무작위(swap = rng.random()<0.5, position bias 통제).
파싱 후 어느 조건이 이겼나 기록(A 이기면 1, B 이기면 0).

수치 = 승률: A 승률 = (A가 선택된 시나리오 수) / (총 비교 수) = sum(v)/len(v).
결과:
```
비교          S1     S2
앵커 c1>c0    97%    89%
핵심 c_kb>c1  20%    43%
```
c_kb>c1 20% → c1이 80% 승(S1 few-shot 압도). S2 43% → 무승부. 앵커 97% → judge가 방언 분별(sanity).
수식적 유의성: 승률이 50%(동등)와 다른가 binomial test. S1 c_kb>c1=20%는 유의(c1 우세),
S2=43%는 p≈0.19로 무승부(유의차 없음).

judge 신뢰성(judge_reliability.py): 조건비교 전에 "정답 아는 문제"로 시험. A단계 교란 재활용 —
원본(방언) vs 표준어화(방언 제거), 원본(맞는권역) vs 타권역화(틀린권역), judge는 원본을 골라야 정답.
정답률 = (원본 고른 횟수)/(총 문제) → 표준어화 98.9%, 타권역화 98.9% = 관문 통과.

한 줄: judge = 점수 아님, 블라인드 쌍대 택1 반복 → 승률, 50%와 binomial 검정. 결과 S1 few-shot 압도,
S2 무승부(→ §10.2b-3이 설명).
