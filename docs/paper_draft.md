# 로컬 오픈소스 LLM과 방언 지식 주입을 활용한 저자원 한국어 방언 악취 민원 대화 합성

> 논문 초안 (draft, 2026-08-10). 대상: 국내 학회/워크샵.
> 결과 = 예비(n=50). RAG DB 검수·n 확대 재실험 예정. 관련연구 서지·연도는 최종 대조 필요.
> 설계 근거는 `research_scope.md`(SSOT)를 따르되, 일정상 RQ2(어휘 vs 규칙 분해)는 제외한 축소본.

## 초록 (Abstract)

지자체 악취 민원은 전화 통화로 접수되며 실제 발화는 지역 방언과 구어체다. 이를 자동 처리하려면
방언 통화 데이터가 필요하나, 개인정보와 수집 비용 때문에 실제 방언 민원 데이터는 거의 없다.
본 연구는 **상용 API에 의존하지 않고 로컬 오픈소스 LLM(Qwen3.6-27B)** 만으로 5개 권역(경상·전라·
충청·강원·제주) 방언 악취 민원 대화를 합성하는 방법을 제안한다. 로컬 모델의 방언 지식 결핍을
보완하기 위해 웹 자원으로 구축한 방언 지식(어휘·문법 규칙)을 프롬프트에 주입하고, 지식 공급
방식(무주입 C0 / 고정 few-shot C1 / 지식 검색·주입 C_kb / 결합 C_kb+C1)을 독립변수로 비교한다.
직접 생성(S1)과 2단계 변환(S2) 두 파이프라인을 함께 분석한다. 인간 평가가 어려운 상황을 전제로,
AI-Hub 코퍼스에서 추출한 방언 종결어미 표지를 이용해 **방언율(dialectness rate)** 과 **타권역
누수율(leakage rate)** 을 자동 산출하는 진단 지표를 설계하고, 채점기와 독립인 참조 모델(Claude)
기반 합성 교란으로 지표의 민감도·특이도를 검증한다. 5권역 n=50 실험에서, 두 파이프라인 모두
**few-shot(C1)이 방언성의 주 동력**이며 RAG DB 검색을 얹어도(C_kb+C1) C1을 안정적으로 넘지 못하고,
RAG DB 단독(C_kb)은 약했다. 직접 생성(S1)이 2단계 변환(S2)보다 누수율이 낮았다. RAG DB의 제한적 기여는
웹 자원을 일일이 검수하지 못해 RAG DB가 RAG에 쓰기 좋은 형태로 정제되지 못한 데서 비롯한 것으로
보인다. 또한 종결어미 중심 지표는 강원처럼 어휘·음운 중심 방언을 과소평가하며(제주는 존댓말
표지 보완으로 완화), 로컬 모델은 한국어 전용 지시에도 40~50%의 대화에서 중국어·영어를 혼입하는
한계를 보였다.

## 1. 서론

- **문제 배경·동기.** 지자체 악취 민원은 주로 전화로 접수되고 실제 발화는 방언·구어체라 일반
  STT·키워드 추출이 잘 안 될 수 있다. 이를 개선하려면 방언 통화 데이터가 필요하나, 실제 방언
  악취 민원 데이터는 개인정보·수집 비용 때문에 거의 없다. → 합성 데이터가 현실적 대안이다.
- **본 연구 범위.** 본 연구는 **방언 대화 "텍스트" 합성과 그 평가**에 한정한다. STT·키워드 추출
  개선은 동기일 뿐 직접 실증 대상이 아니며(downstream=future work), 음성(TTS)도 범위 밖이다.
- **상용 API의 한계.** 상용 LLM(Claude, GPT)은 방언을 잘 살리지만, 호출 비용, 민원 데이터의 외부
  전송(프라이버시), 그리고 모델 버전·정책 변경에 따른 **장기적 재현성** 문제를 안는다.
- **로컬 대체와 가설.** 로컬 오픈소스 모델은 방언 내재 지식이 약해 품질 저하가 예상된다. 본 연구는
  **웹 자원 기반 방언 지식 주입(few-shot / 검색)이 이 결핍을 보완하는지**를 검증 대상(가설)으로 둔다
  (해결책 단정이 아님).
- **평가의 문제.** 방언 화자 인간 평가는 비용·섭외가 어렵다. 인간 평가 부재 시에도 조건 간
  상대 비교가 가능한 **자동 진단 지표**가 필요하다.
- **기여 (Contributions).**
  1. 상용 API·파인튜닝 없이 로컬 LLM + 방언 지식 주입으로 5권역 방언 악취 민원 대화를 합성하는
     파이프라인(S1 직접생성 / S2 2단계 변환)과 지식 공급 조건 설계.
  2. 5권역(경상·전라·충청·강원·제주) 방언 악취 민원 대화 데이터셋.
  3. **채점기와 독립인 참조 모델 기반 합성 교란으로 민감도·특이도를 검증한** reference-free 자동
     진단 지표(방언율·누수율).

## 2. 관련 연구

- **한국어 방언 자원·NLP.** 방언·변종 벤치마크에서 한국어 변종이 특히 저조함을 보인 DialectBench
  (arXiv 2403.11009), 한국어 이해 벤치마크 KLUE·한국어 지식 평가 HAE-RAE(2309.02706)·CLIcK(2403.06412).
- **LLM 기반 합성 데이터 생성(저자원·대화).** 저자원 대화 합성 DiaSynth(2409.19020), 저자원 언어
  데이터 생성 전략 평가(2506.12158, "타깃언어 예시+LLM 수정"이 강력) — 본 연구 few-shot 우위와 상통.
- **RAG·제어 생성.** RAG 원논문 Lewis et al.(NeurIPS 2020), RAG 서베이(2407.13193), 저자원 방언에
  RAG를 적용한 Bengali 표준→방언 번역 비교(2512.14179).
- **방언 식별과 표지 기반 평가.** 방언 판별에서 종결어미·어휘 표지를 사전으로 활용하는 접근.
  본 연구 지표의 뿌리이며, 새로운 방법이라기보다 특정 도메인·목적에 맞춘 적용임을 명시.
- **가장 근접 — DIA-REFINE** (arXiv 2511.06680). 한국어 방언 LLM 변환 + 방언성 자동 지표
  (DFS/TDR, 학습된 분류기 기반). 본 연구와 목적이 겹치므로 **자동 지표는 신규성 주장 없이 인용**한다.
  차별점: (1) 단문 번역 vs **다중턴 대화 생성(악취민원 도메인)**, (2) 그들은 KB·RAG 없음 vs 본 연구
  **어휘+문법 KB 검색·주입 비교**(few-shot 대비 RAG 효용), (3) 분류기 지표 vs **학습 불필요 어미 마커**,
  (4) 3권역 vs **5권역·로컬 전용**.

## 3. 과제 및 데이터

### 3.1 과제 정의
- 도메인: 악취 민원 상담 통화. 상담원(표준어) ↔ 민원인(방언).
- 입력: 구조화된 키워드 슬롯 — 민원인 위치, 냄새 종류, 강도 변화, 지속 시간, 원인 추정 지역.
- 출력: 8~10턴 대화(첫·마지막 턴은 상담원). 첫 상담원 발화는 고정 인사 형식.
- 권역: 경상·전라·충청·강원·제주 (5권역, 모두 RAG DB 보유).

### 3.2 방언 지식베이스 (RAG DB)
- **어휘(vocab):** 웹 사전 스크래핑 → LLM으로 `{standard, dialect, pos}` 구조화. 검색은
  표제어 정확 매칭.
- **문법 규칙(rule):** 방언학 문법서·논문 기반 `standard_form → dialect_form` + 설명. 검색은
  형태소 기반 BM25.
- **5권역 모두 구축.** 제주는 어휘 `jeju_vocab_v2`(13,508개, 지명 유래 오염된 final은 제외) +
  문법 30개(구조화 폼 없는 53개는 자동 제외)를 편입했다. ⚠️ 제주 문법은 직접 웹 검색으로 수집한
  정보(비학술 출처 포함) → 투고 전 학술 근거 보강 필요(8절).
- 라이선스: 원자료(단어 목록)는 비공개, 방법·스크립트만 공개해 재현성 확보.

### 3.3 평가용 방언 표지 추출
- AI-Hub 2인 발화 코퍼스에서 (표준 종결어미 → 방언 종결어미) 변환쌍을 추출.
- 필터: 총빈도 ≥ 8, 권역 변별력(주권역 집중). 자동 추출 후 존댓말 표지 수동 보완 → **현재 78개**.
- 수동 보완(자동 추출이 놓친 존댓말 종결형): 충청 유/슈, 강원 믄, 경상 예, 전라 당께(요)/랑께(요)/
  여라/겄소/부러, 제주 수다/마씸/쿠다/허우다. (수동 개입은 한계로 명시 — 8절)

## 4. 생성 방법

### 4.1 두 생성 전략
- **S1 (직접 생성):** 키워드 슬롯 → 조건별 지식 주입 → 방언 대화 직접 생성. 쿼리(중간 표준어
  텍스트)가 없으므로 엄밀히는 **권역 지식 주입(injection)** 이며 질의 기반 검색은 아니다.
- **S2 (2단계 변환):** 키워드 → 표준어 대화 생성 → (표준어 민원인 발화를 쿼리로) 어휘·규칙
  검색·주입 → 방언 변환. 쿼리가 있으므로 **질의 기반 검색(retrieval)** 이 성립한다.
- 두 전략은 상호 배타가 아니라 서로 다른 질문에 답한다(6절 트레이드오프 분석).

### 4.2 지식 공급 조건 (독립변수)

| 조건 | 주입 내용 | 분리하는 것 |
|---|---|---|
| C0 | 없음 (금지규칙만) | 기준선 (진짜 zero-shot) |
| C1 | 고정 few-shot 예시 (질의 무관) | "예시가 있어서" 생기는 효과 |
| C_kb | RAG DB 어휘+규칙 검색·주입 | 지식 검색의 효과 |
| C_kb+C1 | RAG DB + few-shot 결합 | 두 지식원의 결합 효과 |

- C1을 반드시 포함하는 이유: 품질 향상이 "검색 때문"인지 "예시가 있어서"인지 분리하는 유일한
  대조군.
- 공정 비교를 위해 동일 키워드·프롬프트 구조·출력 형식·temperature·max_tokens·검색 파라미터를
  고정한다.

### 4.3 프롬프트 설계
- 한국어 전용 강제(한자·중국어·일본어·영어 금지), 민원인 존댓말 유지, 상담원 표준어 유지.
- 타권역 어미 누수 금지 목록과 혼종어미 금지 목록을 명시.
- 발화자 라벨 형식("상담원:/민원인:")을 강제 — 라벨 누락 시 자동 채점이 불가하기 때문.

## 5. 자동 진단 지표

### 5.1 방언율과 누수율 (B단계)
권역 $r$의 생성문 $\hat{y}$에 대해:

$$D(\hat{y}, r) = \frac{1}{|\hat{y}|}\Big(\sum_{m \in M_r^+}\mathbb{1}[m \in \hat{y}]
- \sum_{m \in M_r^-}\mathbb{1}[m \in \hat{y}]\Big)$$

- $M_r^+$: 권역 $r$의 방언 표지(+), $M_r^-$: 타권역 표지(−), $|\hat{y}|$: 어절 수.
- **방언율** = 타깃 표지 적중 / 총어절, **누수율** = 타권역 표지 적중 / 총어절.
- S1: 민원인 발화 어절의 표면 접미 매칭. S2: 표준↔방언 정렬 어절쌍(difflib) 기반 매칭.
- 오탐 방지: 1자 표지는 화이트리스트 + 앞 음절 무받침 조건(예: "윤활유"의 '유' 차단),
  표준어 동형 표지("어서","가지고") 제외.

### 5.2 지표 신뢰성 — 합성 교란 (A단계)
인간 라벨 없이 B 지표의 신뢰성을 실증하기 위해, 정상 생성문에 알려진 오류를 통제 주입한 교란문
$\tilde{y}$을 만들고 지표가 그 변화를 감지하는지 측정한다.

$$\text{Sensitivity} = \frac{D(\hat{y}, r) - D(\tilde{y}, r)}{D(\hat{y}, r)}$$

두 교란은 각각 민감도와 특이도에 대응한다.
- (표준어화, 민감도) 방언 → 표준어. 방언율이 떨어져야 지표가 방언 제거에 반응한 것.
- (타권역화, 특이도) 소스권역 → 타권역. 소스 방언율이 떨어지고 누수율이 올라야 타권역 오염을
  잡은 것.

**교란기의 독립성 (핵심).** 교란을 채점기(어미 사전)로 만들면 순환논리가 된다. 이를 피하기 위해
**교란은 채점기와 독립인 참조 모델(Claude)에게 시킨다.** 생성 파이프라인은 로컬 Qwen 전용이라는
논문 요지와 별개로, Claude는 **평가용 독립 교란기로만** 사용한다(시스템 구성요소 아님). 보조로,
어미 사전 기반 교란(자기 사전으로 자기를 시험 → 순환성 존재)을 일관성 검사로 병기한다.

- **포지셔닝:** 본 지표는 조건 간 상대 비교용 진단 도구이며 절대적 방언 품질 척도가 아니다.

## 6. 실험

### 6.1 설정
- 모델: Qwen/Qwen3.6-27B (vLLM 로컬 서버). 상용 API 미사용(Claude는 6.5 지표 검증용으로만).
- 규모: n=50 시나리오(권역당 10개), 5권역 × 4조건. 시드 고정.
- RAG DB: 5권역 모두 구축(제주는 어휘 v2·문법 30개를 편입해 실제 RAG DB 조건으로 실험). 제주 어휘 final은
  지명 유래 오염이라 제외하고 v2만 사용.
- S1/S2 동일 시나리오·시드 사용해 공정 비교.

| 전라 | 0.002 / 0.009 | 0.058 / 0.001 | 0.035 / 0.002 | **0.059** / 0.006 |
| 충청 | 0.009 / 0.000 | 0.087 / 0.002 | 0.037 / 0.001 | **0.099** / 0.004 |
| 제주 | 0.000 / 0.013 | **0.108** / 0.004 | 0.000 / 0.021 | 0.102 / 0.006 |
| 강원 | 0.000 / 0.010 | 0.000 / 0.006 | 0.002 / 0.003 | 0.000 / 0.004 |
| **전체** | 0.003 / 0.007 | **0.071 / 0.003** | 0.018 / 0.007 | 0.070 / 0.004 |

- 강원을 제외한 4권역에서 지식 주입이 방언율을 크게 높인다. 그러나 **최상위는 C1과 C_kb+C1이
  사실상 동률**(전체 0.071 vs 0.070)이며, RAG DB를 few-shot에 얹어도(C_kb+C1) C1을 안정적으로
  넘지 못한다 — 전라·충청에서는 C_kb+C1이 근소 우위, 경상·제주에서는 C1이 우위다.
- RAG DB 단독(C_kb)은 C0보다는 높으나(0.018 vs 0.003) few-shot에 크게 못 미친다.
- 전체 랭킹: **C1 ≈ C_kb+C1 ≫ C_kb > C0**. (0.071 vs 0.070의 차는 n=10에서 유의하지 않음 →
  6.7 통계 참조.)

**표 2. S2(2단계 변환) 권역×조건 — 방언율 / 누수율.** (권역당 n=10)

| 권역 | C0 | C1 | C_kb | C_kb+C1 |
|---|---|---|---|---|
| 경상 | 0.000 / 0.049 | **0.214** / 0.027 | 0.052 / 0.000 | 0.164 / 0.022 |
| 전라 | 0.039 / 0.020 | **0.090** / 0.019 | 0.034 / 0.015 | 0.042 / 0.007 |
| 충청 | 0.211 / 0.000 | **0.405** / 0.000 | 0.148 / 0.006 | 0.245 / 0.005 |
| 제주 | 0.017 / 0.034 | 0.031 / 0.023 | 0.007 / 0.047 | **0.038** / 0.013 |
| 강원 | 0.010 / 0.080 | **0.212** / 0.000 | 0.017 / 0.006 | 0.054 / 0.000 |
| **전체** | 0.032 / 0.040 | **0.157 / 0.017** | 0.044 / 0.019 | 0.098 / 0.010 |

- S2에서는 **few-shot(C1)이 뚜렷하게 지배적**(0.157)이고, RAG DB를 얹은 C_kb+C1(0.098)은 오히려
  C1보다 낮다. RAG DB 단독(C_kb 0.044)은 C0(0.032)보다 소폭 높은 정도다.
- 전체 랭킹: **C1 > C_kb+C1 > C_kb > C0**. S1과 마찬가지로 few-shot이 핵심 지렛대다.

> **주의(분모 차이):** S1 방언율의 분모는 민원인 발화 전체 어절, S2는 표준↔방언 정렬에서 실제로
> 치환된 어절쌍이다. 따라서 S1과 S2의 방언율 **절대값은 직접 비교할 수 없고**, 각 파이프라인
> **내부의 조건 순서**와 **누수율**로만 해석한다.

### 6.3 S1 vs S2 트레이드오프
- **공통 결론 — few-shot 지배:** 두 파이프라인 모두 few-shot(C1)이 방언성의 주 동력이며, RAG DB를
  얹어도 C1을 안정적으로 넘지 못한다. RAG DB 단독은 약하다. 즉 **로컬 모델의 방언 유도에는 검색된
  지식 조각보다 완결된 대화 예시가 더 강한 신호**다.
- **누수·안정성:** S1이 누수율이 낮고(전체 C1 누수 0.003) 조건 반응이 안정적이다. S2는 누수율이
  전반적으로 높다(전체 C0 누수 S2 0.040 vs S1 0.007) — 표준어→방언 변환 압력이 타권역 오염을
  키운다.
- **검색 정당성:** 반대로 S2만이 쿼리(중간 표준어 텍스트) 기반의 실제 검색을 성립시킨다. S1의
  C_kb는 쿼리가 없어 권역 지식 통째 주입에 그친다.
- **결론적 함의:** 표면 방언 품질과 낮은 누수가 목표라면 **직접 생성(S1)**이 우세하다. 어느
  파이프라인에서도 **RAG DB 검색이 few-shot을 넘어서는 이득을 보이지 못했다** — 이는 잘 정제된
  방언 예시의 가치와, 뒤에서 논의할 RAG DB 자원의 형식·품질 한계(8절)를 함께 시사한다.

### 6.4 권역별 분석
- **경상·충청·전라:** 지식 주입 효과가 뚜렷. C1과 C_kb+C1에서 방언율 0.06~0.10대. 충청·전라는
  C_kb+C1이 C1을 근소하게 앞서 RAG DB가 소폭 보탬이 되나, 경상은 C1이 더 높다.
- **제주:** 제주 RAG DB(어휘 v2 13.5k·문법 30개)를 편입해 **진짜 RAG DB 조건**으로 측정했다. 다만 C_kb
  단독은 여전히 ≈0이고, few-shot(C1 0.108)·결합(C_kb+C1 0.102)에서 방언율을 확보한다. 즉 제주도
  다른 권역과 같은 "few-shot 지배" 패턴을 따른다. **주의:** 제주 방언율은 존댓말 표지(-수다/-마씸/
  -쿠다 등)를 마커에 보완한 뒤에야 제대로 측정됐다(보완 전 0.04 → 후 0.10). 이는 제주 저측정이
  생성 실패가 아니라 **지표의 존댓말 표지 부족** 때문이었음을 보여준다.
- **강원(지표 맹점):** S1에서 전 조건 방언율 = 0. 강원 방언은 종결어미 변화보다 어휘·음운
  변화(아이들→아들, 같아→같애)가 특징이라 어미 표지 기반 지표로 포착되지 않는다 — 생성 실패가
  아니라 지표의 구조적 한계다(정성 예시로 방언 실현 확인). 제주와 달리 표지 보완으로도 해소되지
  않는, 방언 유형 자체의 문제다. (S2에서는 정렬쌍 매칭이 일부 어미(예: -아요→-소)를 잡아 C1
  0.212로 측정됨.)

**정성 예시.** 실제 생성 대화 발췌(민원인 발화)로 정량 결과를 뒷받침한다.

- (성공, S1 충청 C_kb+C1) "세종에서 전화 **혀는디유**. 대창빌라 맞은편에 사는데 유난히 고약한
  냄새가 나서 전화**혔슈**." → 충청 존댓말 방언형(-는디유/-혔슈)이 자연스럽게 실현됨.
- (성공, S1 경상 C_kb+C1) "접착제 냄새 나는 **기라예**. 코가 슬슬 따가워질 지경**입니더**." →
  경상 종결형(-기라예/-입니더) 실현.
- (지표 한계, S1 강원 C_kb+C1) "전화**했잖소**. … 거름 냄새**래요**. … 있**잖우야**. 코가 다
  **따갑소**." → 강원 방언형(-잖소/-래요/-우야/-소)이 뚜렷하나 방언율 지표는 0으로 측정됨.
  이는 해당 표지가 1자(-소)이거나 표지 목록 미포함이기 때문으로, **생성 실패가 아니라 지표의
  구조적 한계**임을 보여준다.
- (타권역 누수, S2 경상 C0) "접착제 냄새가 **나가유**. … 언제부터인지 기억이 안 **나유**." →
  경상 대화에 충청 종결형(-유)이 혼입. 지식 주입 없는 2단계 변환에서 누수가 두드러진다.

### 6.7 통계 검정 (부트스트랩, 시나리오 재표집 n=50)
시나리오를 재표집 단위로 삼아(B=10,000) 조건별 방언율의 95% CI와, 같은 시나리오의 짝지은(paired)
차이를 검정했다. 값은 시나리오 평균(macro-average)이라 표1·2의 풀링(micro) 값과 소폭 다르다.

## 7. 논의
- **few-shot이 지식 주입의 핵심 지렛대다.** 두 파이프라인 모두에서 C1의 효과가 크고 일관적이며,
  RAG DB를 얹은 C_kb+C1도 C1을 안정적으로 넘지 못했다. 이는 로컬 모델에 방언을 유도할 때, 검색된
  어휘·규칙 조각보다 **완결된 대화 예시가 더 강한 신호**임을 시사한다.
- **RAG DB 검색이 왜 약한가 — 원인은 단정 불가(복수 가설).** 검색 이득이 작은 원인은 하나로
  귀결되지 않는다. 최소 다섯 가지를 구분해야 한다: (1) **RAG DB 품질·형식**(항목별 검수를 못 해
  표준형 오염·빈 폼 다수 — 제주 어휘 final 오염, 문법 83개 중 53개 폼 결측), (2) **정보량 부족**
  (도메인 커버리지), (3) **검색 방식**(정확매칭·BM25·top-k·쿼리 구성), (4) **주입 방식**(프롬프트
  삽입 형식), (5) **모델 활용 실패**(few-shot이 더 강한 신호라 검색 지식을 무시). 본 실험 데이터로는
  이들을 분리하지 못한다. (1)이 현재 가장 유력한 가설이나 **확정 결론이 아니며**, 검수로 (1)을
  제거한 뒤에도 이득이 없으면 (2)~(5)를 점검해야 한다(future work).
- **파이프라인 선택.** 표면 방언 품질과 낮은 누수가 목표라면 직접 생성(S1)이 우세하다. 2단계
  변환(S2)은 쿼리 기반 검색을 성립시키는 이론적 장점이 있으나, 본 실험에서는 누수 증가와 검색
  이득 불안정이라는 실질 비용이 더 컸다.
- **로컬 모델의 한계.** 방언율과 별개로, 40~50%의 대화에 외국어가 혼입되어 후처리 필터가
  필수적이다. 이는 상용 API 대비 로컬 접근이 감수해야 할 비용이다.

## 8. 한계
- **RAG DB 자원 검수 미비(검색 약함의 유력 가설).** 웹 자원을 각기 다른 형식으로 모아 자동
  구조화만 했을 뿐 항목별 수작업 검수를 하지 못해, RAG에 바로 쓰기 어려운 형태(오염된 표준형·
  빈 폼·비학술 웹 출처)가 많았다. RAG DB 검색 이득이 작은 것은 이 자원 품질과 얽혀 있으나, 정보량·
  검색·주입·모델 활용 등 다른 원인과 미분리 상태다(7절).
- **지표의 종결어미 편향.** 강원처럼 어휘·음운 중심 방언은 과소평가된다(제주는 존댓말 표지
  보완으로 완화했으나 강원은 방언 유형상 해소 곤란). 표지 목록에 수동 보완·오탐 규칙이 포함되어
  완전 자동·객관은 아니다.
- **인간 평가 부재.** 지표의 절대 타당성은 미검증(상대 비교로만 사용). A단계는 인간 대신 독립
  모델(Claude)을 참조로 쓰므로 Claude의 방언 역량과 공유 맹점에 검증이 의존한다.
- **통계·규모.** 권역당 n=10으로 조건 간 근소차(C1 vs C_kb+C1)는 유의성 미확인(6.7). 단일 로컬
  생성 모델·단일 도메인.
- RQ2(어휘 vs 규칙 기여 분해)는 본 논문 범위에서 제외(future work).

## 9. 결론
상용 API 없이 로컬 오픈소스 LLM과 방언 지식 주입만으로 5권역 방언 악취 민원 대화를 합성하고,
인간 평가 없이 조건을 비교하는 자동 진단 지표를 제시했다. few-shot 예시가 방언성의 핵심 동력임을
확인했고, 현재의 RAG DB 검색은 few-shot을 넘어서는 이득을 주지 못했는데 이는 자원 정제·검수의 한계와
맞물린 결과로 해석된다. 직접 생성이 2단계 변환보다 누수가 낮았고, 독립 모델 기반 교란으로 지표의
민감도·특이도를 실증했다.
