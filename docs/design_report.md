# 논문 설계서 (개정판) — 로컬 LLM + 방언 지식 주입 기반 방언 악취 민원 대화 합성

> 보고용 설계서. 2026-08-12 기준 현재 진행 상태·예비 결과 반영.
> 상세 설계 SSOT=`research_scope.md`, 논문 초안=`paper_draft.md`, 데이터 감사=`data_audit.md`.
> ⚠️ 개정 핵심: (1) 제주 RAG DB 구축 완료(5권역 전부 보유), (2) 핵심 발견이 "RAG 효과적"이 아니라
> "few-shot 지배·RAG DB 이득 없음"으로 확인됨, (3) A단계 지표 신뢰성 검증·통계 검정 추가.

## 1. 서론

### 1.1 연구 배경

- **동기(응용 맥락).** 지자체 악취 민원은 주로 전화로 접수되고, 지역에 따라 방언·구어체가 쓰여
  일반 STT·키워드 추출이 잘 안 될 수 있다. 이를 개선하려면 방언 통화 데이터가 필요하다.
- **데이터 부족.** 실제 방언 악취 민원 데이터는 개인정보·수집 비용 때문에 확보가 어렵다
  → **합성 데이터**가 현실적 대안.
- **본 연구 범위(명확화).** 본 연구는 **방언 대화 "텍스트" 합성과 그 평가**에 한정한다. STT·키워드
  추출 개선은 이 연구의 동기일 뿐 직접 실증 대상이 아니며(downstream=future work), 음성(TTS)
  변환도 범위 밖이다.
- **상용 API의 한계.** 상용 API(예: Claude Opus) + few-shot으로 자연스러운 방언 텍스트 생성은
  가능하나, (a) 비용, (b) 모델 버전 변경 시 동일 프롬프트라도 출력이 달라짐, (c) 정책 변경·서비스
  종료 가능성 → **장기적 재현성**이 낮다.
- **로컬 대체와 열린 가설.** 이에 로컬 오픈소스 LLM으로 대체하고자 하나, 로컬 모델은 방언 내재
  지식이 약해 품질 저하가 예상된다. → **가설:** 웹 자원 기반 방언 지식을 주입(few-shot / RAG DB
  검색)하면 이 결핍을 보완할 수 있는가? (해결책 단정이 아니라 검증 대상)
- **평가 문제.** 방언 화자 인간 평가는 비용·섭외가 어렵다 → 인간 평가 없이 조건을 비교하는
  **자동 진단 지표**가 필요.

### 1.2 기여

1. 상용 API·파인튜닝 없이 로컬 LLM + 방언 지식 주입으로 5권역 방언 악취 민원 대화 합성
   파이프라인(S1 직접생성 / S2 2단계 변환) + 지식 공급 조건 설계.
2. 5권역(경상·전라·충청·강원·제주) 방언 악취 민원 대화 데이터셋.
3. **합성 교란으로 신뢰성을 검증한** reference-free 자동 진단 지표(방언율·누수율).

## 2. 관련 연구

- **한국어 방언 자원/NLP** — 방언 벤치마크에서 한국어 변종이 특히 저조(DialectBench 등).
- **LLM 기반 합성 데이터 생성(저자원·대화)** — DiaSynth, 저자원 LLM 데이터 생성 전략 연구
  (타깃언어 예시 + LLM 수정이 강력하다는 보고 → 본 연구 few-shot 우위와 연결).
- **RAG for controllable generation** — Lewis et al. (2020) 등 지식 주입 생성.
- **어미/표지 기반 방언 식별** — Stable Lexical Marker Analysis(코퍼스 기반 어휘변이 마커),
  한국어 방언 식별(단 음성 기반) → 본 지표의 방법적 뿌리. LLM-as-judge(A단계 독립 참조 근거).
  *(인용 후보 조사 완료, 저자·연도 최종 대조 필요.)*

## 3. 제안 방법

### 3.1 시스템 구조
- **입력:** 시나리오 파라미터 5개 — 냄새 종류, 민원인 위치, 강도 변화, 지속시간, 원인 추정지역.
- **출력:** 5권역(경상/전라/충청/강원/제주) 8~10턴 방언 상담 대화(상담원 표준어 ↔ 민원인 방언).

### 3.2 방언 지식베이스 (RAG DB)
- **어휘(vocab):** 웹 사전 → `{표준, 방언, 품사}` 구조화. 검색=표제어 정확 매칭.
- **문법 규칙(rule):** 문법서·문헌 → `표준형→방언형` + 설명. 검색=형태소 BM25.
- **✅ 5권역 전부 RAG DB 보유(개정):** 제주 RAG DB를 편입해 4권역 → **5권역**으로 확장.
  제주는 어휘 `jeju_vocab_v2` **13,508개**(오염된 final 제외) + 문법 30개 사용.
  ⚠️ 제주 문법은 나무위키 파생 → 투고 전 학술 근거 보강 필요.
- **평가용 마커:** AI-Hub 2인 발화 코퍼스 → (표준꼬리→방언꼬리) 변환쌍 추출.

### 3.3 합성 파이프라인 (핵심)
- **S1 (Single-Stage, 주력):** 조건별 지식 주입 후 방언 대화 직접 생성. 쿼리 없어 엄밀히는
  "지식 주입".
- **S2 (Two-Stage, 대조):** 표준어 생성 → 방언 변환. 쿼리(표준어) 기반 실제 검색 성립.
  변환 압력에 의한 누수·hallucination 대조군.
- **지식 공급 조건:** C0(zero-shot) / C1(고정 few-shot) / C_kb(RAG DB) / C_kb+C1(RAG DB+few-shot).
  C1은 "예시가 있어서"의 효과를 "검색 때문"과 분리하는 필수 대조군.
- **프롬프트:** 한국어 전용(외국어 금지), 민원인 존댓말, 타권역 어미 누수 금지, 발화자 라벨 형식.

### 3.4 자동 진단 지표
- **마커:** (표준꼬리→방언꼬리), 필터(빈도≥8·변별력). 코퍼스 자동추출 + 존댓말 표지 수동 보완
  → 현재 **78개**(전라 당께/랑께·제주 수다/마씸 등 보완 포함).
- **방언율** = 타깃 마커 적중 / 총어절, **누수율** = 타권역 마커 적중 / 총어절.
- S1 표면 접미 매칭 / S2 표준↔방언 정렬 어절쌍 매칭. false positive 방지(1자 마커 받침조건,
  표준어 동형 제외).
- **명시:** 조건 간 **상대 비교용 진단 도구**이며 절대 품질 척도가 아님.

### 3.5 지표 신뢰성 검증 — A단계 (신규)
- 인간 라벨 없이 지표를 검증: 정상 생성문을 **채점기와 독립인 참조 모델(Claude)** 로 오염시켜
  지표 반응 측정.
  - 표준어화(방언 제거) → 방언율 하락해야 함(민감도).
  - 타권역화(다른 권역으로) → 소스 방언율 하락 + 누수율 상승해야 함(특이도).
- 채점기(어미 사전)와 오염기(Claude)가 독립이라 순환성 완화. Claude는 **평가용 독립 도구로만**
  사용(생성은 로컬 Qwen 전용, 요지 불변).

## 4. 실험

- **세팅:** Qwen3.6-27B(로컬 vLLM). **n=50(권역당 10)**, 5권역 × 4조건, 시드 고정. S1/S2 동일
  시나리오.
- **결과(예비, 방언율 전체 평균):**

| 파이프라인 | C0 | C1 | C_kb | C_kb+C1 |
|---|---|---|---|---|
| S1 | 0.003 | **0.071** | 0.018 | 0.070 |
| S2 | 0.032 | **0.157** | 0.044 | 0.098 |

- **통계 검정(부트스트랩 CI + 시나리오 짝지은 검정, 신규):**
  - few-shot 우위 유의 — 두 파이프라인 모두 C1 > C0·C_kb (p<0.001).
  - **C1 vs C_kb+C1:** S1 **동률(ns, p=0.54)**, S2 **C1이 유의하게 높음**(RAG DB가 오히려 방해).
  - RAG DB 단독: S1 C_kb>C0 유의 / S2 C_kb≈C0 ns.
- **A단계 지표검증:** 민감도 0.96·특이도 0.96, 타권역화 시 누수 검출(+0.09), 타권역화한 문장을
  타깃권역 방언으로 인식(수렴 타당도).
- **정성 예시:** 권역별 성공(충청 -혔슈, 경상 -기라예)·지표한계(강원 -잖소/-래요는 방언이나
  지표 0)·누수(S2 경상에 충청 -유) 사례.

## 5. 논의

- **핵심 발견(개정 — 기대와 다름):** 원래 가설은 "RAG DB가 방언성을 높인다"였으나, 실측은
  **few-shot(C1)이 주 동력이고 RAG DB를 얹어도 이득이 없음**(S1 동률, S2 방해). 즉 로컬 모델 방언
  유도에는 검색된 지식 조각보다 **완결된 예시**가 더 강한 신호.
- **왜 RAG DB가 약한가 — 자원 검수의 문제(근본원인).** RAG DB는 서로 다른 출처(웹사전·문법서·나무위키)를
  각기 다른 형식으로 모아 자동 구조화만 했고 항목별 수작업 검수를 못 함 → 표준형 오염·빈 폼 다수.
  즉 **RAG DB가 RAG에 쓰기 좋은 형태로 정제되지 못한 것**이 원인. 방법 실패가 아니라 자원 문제이며,
  잘 검수된 RAG DB에서는 결과가 달라질 수 있음.
- **강원/제주 구분(개정):**
  - 제주는 존댓말 표지(-수다/-마씸/-쿠다) 보완 후 정상 측정(0.10대). "저측정=생성 실패"가 아니라
    지표 맹점이었고 보완으로 해결.
  - 강원만 여전히 ~0 — 방언 유형이 어미보다 **어휘·음운 변화** 중심(아이들→아들)이라 어미 지표로
    포착 불가. 보완으로도 해결 안 되는 구조적 한계.
- **로컬 LLM 한계:** 한국어 전용 지시에도 40~50% 대화에 외국어 혼입(code-switching) → 후처리 필터
  필요. 상용 대비 로컬의 실질 비용.

## 6. 한계

- **RAG DB 자원 검수 미비(근본원인).** 웹 자원을 형식 제각각으로 모아 자동 구조화만 함 → RAG 가용
  형태 아님. RAG DB 검색 이득 저조와 직결.
- **지표의 어미 편향.** 강원 등 어휘·음운 중심 방언 과소평가(제주는 보완). 마커·오탐 규칙에 수작업
  개입 → 완전 자동·객관 아님.
- **인간 평가 부재.** 지표 절대 타당성 미검증(상대 비교로만). A단계는 Claude 역량·공유 맹점에 의존.
- **규모·범위.** 권역당 n=10, 단일 로컬 모델·단일 도메인.
- RQ2(어휘 vs 규칙 분해)는 범위 제외(future work).
