## 1. 연구 배경 (유효)

- 지자체 악취 민원은 전화로 접수되고 실제 발화는 방언·구어체 → STT·키워드 추출 자동화에 방언 통화
  데이터 필요. 그러나 실제 방언 악취 민원 데이터는 개인정보·수집 비용으로 거의 없음 → **합성 데이터**가
  현실적 대안.
- 상용 API(Claude 등)+few-shot으로 방언 텍스트 생성은 가능하나 **비용·데이터 외부전송·장기 재현성**
  문제. → **로컬 오픈소스 LLM(Qwen3.6-27B)**으로 대체하고자 하나, 로컬은 방언 내재 지식이 약함.
- **가설:** 웹 자원 기반 방언 지식(어휘·문법)을 주입(few-shot / 검색)하면 이 결핍을 보완할 수 있는가?
- **본 연구 범위:** 방언 대화 **텍스트** 합성과 그 평가에 한정. STT·키워드 추출·음성(TTS)은 동기·future.

## 2. 연구 문제

로컬 LLM은 방언 데이터가 거의 없어 방언 악취 민원 대화 생성 시 품질 저하(방언 미적용, 타권역 어미
혼입)가 예상된다. **어떤 지식 공급 방식(고정 few-shot vs 검색·주입 RAG)이 이를 얼마나 완화하는지,
그리고 그 결과가 자원 품질·주입 방식·검색 방식 중 무엇에 좌우되는지**가 검증되지 않았다.

## 3. 연구 질문

**RQ1 (핵심):** 방언 지식을 주입(few-shot C1 / RAG 검색 C_kb / 결합 C_kb+C1)하면, 무주입(C0) 대비
방언 생성 품질이 향상되는가? 특히 **RAG 검색이 few-shot을 넘어서는 추가 이득**을 주는가?

**RQ1-보조 (원인 분해):** RAG 이득이 (거의) 없다면 그 원인이 자원 품질(RAG DB 미검수)인가, 주입
방식(규칙만 vs 규칙+예문)인가, 모델 능력인가? — 검수·조건변경·모델비교로 분리.

**Future (원 RQ2·보조 RQ, 본 논문 범위 밖):** 어휘 vs 문법규칙 기여 분해(상가성), 로컬+RAG의 상용
API 대비 품질·비용 격차.

## 3-1. 수학적 모델링

**기본 정의.** 권역 $r$의 방언 대화 생성: $\hat{y} = \text{LLM}(\text{입력},\ \mathcal{K}_r)$.
- S1(직접생성): 입력=키워드 슬롯, 쿼리 부재 → $\mathcal{K}_r$는 고정 주입.
- S2(2단계): 입력=키워드 → 표준어 $x$ 생성 → $x$를 쿼리로 $\mathcal{K}_r$ 검색·주입 → 방언 변환.

**조건별 지식원.**

| 조건 | 지식 $\mathcal{K}$ | 의미 |
|---|---|---|
| C0 | $\emptyset$ | 무주입(zero-shot, 금지규칙만) |
| C1 | $\mathcal{F}_r$ | 고정 few-shot(악취민원 도메인 대화) |
| C_kb | $\mathcal{R}(x,\mathcal{K}_r)$ | RAG 검색·주입(규칙+예문) |
| C_kb+C1 | $\mathcal{F}_r \cup \mathcal{R}(x,\mathcal{K}_r)$ | 결합 |

**방언성 지표 — B단계.** 생성문 $\hat{y}$의 방언성:
$$D(\hat{y}, r) = \frac{1}{|\hat{y}|}\Big(\sum_{m \in M_r^+}\mathbb{1}[m \in \hat{y}] - \sum_{m \in M_r^-}\mathbb{1}[m \in \hat{y}]\Big)$$
- $M_r^+$: 권역 $r$ 방언 표지(+, 방언율), $M_r^-$: 타권역 표지(−, 누수율), $|\hat{y}|$: 어절 수.
- 구현은 방언율·누수율을 **분리** 보고. 표지 = 코퍼스(AI-Hub 1인+2인발화) 유래 v3 마커(287).

**RQ1 검정.** $D(\hat{y}_{C1}) \gtrless D(\hat{y}_{C\_kb})$, $D(\hat{y}_{C\_kb+C1}) \gtrless D(\hat{y}_{C1})$
를 시나리오 짝지은 부트스트랩으로 유의성 검정(§7.8).

**지표 신뢰성 — A단계.** 교란문 $\tilde{y}$(독립 모델이 표준어화·타권역화)에 대한 민감도·특이도:
$$\text{Sensitivity} = \frac{D(\hat{y}, r) - D(\tilde{y}, r)}{D(\hat{y}, r)}$$

## 4. 과제 정의

| 항목 | 내용 |
|---|---|
| 도메인 | 악취 민원 상담 통화 (상담원 표준어 ↔ 민원인 방언) |
| 권역 | 경상·전라·충청·강원·제주 (5권역). **모두 RAG DB 보유**(제주는 어휘 v2·문법 30 편입). |
| 입력 | 구조화 키워드 슬롯(위치·냄새종류·강도·지속시간·원인추정지역) |
| 출력 | 8~10턴 방언 대화(첫·마지막 상담원). 정답 라벨=입력 키워드(내장 GT) |
| 생성 전략 | **S1 직접생성(주력)** / **S2 2단계 변환(대조)**. 둘 다 분석. |
| 비교 축 | 지식 공급: C0 / C1 / C_kb / C_kb+C1 |
| 보조 축(future) | 모델: 로컬 vs 상용, 파라미터 크기별(threshold 가설) |
| 음성(TTS) | 범위 밖(future) |
| 사람 평가 | 미실행 — 인간 없이 자동지표(B)+독립모델 교란(A)로 대체 |

**S1/S2 관계(원설계에서 수정).** 원설계는 "S2가 RAG 성립 핵심 경로, S1은 baseline"이었으나, 실측
결과 (a) **S1이 표면 방언 품질·저누수에서 우세**, (b) **RAG는 S2에서 오히려 방언율을 낮춤**. 따라서
S1을 주력, S2를 대조(변환 압력에 의한 누수·hallucination)로 재배치. "품질(S1) vs 검색 정당성(S2)의
트레이드오프"를 분석 축으로 삼는다.

**⚠️ C_kb = 검색이 아니라 "고정 규칙 주입"임 (2026-08-18 확인, 방법·한계 필수 명시).**
retriever는 존댓말·종결·조사 어미 규칙(category "종결/조사/경어/높임")을 **쿼리와 무관하게 항상
주입(fixed_rules, BM25 우회)**하는데, 권역별 고정 규칙이 11~26개로 주입 상한(cap_rule=10)을 이미
채워 **BM25 검색분이 전부 잘려나간다.** 결과: (1) 문법 어미는 쿼리가 뭐든 **동일하게 고정 주입**되고,
(2) 쿼리 기반 검색은 **어휘 채널에만** 작용하는데 그것도 쿼리 단어(예: "냄새")만 매칭한다. 우리 지표는
어미를 재므로, **C_kb의 방언율 효과 = "고정 어미 규칙 주입" 효과이지 "쿼리 기반 검색(retrieval)"이
아니다.** 따라서 S1의 C_kb를 "RAG retrieval"로 주장하면 과장이며, "지식 주입(injection)"으로
서술한다. (C_kb+예문 조건도 그 고정 규칙에 예문을 부착하는 "주입 표현" 개선이지 검색 개선이 아님.)
진짜 검색 효과 측정은 어휘 지표 추가 또는 S2 어휘 채널 분석이 필요(future work).

## 5. 데이터·리소스

### 5.1 검색 리소스 (RAG 대상)
- **어휘(vocab):** 웹 사전 → LLM 구조화 `{standard, dialect, pos}`. 4권역 + **제주 `jeju_vocab_v2`
  13,508개**(지명유래 오염된 final 제외). 검색=표제어 정확 매칭.
- **문법 규칙(rule):** 문법서·논문 + **웹에서 수집한 문법 정보**(비학술 출처 포함, 투고 전 학술 근거
  보강 필요) → `standard_form → dialect_form` + explanation. 검색=형태소 BM25.
- **문법 예문(examples) — rev.4에서 포함으로 반전:** 원설계는 "예문=LLM 인공물, 검색하면 미리 만든
  few-shot이 되어 C1과 구분 소멸"이라 제외했으나, (a) RAG가 약했던 원인이 "규칙이 앙상해 모델이
  못 씀"일 수 있고 (b) 실제 RAG는 예시도 함께 검색하는 게 자연스러움 → **C_kb에 규칙+예문 주입**
  (actionable). C1(악취민원 완결 대화)과는 종류가 달라(예문=일반 단문) C1↔C_kb 구분은 유지. 단
  예문이 LLM 합성물임은 논문에 명시.

### 5.2 출처·라이선스 (제출 전 필수)
- 웹 사전: 원자료 비공개, 방법·스크립트만 공개해 재현성 확보.
- 비학술 웹 문법 출처: 방언학 논문·문법서로 교차검증·보강 필요(⏳ 미완).

### 5.3 정제 상태
- 어휘: 중복·오염 제거, 5권역 통합 포맷(제주 편입 완료).
- **문법 RAG DB 검수(진행 예정):** 기준을 "문법이냐"가 아니라 "**주입해 모델이 쓸 수 있냐**"로.
  어미=유지(코퍼스 마커 확인/경어법·연결어미), 어휘성=어휘 DB 이관, 음운=저효용(추상 규칙, top-k 낭비).
- **평가 마커:** AI-Hub 1인+2인발화 통합 추출 → 채점 287개(노이즈 차단 필터, `data_audit` 참조).

## 6. 실험 설계

## 7. 평가 (구현 상태 반영)

### 7.1 역할분담
| 속성 | 담당 | 상태 |
|---|---|---|
| 방언성(어미) | **B. 규칙기반 자동**(코퍼스 마커 매칭) | ✅ 구현 |
| 지표 신뢰성 | **A. 합성 교란**(독립 모델 Claude로 표준어화·타권역화) | ✅ 구현 |

### 7.2 B단계 — 방언성 (구현: `src/eval/eval_conditions.py`)
- 방언율 = 타깃 마커 적중/총어절, 누수율 = 타권역 마커 적중/총어절.
- S1 표면 접미 매칭 / S2 표준↔방언 정렬 어절쌍. false positive 방지(1자 화이트리스트+받침, 표준어
  동형 제외). 마커 v3(287, 1인+2인발화).
- ⚠️ 어휘 방언형 치환율은 미측정(지표가 어미 중심). 음운·철자 변이는 임베딩 보조지표(후순위)로 future.

### 7.3 A단계 — 지표 신뢰성 (구현: `src/eval/llm_perturb_sensitivity.py` 주 / `perturb_sensitivity.py` 보조)
- **채점기(어미 사전)와 독립인 참조 모델(Claude)**로 정상문을 표준어화·타권역화 → 지표 반응 측정.
  민감도·특이도, 타권역화 시 누수 검출, 타권역 방언으로 인식(수렴 타당도).
- 사전 기반 교란은 순환성 있어 보조 sanity check로만.
- ⚠️ **DIA-REFINE(arXiv 2511.06680: 한국어 방언 LLM + DFS/TDR)과 목적이 겹침** → 자동지표는
  신규성으로 주장하지 않고 인용·도구화. 우리 차별점은 다중턴 대화·악취민원 도메인·KB/RAG 비교·로컬 전용.

### 7.4 통계 (구현: `src/eval/stats_test.py`)
부트스트랩 95% CI + 시나리오 짝지은 차이 검정. 마커 78→287 양쪽에서 결론 동일(robust).

### 7.5 미실행(future)
LLM judge(담화 적합성), 사람평가 anchor, downstream 유효성(키워드 재추출 F1), 비용·효율, 형식·시스템
지표(파싱률 등).

## 8. 예상·확인된 한계

- **방법 신규성 약함**(확인): RAG+few-shot은 확립 기법. + DIA-REFINE과 겹쳐 자동지표도 신규성 약함.
  → 신규성은 "로컬 전용 + 악취민원 도메인 + few-shot vs RAG 실증 + 데이터셋" 조합으로.
- **핵심 발견이 기대와 반대**(예비): few-shot 지배, RAG는 few-shot 넘는 이득 없음(S1 동률, S2 방해).
  원인은 자원 품질/정보량/검색/주입/모델활용 중 **미분리** — 검수 후 재검증 필요.
- **RAG DB LLM 구조화 오차**(적중): 문법 규칙 다수가 추상 음운·문장형 오염, 존댓말 커버리지 부족.
- **지표 어미 편향**: 강원 등 어휘·음운 중심 방언 과소평가(제주는 존댓말 표지 보완). 강원은 생성측
  병목도 있음(모델이 강원 대신 충청 유 산출). 마커에 수동 개입 → 완전 자동·객관 아님.
- **인간 평가 부재**: 지표 절대 타당성 미검증(상대 비교로만). A단계는 Claude 역량·공유 맹점에 의존.
- **규모**: 권역당 n=10 예비(권역별 세부는 경향). 단일 로컬 모델·단일 도메인.
- **출처 신뢰도**: 비학술 웹 문법 출처의 학술 근거 보강 미완(투고 전).

## 9. 기여 (rev.5 — 정직성 재정립)

**핵심 원칙: "RAG가 이긴다"를 주장하지 않는다.** 우리 지표는 전부 대리 지표(proxy)이고 인간 평가가
없으므로, 어떤 방식의 "우월성"도 단정하지 않는다. 결과는 있는 그대로 보고한다.

1. **(주 기여) 파이프라인·데이터셋:** 상용 API·파인튜닝 없이 로컬 LLM으로 5권역 방언 악취 민원
   대화를 합성하는 파이프라인(S1/S2)과 지식 공급 조건, 그리고 그 산출 데이터셋. **이것이 논문의 축.**
2. **(부차) 자동 진단 지표:** 코퍼스 유래 마커 기반 reference-free 방언율·누수율 + 독립 모델 교란
   신뢰성 검증(A단계). 진단 도구로 포지션(우월성 증명 아님). DIA-REFINE 인용.
3. **(부차) 정직한 실증 관찰:** few-shot vs 지식주입의 **비대칭 효과**(문법/어미 vs 어휘), S1/S2
   트레이드오프, 권역별 한계(강원/제주), 로컬 모델 외국어 혼입 등을 **어느 쪽 승리도 주장하지 않고** 보고.

*(원설계 "어휘 vs 규칙 분해(핵심 신규성)"·"상용 비교"는 폐기/future.)*

### 10.1 최종 본실험 (2026-08-18, Qwen3.8-27B-FP8로 모델 통일, n=100)
- 이전 n=100은 Qwen3.6, 예문 ablation은 3.8로 섞여 있어 **모델을 3.8-27B-FP8로 통일 재실행**.
  조건 4개(c0/c1/c_kb/c_kb_c1), c_kb=규칙+예문. 파일: `s1_20260818_115333`, `s2_20260818_135335`.
- **방언율(paired bootstrap, `stats_test.py`):**
  - S1: c0 .014 / c_kb .050 / c1 .084 / c_kb_c1 .085. → c_kb>c0(+.036***), c1>c_kb(+.034***),
    **c1≈c_kb_c1(-.001 ns)** = few-shot에 RAG 얹어도 무변화.
  - S2: c0 .048 / c_kb .060 / c1 .199 / c_kb_c1 .112. → **c_kb≈c0(+.012 ns, 기준선도 못 넘음)**,
    **c1>c_kb_c1(+.087***, RAG 얹으면 오히려 하락)**.
- **핵심 결론(3.6보다 선명):** RAG(지식 검색·주입)의 few-shot 대비 **고유 기여 ≈ 0, S2에선 음(−)**.
  최고 설정 = **S2×c1(.199)**. → 정직한 주장 = "구조화 지식 단편 주입 < 완결 예시 제시".

### 10.2 메커니즘 — 주입 활용률 (`src/eval/injection_utilization.py`, S1)
- 추측을 측정으로: c_kb에서 **주입한 어휘·규칙 중 생성문에 실제 등장한 비율**.
- 결과(n=100): **어휘 활용률 21.1%**(79% 무시), **규칙 활용률 10.6%**(89% 무시),
  **무주입 시나리오 28/100**(어휘 검색 미발화, 강원13·충청9).
- **병목 = 활용률(출력측).** 규칙을 시나리오당 15개 넉넉히 줘도 89% 무시 → 검색량 문제가 아니라
  **모델이 단편 지식을 조합·적용하지 않음.** few-shot이 이기는 관찰된 원인(완결 예시는 표면 모방).
- 부차 = 검색 약점(28% 무주입) — 한계로 명시. ⚠️ **방언율은 어미 기반이라 어휘 개선은 지표 불변**;
  지표를 움직이려면 **어미 규칙 활용**을 올려야 함.

### 10.2b 어휘 방언율 (검색축) — 객관 청소 후 비대칭 확정 (`vocab_dialect_rate.py`, `vocab_stats.py`)
- 동기: 어미 방언율은 고정주입(어미)만 봄 → RAG의 진짜 검색 파트(어휘)를 놓침. 어휘 실현을 별도 측정.
- **오탐 문제·객관 청소:** 초기엔 전체 사전(6k~22k) 부분문자열 매칭이라 표준어(부터·시간·위치)가
  방언으로 오탐(육안검증에서 발견). **결과 무관 객관 규칙 2개로 청소** — (1) 어절 단위 매칭(부분문자열
  배제), (2) kiwi가 통짜 단일 형태소로 인식하면 표준어로 보고 참조에서 제외.
- **청소 효과:** 바닥(c0)이 S1 .036→.0045, S2 .039→.0032로 **~90% 붕괴** = 옛 수치 대부분이 오탐이었음.
- **청소 후 통계(paired bootstrap):** c_kb−c1 = **S1 +.0048(**), S2 +.0397(***)**. c_kb−c0 유의(***).
  → **객관 청소 후에도 RAG 어휘 우위 생존 = 지표 인공물 아닌 진짜 신호.** S2에서 c_kb .045 vs c1 .005(≈9배).
- **재육안검증:** 억수로·사롬·내움새·미칠·어짜다 등 대부분 진짜 방언. 잔여 오탐(방을·난다 등 다형태소
  표준어)은 소수·전 조건 균등 → 결론 영향 미미.
- **1차 관찰(RAG 사전 참조):** 어미축=few-shot / 어휘축=지식주입 우위처럼 보임. **단 아래 독립검증서 뒤집힘.**

### 10.2b-2 어휘축 독립 참조 재검증 — "어휘 우위는 견고하지 않음" (`extract_vocab_pairs_aihub.py`)
- **홈 어드밴티지 발견:** 10.2b의 어휘 참조는 RAG가 검색하는 **자기 사전**이라 c_kb에 구조적 유리
  (자기 사전으로 자기 채점). → **독립 참조(AI-Hub 코퍼스 유래 방언어휘)로 재검증.** AI-Hub 표준-방언
  정렬쌍에서 어간(내용어) 변화만 추출(어미와 대칭), 표준어 kiwi로 내용/어미 분리, 방언엔 kiwi 미사용.
- **세 참조가 불일치(S2 c_kb−c1):** RAG사전 +.0397*** / AI-Hub 용언포함 −.0057* / AI-Hub 명사한정 +.0045**.
  → **참조 구성에 따라 이겼다 졌다** = 어휘 우위 **견고하지 않음.** 절대값 매우 작음(어절 1%대), 잔여 노이즈.

### 10.3 연구 방향 재정립 (2026-08-20, 정직성 점검 결과)
- **문제 인지:** 어미 방언율에서 RAG가 지자, 어휘 방언율을 신설했더니 RAG가 이김 → 다시 노이즈
  청소를 시도. 이 궤적은 **"원하는 결과 나올 때까지 지표 갈아치우기(metric shopping)"**로 보임.
- **폐기 결정:**
  - **순환 지표 폐기** — "시나리오별 검색된 어휘의 실현율"은 c_kb에 그 단어를 주입해놓고 등장을
    세므로 **동어반복(시킨 대로 했나?)**. RAG 우월의 증거가 못 됨.
  - **C_kb+ 개선 실험 폐기** — "RAG를 이기게 만들자"는 목표 자체가 과적합의 뿌리.
  - 오라클(어미 강제치환)도 준-동어반복이라 폐기(기존 판단 유지).
- **유지·확정:**
  - **어미 방언율 = 주 결과.** 마커가 외부 코퍼스 유래로 독립적·공정, S2는 reference-based.
    결과(few-shot 우위, RAG 어미 무이득)는 **조작 불가능한 신뢰 결과**로 그대로 채택.
  - **어휘 방언율 = 부차·투명 보고.** 참조(사전)는 독립적이나 표준어 오탐 노이즈 有. **결과와 무관한
    객관 규칙(형태소 분석기가 표준어로 인식하는 형태 제외)으로 1회 청소** 후, 이기든 지든 그대로 보고.
    절대값 불신·상대 방향만, 한계 명시.
- **정직한 주장(주장하지 않는 것 포함):** "few-shot이 어미 실현을 지배, 지식주입은 어휘 실현에 더
  기여하는 경향" — **어느 쪽도 일률 우월 아님.** 인간 평가 부재·대리 지표 한계 명시.

### 10.4 논문 구성 계획 (rev.5, 정직 프레임)
- **Ⅰ 서론:** 로컬 LLM 방언 합성의 필요(비용·프라이버시·재현성) + 저자원 방언 데이터 부재.
  기여 = 시스템·데이터셋(주), 진단 분석(부차). "RAG 효과 입증"이 아니라 "정직한 비교".
- **Ⅱ 관련연구:** 방언 생성/번역(DIA-REFINE 등), RAG, 합성 데이터, reference-free 평가.
- **Ⅲ 제안방법:** (작성됨) 시스템 개요 → 지식주입(어휘 검색 / 어미 고정주입, injection vs
  retrieval) → S1/S2 → 조건 → 자동지표. **"정교한 RAG" 과대포장 금지, 정확히 기술.**
- **Ⅳ 실험·결과:** 설정(3.8-27B-FP8, n=100) → **어미 방언율(주, few-shot 우위, 통계)** →
  어휘 방언율(부차, 청소 후, 투명) → 주입 활용률(메커니즘: 왜 어미에서 few-shot이 이기나) →
  A단계 지표 신뢰성 → 정성 예시. **비대칭(어미/어휘)을 발견으로 서술, 승부 판정 회피.**
- **Ⅴ 결론:** 시스템·데이터셋 요약 + 비대칭 관찰 + 한계(인간평가 부재, 지표 대리성, 검색 약점,
  강원/제주) + future(threshold, 인간평가, 어휘 지표 정교화).
