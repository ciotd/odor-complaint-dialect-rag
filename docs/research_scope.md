## 1. 연구 배경

- 지자체 악취 민원은 전화 통화로 접수되며, 실제 발화는 지역 방언·구어체다. 이를 STT·키워드
  추출로 자동 처리하려면 방언 통화 데이터가 필요하나, **실제 방언 악취 민원 데이터는 거의 없다**
  (개인정보·수집 비용). → 합성 데이터 생성이 현실적 대안.
- 기존 생성은 **상용 API(Claude Opus 4.8) + few-shot**으로 4권역(경상·전라·충청·강원) 텍스트를
  자동 생성했다(RAG 미사용). 상용 모델은 방언 지식이 풍부해 규칙 프롬프트만으로도 방언을 살린다.
- 그러나 상용 API 의존은 **비용·재현성·개인정보(외부 전송)** 문제가 있다. 로컬 오픈소스 LLM으로
  대체하려 하면, 로컬 모델은 방언 내재 지식이 약해 품질이 떨어질 가능성이 크다.
- **RAG의 역할(핵심 관점):** 로컬 모델의 방언 지식 결핍을, **웹 자원으로 구축한 방언 지식
  (어휘·문법규칙)을 검색·주입**해 보완할 수 있는지 검증한다. 이때 문장 단위 병렬 코퍼스는 없고,
  검색 대상은 어휘 사전·문법 규칙이라는 점이 일반적 RAG-MT와 다르다.

## 2. 연구 문제

로컬 LLM은 방언 학습 데이터가 거의 없는 상태에서 방언 악취 민원 대화를 생성할 때 낮은 품질을
보일 가능성이 크다(방언 미적용, 타권역 어미 혼입 등). 실제 방언 자원(어휘·문법규칙)을 검색해
근거로 제공하면 이 문제가 완화되는지, 그리고 **어떤 자원(어휘 vs 문법규칙)이 방언 전이에
유효한지**가 검증되지 않았다.

## 3. 연구 질문

**핵심 연구 질문 1**
> 웹 자원 기반 방언 지식(어휘·규칙)을 검색·주입하면, 로컬 LLM의 방언 악취 민원 생성 품질이
> (a) 지식을 주지 않은 경우(C0), (b) 질의와 무관한 고정 few-shot(C1)보다 향상되는가?

**핵심 연구 질문 2 (기여 지점)**
> 방언 지식 중 **어휘(단어 치환)** 와 **문법 규칙(어미·음운)** 중 어느 자원이 로컬 모델의
> 방언 전이에 더 유효한가? 둘의 결합은 상가적(additive)인가?

**보조 연구 질문**
> 방언 지식 RAG가 적용된 로컬 LLM은 상용 LLM과 비교하여 어느 수준의 품질과 비용 효율성을
> 보이는가?

## 4. 과제 정의 (Task Definition)

| 결정 항목 | 결정 내용 |
|---|---|
| 도메인 | 악취 민원 상담 통화 (상담원 표준어 ↔ 민원인 방언) |
| 권역 | 경상 · 전라 · 충청 · 강원 (4권역). **제주는 보류**(z 제주어 논문과 중복 관리 이슈) |
| 입력 | 구조화된 키워드 슬롯(민원인 위치·냄새 종류·강도 변화·지속 시간·원인 추정 지역) + 상황 |
| 출력 | 8~10턴 방언 악취 민원 대화(첫·마지막 턴 상담원). 정답 라벨 = 입력 키워드(내장 GT) |
| 생성 전략 1 (baseline) | **S1 직접생성**: 키워드 → 방언 대화 직접 생성 (쿼리 부재로 RAG는 권역지식 고정주입에 그침) |
| 생성 전략 2 (RAG 성립) | **S2 변환**: 키워드 → 표준어 민원 대화 → (표준어 문장을 쿼리로) 어휘·규칙 검색·주입 → 방언 대화 |
| 핵심 비교 축 1 | 지식 공급 방식: 없음(C0) / 고정 few-shot(C1) / 지식 검색(C_kb) |
| 핵심 비교 축 2 | C_kb 리소스 종류: 어휘만 / 규칙만 / 어휘+규칙 |
| 보조 비교 축 | 모델: 로컬(Qwen3.6-27B) vs 상용(Claude/GPT) |
| 음성(TTS/VC) | **L1**: 방법 기여 아님. 산출물·응용 서사 + 부록 샘플로만. MOS 등 정식 음성평가 없음 |
| 사람 평가 | 방언 화자 확보 시 anchor로 포함. 미확보 시 삼각 자동평가로 대체(7절) |

**핵심 구조적 근거**: RAG(검색)는 쿼리(=표준어 텍스트)가 있어야 성립한다. S1(직접생성)은 쿼리가
없어 검색이 불가하고 권역 지식 통째 주입에 그친다. 따라서 **S2(변환)가 RAG를 성립시키는 핵심
경로**이며, S1은 비교 baseline이다. C_kb의 검색 효과는 주로 S2에서 측정된다.

## 5. 데이터·리소스

### 5.1 검색 리소스 (RAG 대상)
- **어휘(vocab)**: 네이버 사전 웹스크래핑 → LLM으로 `{standard, dialect, pos}` 구조화. 4권역
  6.7k~26.6k개. **실제 언어 자원**이므로 검색소스로 정당. LLM 구조화 오류(오염 항목) 정제 필요.
- **문법 규칙(grammar rule)**: 논문·문법서 PDF(+ 나무위키) → LLM 구조화
  (`standard_form → dialect_form` + explanation). 규칙 자체는 근거 있음.
- **문법 예문(examples)은 검색소스에서 제외**: LLM이 규칙에 맞춰 생성한 인공물이므로(강원·전라만
  악취 도메인 작문됨), 검색하면 "미리 만든 few-shot 검색"이 되어 RAG 정당성이 없다(C1과 구분
  소멸, distillation 위험). 예문은 필요 시 평가용 참조로만.

### 5.2 출처·라이선스 (제출 전 필수 정리)
- **네이버 사전**: 원자료(단어 목록) 비공개 원칙. 방법·출처·수집 스크립트만 공개해 재현성 확보.
  데이터셋 자체 공개는 저작권상 지양.
- **나무위키**: 학술 신뢰도 약함 → 나무위키 문서의 참고문헌을 따라 **실제 방언학 논문·문법서로
  교체·교차검증** 필요. 라이선스(CC BY-NC-SA)보다 신뢰도가 더 큰 문제.

### 5.3 정제
- vocab 중복 제거(전라 5.8%), 오염 항목(`standard` 비정상 길이) 제거, 4권역 통합 포맷.
- 규칙 `dialect_form`의 프롬프트 금지어미 정합성 조정(전라 '-당께라우' 등).

## 6. 실험 설계

### 6.1 조건 매트릭스

| 지식 공급 | 리소스 | 목적(무엇을 분리) |
|---|---|---|
| C0 | 없음 (zero-shot, 금지규칙만) | 기준선 |
| C1 | 고정 few-shot (질의 무관) | "예시가 있어서" 생기는 효과 |
| C_kb-lex | 어휘 검색 | 어휘 자원의 효과 |
| C_kb-rule | 규칙 검색 | 규칙 자원의 효과 |
| C_kb-both | 어휘+규칙 검색 | 결합 효과(상가성 확인) |

- **C1(고정 few-shot)은 반드시 포함**: 품질 향상이 "검색 때문"인지 "예시가 있어서"인지 분리하는
  유일한 방법. C1을 빼면 RAG 기여를 증명할 수 없다.
- 전체 = 생성전략(S1/S2) × 지식공급(C0/C1/C_kb 3종) × 모델(로컬/상용) × 4권역. 파일럿에서 축소.

### 6.2 공정 비교를 위해 고정할 항목
동일한 키워드 슬롯 · 동일 상황 · 동일 프롬프트 구조 · 동일 출력 형식 · 동일 temperature·max_tokens ·
동일 생성 횟수 · C_kb 조건 간 동일 검색 파라미터 · 모델별 유리한 별도 프롬프트 최적화 금지.

## 7. 평가 — 삼각 평가 (사람평가 부재 대비)

사람평가가 가능하면 소량 표본을 **anchor**(자동지표·judge를 보정·검증하는 기준점)로 포함한다.
불가한 경우에도 성립하도록 아래 삼각 구조로 설계한다.

### 7.1 속성별 역할분담
| 속성 | 담당 | 근거 |
|---|---|---|
| 방언성(어미·어휘) | **규칙기반 자동**(어휘·규칙 리소스 매칭) | 방언표지 밀도·타권역 어미누수는 객관 매칭이 judge보다 신뢰 |
| 의미 보존 | 역번역 + 다국어 임베딩 유사도 | 검증 가능한 객관 신호 |
| 담화 적합성(상황·화자·자연스러움) | LLM judge | 방언 무관 담화 수준은 judge 강점 |
| 최종 자연성 | 사람평가(가능 시 anchor) | judge 검증용 |

### 7.2 형식·시스템 지표 (자동)
JSON/형식 파싱 성공률, 턴 수·화자 순서 충족률, 빈 출력·필드 누락률.

### 7.3 방언성 지표 (규칙기반, 리소스 활용)
- 방언 표지(어미·방언 어휘) 사용률, **타권역 어미 누수율**(프롬프트에 이미 정의된 금지어미 목록 재사용),
  어휘 방언형 치환율.

### 7.4 의미 보존 지표
- 입력 표준어(S2의 중간 산출물) ↔ 출력 방언의 교차 의미 유사도, 역번역(방언→표준어) 후 원문 유사도.

### 7.5 LLM judge + 검증 (기여 후보)
- judge는 이진/척도 항목 + 근거 지목으로 강제(자유서술 금지). 최종심판이 아니라 자동지표군과 삼각측량.
- **judge 검증 = 합성 오류 probe**: 타권역 어미 혼입 / 의미 훼손 / 표준어 미변환 등 알려진 오류를
  주입해 judge의 민감도·특이도 측정 → 논문 별도 절.
- **순환 함정(명시)**: judge LLM도 방언을 모를 수 있으므로 방언성 판단은 judge에 맡기지 않고
  규칙기반으로. judge는 방언 무관 속성만.
- 프레이밍: "사람 완전 대체"가 아니라 **"검증 가능한 속성에 한한 신뢰성 있는 근사"**.

### 7.6 downstream 유효성 (응용 기여)
- 생성 대화 → `extract_prompt`로 5개 키워드 재추출 → 내장 정답과 비교(성격별 F1: 엔티티형 vs 문장형).

### 7.7 비용·효율
- 샘플당 생성 시간, 초당 토큰, 총 입출력 토큰, GPU 메모리·하드웨어, 상용 API 비용, 유효 샘플당 비용.
  "무비용"이 아니라 "상용 API 비용 없이 내부 운영 가능"으로 표현.

### 7.8 통계
평균만 보고하지 않음: 표준편차·95% CI, 권역별·조건별 분해, RAG 효과의 paired 비교
(paired bootstrap / Wilcoxon signed-rank / permutation).

## 8. 예상 한계

- **방법 신규성 약함**: RAG+few-shot은 확립 기법. 신규성은 "방언 지식베이스 구축 + 리소스 종류
  효과 분해 + 악취 민원 응용"의 조합에서 확보. 국내 저널엔 적정, 영문/SCI엔 확장 필요(11절).
- **출처 신뢰도·라이선스**: 나무위키 교체, 네이버 사전 라이선스 정리 필요(5.2).
- **judge 순환**: judge 모델의 방언 지식 결핍(7.5).
- **사람평가 확보 불확실**: 방언 화자 섭외 여부에 방언성·자연성 강한 주장이 좌우됨.
- **생성 전략 공정 비교**: S1(중간 산출물 없음) vs S2(있음)의 평가 기준 통일 설계 필요.
- **리소스 LLM 구조화 오차**: 어휘·규칙이 LLM으로 정리돼 원문 왜곡 가능(표본 검증 필요).

## 9. 기여

1. **방법·응용**: fine-tuning·상용 API 없이 로컬 LLM + 방언 지식 RAG로 방언 악취 민원 데이터 생성
   가능성 검증.
2. **분석(핵심 신규성)**: 어휘 vs 문법 규칙 중 무엇이 로컬 모델의 방언 전이에 유효한지 분해.
3. **비교**: 로컬+RAG가 상용 API와의 품질·비용 격차를 얼마나 좁히는지.
4. **응용·리소스**: 생성 데이터의 downstream(키워드 추출) 유효성 + 웹 자원 LLM 구조화 방언
   지식베이스 + 실제 음성 파이프라인(L1).

## 10. 파일럿 계획 (최소)

- **상용 모델 먼저** 실행(GPU 불필요, 파이프라인 부트스트랩) → 이후 로컬 Qwen 확장.
- 축소 규모: 2~3권역 × S1/S2 × C0·C1·C_kb-both × 상용 1개. 입력 15~30건.
- 확인 사항: 방언 실제 생성 여부, 타권역 어미 누수, C_kb 검색 적합성, 출력 형식 안정성,
  자동 지표 계산 가능성, RAG 전후 육안 차이.
- 중단·수정 조건: 검색 결과 대부분 무관 / RAG 전후 차이 미미 / 검색 지식 복사 / 형식 붕괴.

## 11. 영문/SCI 확장 로드맵 (future work)

- **(A)** downstream 인과 실증: 생성 데이터 학습 → 실제 방언 STT WER/CER 감소(README 파이프라인 연결).
