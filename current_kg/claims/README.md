# Claim 작업 영역

이 디렉터리에는 세 활성 문헌에서 새로 추출한 Claim만 저장한다. 과거 39규칙이나 기존
문법 JSON을 복사하거나 비교 기준으로 사용하지 않는다.

## 파일과 역할

- `source_registry.json`: 사용할 수 있는 자료와 사용할 수 없는 자료를 구분하는 자료 통제표
- `claim_record_schema.json`: Claim 한 건이 지켜야 할 기계 검증 형식
- `raw/`: 문헌별로 독립 추출한 JSONL 장부
- `review/`: 사람이 읽고 승인·수정·기각하기 위한 검토 자료

`claim_record_schema.json`은 KG 스키마가 아니다. Claim 전체를 확인하기 전에 노드·관계나
운영 Rule을 미리 고정하지 않는다.

## 자료 사용 경계

신규 Claim을 만들 수 있는 자료는 `source_registry.json`에서
`eligible_for_claims: true`인 다음 세 자료뿐이다.

- `JO2018`: 조현준(2018)
- `RYU2014`: 류성기(2014)
- `NAMU20260901`: 나무위키 동남 방언 문서의 2026-09-01 판

경상 어휘 JSON은 별도 어휘 후보이고, AI-Hub 경상도 코퍼스는 독립 평가 후보이다.
둘 다 현재 Claim 근거로 사용하지 않는다.

## 원자 단위 추출 원칙

1. Claim 하나에는 독립적으로 승인하거나 기각할 수 있는 주장 하나만 넣는다.
2. 모든 Claim에는 PDF 페이지와 해당 절·표·예문 위치를 기록한다.
3. 원문의 직접 진술, 표·빈도, 설문 결과, 예문 관찰을 `claim_basis`로 구분한다.
4. 예문 하나가 존재한다는 사실과 저자가 일반적 사용법으로 분석한 주장을 구분한다.
5. 원문에 없는 표준어 대응형·지역·의미·사용 조건을 상식으로 보충하지 않는다.
6. 방언 형태는 원문 철자를 `source_spelling`에 그대로 보존한다.
7. 문헌의 분류 용어는 `usage_conditions_raw`에 먼저 보존하고 공통 KG 용어로 미리 통합하지 않는다.
8. 문헌상 전통형이라는 사실과 현대 화자에게 자연스럽다는 판단을 분리한다.
9. 자료 안의 빈도는 그 자료의 관찰값으로만 기록하며 현대 사용 확률로 바꾸지 않는다.
10. 문헌 간 일치·충돌은 전수 추출 후 `claim_links`로 연결하며 어느 한쪽을 삭제하지 않는다.

## 지역 기록 원칙

`normalized_regions`에는 다음 네 값만 사용한다.

- `경상 전역 공통`
- `경북`
- `경남`
- `세부 지역 미상`

포항·안동·함양처럼 원문에 나온 세부 지역은 `subregions`에 별도로 보존한다.
`세부 지역 미상`은 표현의 신뢰도가 낮다는 뜻이 아니라 경북·경남을 가를 근거가
없다는 뜻이다.

## 검토 상태

- `unreviewed`: AI가 원문에서 추출했으나 사용자가 확인하지 않음
- `approved`: 원문 위치와 Claim 해석을 사용자가 승인
- `revised`: 사용자 검토에 따라 내용을 고침
- `rejected`: 잘못 분리했거나 원문보다 확대 해석하여 사용하지 않음

최초 추출물은 모두 `unreviewed`로 저장한다. 사용자 확인 전에는 Claim을 운영 Rule로
승격하지 않는다.

## 작업 순서

1. 세 문헌에서 각 5~10건의 파일럿 Claim을 독립적으로 추출한다.
2. 검토용 표를 만들어 사용자와 원문 위치·분리 단위·해석을 확인한다.
3. 필요하면 이 추출 원칙과 스키마를 수정한다.
4. 기준이 승인된 뒤 문헌별 전수 추출을 수행한다.
5. 전수 추출 후에만 중복·지지·세분화·충돌 관계를 연결한다.
6. Claim 1차 검토가 끝난 다음 KG 노드·관계 초안을 설계한다.

JSONL은 KG 자체가 아니라 출처 기반 Claim 장부이다. 사용자 검토가 끝나기 전에는
Claim을 운영 Rule로 승격하지 않는다.
