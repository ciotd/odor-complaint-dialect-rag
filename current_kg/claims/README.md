> **2026-09-15 현재:** 이 디렉터리의 추출본(기존 318건 및 `v3/`의 688건 포함)은 이력이다.
> 새 문법 지식은 [`../grammar/records.jsonl`](../grammar/records.jsonl), 새 그래프는
> [`../grammar/grammar.graph.json`](../grammar/grammar.graph.json)에 있다.
> [현재 연구 안내](../README.md)와 [연구미팅](../../연구미팅.md)을 우선한다.
> `source_registry.json`은 자료 통제표로 계속 참고하되 아래 과거 포맷·순서 지시는 자동 적용하지 않는다.

> 2026-09-09 전면 재추출 결정: 기존 류성기 318건은 신규 KG 입력에서 제외하고
> 이전 추출 이력으로 보존한다. 아래의 2.0 형식·전수 초안·순서 설명은 이전 작업 기록이다.
> 현재 기준은 [전면 재추출용 포맷 초안](../docs/CLAIM_FORMAT_V3_DRAFT.md)이며,
> 사용자 방향 확인·최소 그래프 점검을 거쳐 원문 재추출을 시작했다.
> 첫 정식 초안은 `v3/`의 15건이며 [첫 구간 검토](v3/BATCH_001_REVIEW.md)를 읽는다.
> 과거 `경상 전역 공통` 분류를 자동 승계하지 않는다.

당시에는 이 디렉터리에 자료 통제표의 활성 문헌에서 추출한 Claim을 저장했다. 과거 39규칙이나 기존
문법 JSON을 복사하거나 비교 기준으로 사용하지 않는다.

`current_kg/claims/v3/BATCH_001_REVIEW.md`는 이전 첫 배치의 검토 이력이다. `v3/`와 `../design_probe/`는 각각 과거 추출본과 별도 시험 데이터다. 새 지식과 합산하지 않는다. 아래 내용은 과거 파일을 확인할 때만 참고한다.

## 파일과 역할

- `source_registry.json`: 사용할 수 있는 자료와 사용할 수 없는 자료를 구분하는 자료 통제표
- `claim_record_schema.json`: 기존 1.0 파일럿 형식(역사 기록용)
- `structured_claim_schema.json`: 새 구조화 Claim 2.0 형식(현재 류성기 추출본용)
- `grammar_categories.json`: 문법 대분류·세부 분류의 잠정 목록
- `structured/`: 신규 구조화 장부와 페이지별 처리 기록
- `raw/`: 이전 형식의 파일럿·구간 시험 장부(신규 전수본과 합산 금지)
- `review/`: 사람이 읽고 승인·수정·기각하기 위한 검토 자료
- `review/checkpoints/`: Claude의 읽기 전용 검토와 Codex의 처리 판단(원본 장부와 분리)

`claim_record_schema.json`은 KG 스키마가 아니다. Claim 전체를 확인하기 전에 노드·관계나
운영 Rule을 미리 고정하지 않는다.

## 자료 사용 경계

신규 Claim을 만들 수 있는 자료는 `source_registry.json`에서
`eligible_for_claims: true`인 다음 여섯 자료뿐이다.

- `JO2018`: 조현준(2018)
- `RYU2014`: 류성기(2014)
- `NAMU20260901`: 나무위키 동남 방언 문서의 2026-09-01 판
- `NAMU_GRAMMAR_20260908`: 2026-09-08 추가된 동남 방언/문법 PDF 51쪽. 별도 Source이며 상위 위키 문서와 독립 증거로 중복 계산하지 않는다. Claim 전수 추출 전의 범위 검토 상태다.
- `NAMU_HONORIFICS_20260908`: 상대 높임법 PDF 35쪽. 문헌별 체계와 혼용·결합 조건 후보. JO·위키와의 재인용 관계를 보존한다.
- `NAMU_PHONOLOGY_20260908`: 음운 PDF 8쪽. 형태음운·발음/표기 관계 후보이며 일괄 철자 치환 근거가 아니다.

2026-09-09 [여섯 자료 통합 검토](../docs/KG_FEASIBILITY_2026-09-09.md) 완료.
이는 Claim 전수 검증이나 운영 Rule 승인과 다르다. 현재 구조화 스키마는 RYU 전용이며
다른 자료에 그대로 적용하지 않는다. 우선 용법·구성 단위의 설계 점검을 수행한다.

경상 어휘 JSON은 별도 어휘 후보이고, AI-Hub 경상도 코퍼스는 독립 평가 후보이다.
둘 다 현재 Claim 근거로 사용하지 않는다.

## 원자 단위 추출 원칙

1. Claim 하나에는 독립적으로 승인하거나 기각할 수 있는 주장 하나만 넣는다.
2. 모든 Claim에는 PDF 페이지와 해당 절·표·예문 위치를 기록한다.
3. 원문의 직접 진술, 표·빈도, 설문 결과, 예문 관찰을 `claim_basis`로 구분한다.
4. 예문 하나가 존재한다는 사실과 저자가 일반적 사용법으로 분석한 주장을 구분한다.
5. 원문에 없는 표준어 대응형·지역·의미·사용 조건을 상식으로 보충하지 않는다.
6. 방언 형태는 원문 철자를 `source_spelling`에 그대로 보존한다.
7. 문헌의 분류 용어는 `usage_conditions_raw`에 먼저 보존하고 공통 KG 용어로 미리 통합하지 않는다.
8. 문헌상 전통형이라는 사실과 현대 화자에게 자연스럽다는 판단을 분리한다.
9. 자료 안의 빈도는 그 자료의 관찰값으로만 기록하며 현대 사용 확률로 바꾸지 않는다.
10. 문헌 간 일치·충돌은 전수 추출 후 `claim_links`로 연결하며 어느 한쪽을 삭제하지 않는다.

## 지역 기록 원칙

`normalized_regions`에는 다음 네 값만 사용한다.

- `경상 전역 공통`
- `경북`
- `경남`
- `세부 지역 미상`

포항·안동·함양처럼 원문에 나온 세부 지역은 `subregions`에 별도로 보존한다.
`세부 지역 미상`은 표현의 신뢰도가 낮다는 뜻이 아니라 경북·경남을 가를 근거가
없다는 뜻이다.

## 검토 상태

- `unreviewed`: AI가 원문에서 추출했으나 사용자가 확인하지 않음
- `approved`: 원문 위치와 Claim 해석을 사용자가 승인
- `revised`: 사용자 검토에 따라 내용을 고침
- `rejected`: 잘못 분리했거나 원문보다 확대 해석하여 사용하지 않음

최초 추출물은 모두 `unreviewed`로 저장한다. 사용자 확인 전에는 Claim을 운영 Rule로
승격하지 않는다.

## 작업 순서

1. 문헌에서 페이지·절 단위 시험 구간을 먼저 정하고 방법·표 기호를 확인한다. 문헌당 5건이라는 수를 완료 기준으로 사용하지 않는다.
2. 검토용 표를 만들어 사용자와 원문 위치·분리 단위·해석을 확인한다.
3. 필요하면 이 추출 원칙과 스키마를 수정한다.
4. 기준이 승인된 뒤 문헌별 전수 추출을 수행한다.
5. 전수 추출 후에만 중복·지지·세분화·충돌 관계를 연결한다.
6. Claim 1차 검토가 끝난 다음 KG 노드·관계 초안을 설계한다.

JSONL은 KG 자체가 아니라 출처 기반 Claim 장부이다. 사용자 검토가 끝나기 전에는
Claim을 운영 Rule로 승격하지 않는다.

## 현재 전수 1차 초안

현재 검토 시작점은 [류성기 구조화 검토 문서](review/RYU2014_STRUCTURED_REVIEW.md)이다.
류성기(2014) PDF 38쪽 전체를 구간별로 처리하여 318건을 구조화했다.
생성 검토 후보 233건, 보류 37건, 맥락 전용 48건이다. 모두 사용자 미검토 상태다.
전체 페이지를 처리했다는 뜻이지 독립 검토로 무누락·무오류가 증명되었다는 뜻은 아니다.

이전 대명사 81건 및 초기 류성기 5건은 역사 기록으로 남긴다. 새 장부와 겹치므로 합산하거나
동시에 KG에 적재하지 않는다. 다른 두 문헌의 기존 파일럿은 아직 1.0 형식이다.

## 새 구조화 기준과 문법 분류

| 필드 | 역할 |
|---|---|
| `subject / predicate / object` | 무엇에 대한 어떤 사실인지 분리한 핵심 주장 |
| `category.primary / secondary` | 문법 대분류와 세부 분류 |
| `category.related` | 함께 조회할 다른 문법 범주(복수 허용) |
| `category.functions` | 의미·문법 기능의 잠정 검색 표지 |
| `grammatical_context` | 인칭·수·문장 유형·상대높임 등급 |
| `conditions` | 원문을 바탕으로 추출자가 정리한 적용 맥락 |
| `source_location / evidence` | 원문 절·PDF쪽·지면쪽·해당 항목과 근거 요약 |
| `geography / temporal_context` | 함양이라는 세부 범위와 조사 시점 |
| `attestation` | 초기 조사/후속 확인 구분. 알 수 없는 경우 명시 |
| `examples / cautions` | 원문 용례와 예외·불일치·일반화 금지 사항 |
| `review / generation_status` | 사람 검토 여부와 후보·보류·맥락 전용 구분 |

문헌의 절 제목을 문법 분류와 혼동하지 않는다. 예를 들어 대명사 절 각주의 ‘왜→와’는
원문 위치를 그대로 남기면서 분류는 부사로 기록한다. `-지 않다`처럼 범주가 겹치면
주 분류 하나와 관련 분류를 함께 기록한다. 이 분류는 추출자의 잠정 매핑이지 원문의
분석을 그대로 인용한 것이 아니다. 특히 ‘무슨/어느’의 품사, 보조용언의 피동·상태 변화,
형태소와 활용형의 구분 등은 후속 검토가 필요하다.

`null`이나 빈 조건 목록은 ‘아직 확정하지 못함’이지 ‘모든 문맥에서 허용’이 아니다.
`candidate`도 즉시 생성에 사용할 수 있다는 승인이 아니다. KG의 Category 노드와
Claim–Category 관계는 이 메타데이터를 바탕으로 설계할 수 있지만 아직 구현하지 않았다.

사용비율 수치는 새 장부에서 제외한다. 본문의 정성적 변화 설명을 보존한 경우에도
맥락 전용으로 두며 현대 생성 선택 확률이나 사용 금지 규칙으로 전환하지 않는다.
사용자의 ‘우리들 유지’, ‘너→니’ 등의 선택은 `structured/user_generation_choices.json`에
문헌 근거와 분리해 저장했다. 기존 원문 기록을 그 선택에 맞춰 고치지 않는다.

검증 명령: `python current_kg/claims/claim_review.py --check` (프로젝트 루트에서 실행).
현재 스키마에 사용하는 키워드만 검사하는 자체 검증기이며, 원문 해석의 정확성은 검증하지 않는다.

Claude 체크포인트의 역할·격리·실행 제한은 [체크포인트 안내](review/checkpoints/README.md)를 따른다.
첫 대상은 류성기 부정 절 9건이다. 검토가 끝나도 `review.human`을 자동 승인으로 바꾸지 않는다.
첫 외부 검토와 Codex의 원문 재대조·수정은 완료했다.
[검토 의견별 처리 결과](review/checkpoints/RYU2014-NEGATION-001/decision.md)를 따른다.
수정본의 외부 재검토와 나머지 309건의 외부 검토는 아직 수행하지 않았다.

## 이전 구간 시험(역사 기록)

함양 논문 2.1 대명사 절의 재추출본은 `raw/ryu2014_pronouns_section.jsonl`이다.
81건(표 행 44건, 본문·각주 37건)의 AI 원문 재대조 결과와 미해결 항목은
`review/RYU2014_PRONOUN_AUDIT.md`를 따른다. 기존 파일럿의 RYU2014-C0001/C0002는
새 C0103/C0134와 겹치므로 합산하지 않는다. 다른 절의 기존 파일럿도 아직 검증 전이다.
표본을 늘렸다는 사실만으로 스키마나 KG가 검증되었다고 보지 않는다.
