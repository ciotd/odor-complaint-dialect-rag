# Claude 검토 체크포인트

Claim 원본의 편집자는 Codex 하나다. Claude는 고정 입력을 검토하여 문제와 수정안을
응답으로 반환한다. Claude의 통과 판정은 사람 승인이나 운영 Rule 승인이 아니다.

## 최소 구성

- 실행기: `current_kg/claims/checkpoint_review.py` (프로젝트 루트에서 실행).
- 체크포인트별 `packet.json`: 대상 Claim 스냅샷·필요 원문 구간·검토 기준·원본 해시.
- `review.json`: Claude의 원 응답과 실제 모델·사용량·격리 시험 결과. Codex가 저장한다.
- `decision.md`: Codex의 수용/반박/보류 및 원문 근거·반영 내역. 현재 상태의 시작점이다.

실제 Claim 장부는 `structured/ryu2014_claims.jsonl` 하나다. packet의 복사본은 특정 버전에
대한 검토 증빙이며 KG 적재 대상이 아니다. 완료된 체크포인트 입력·응답을 덮어쓰지 않는다.

## 권한 경계

1. Linux bubblewrap으로 호스트 파일시스템을 읽기 전용으로 마운트한다.
2. Claude의 임시 실행 공간만 독립적인 `/tmp`로 제공한다. 기존 프로젝트 임시 파일과도 분리된다.
3. Claude 인증 파일은 읽기 전용으로 제공한다. 인증 갱신이 필요하면 실행이 실패할 수 있다.
4. `--safe-mode`로 사용자/프로젝트 확장·훅을 비활성화하고, `--tools ""`로 모델의 도구를 제거한다.
5. MCP도 빈 구성만 허용한다. 권한 우회 옵션은 사용하지 않는다.
6. 실행 전 기존 Claim·실행기 파일의 쓰기용 열기가 `EROFS`로 거부되는지 시험한다.
7. 실행 후 입력 파일 해시가 그대로인지 확인한다. 검사 실패 시 자동 수정을 하지 않는다.

이 구성은 원본 쓰기를 막는 것이며, 호스트 전체를 읽기 불가능하게 만드는 별도 기밀성
샌드박스는 아니다. 모델에 제공하는 연구 자료는 packet으로 한정하고 파일 읽기 도구는 없다.
Claude 서비스 호출에 필요한 네트워크는 상위 환경 정책을 따른다. 권한이 막히면
격리를 해제하여 우회하지 않는다. packet에 포함한 자료는 Claude 서비스에 전송된다.

## 검토·반영 원칙

- 원문에서 먼저 사실을 정리하고 Claim의 근거와 누락을 양방향 검토한다.
- 각 대상에 pass/revise/hold, 문제의 쪽수와 수정 제안을 요구한다.
- Codex는 원문을 재확인하고 의견별 수용/반박/보류 사유를 남긴다.
- 쟁점은 무조건 합의하지 않는다. 의미·지역·현대 자연스러움 판단이 남으면 사람에게 올린다.
- 원칙적으로 1차 검토와 필요한 수정 재검토까지만 수행한다. 자동 무한 반복은 없다.
- 모델, 입력 해시, 실행 시간과 반환 사용량을 기록한다. 비용 숫자는 CLI 보고값이며 실제 청구와 다를 수 있다.
- 최초 실행 제한은 240초·CLI API 예산 상한 2달러다. 구독 이용 한도는 별개다.

## 다른 터미널에서 보기

현재 방식은 비대화형이며 대화 세션을 디스크에 남기지 않는다. `claude --resume`이나
다른 터미널의 대화형 UI로 붙는 방식이 아니다. 프로세스는 다음처럼 확인할 수 있다.

```bash
pgrep -af 'checkpoint_review.py review|claude --safe-mode'
```

완료 후 `RYU2014-NEGATION-001/decision.md`와 `review.json`을 읽으면 된다.
현재 실시간 토큰 스트리밍·터미널 공유는 구현하지 않았다. 응답은 실행 종료 뒤 Codex가 저장한다.
