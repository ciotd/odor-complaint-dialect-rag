## 확인된 문제와 처리

### 사용자용 설명 및 피드백 반영

아래 C번호는 문헌에서 추출한 문장에 붙인 관리번호다. 서로 다른 방언 표현의 이름이 아니다.
기존 번호 중심 감사 기록은 이 절 아래에 보존하며, 우선 이 설명을 읽는다.

| 항목 | 실제로 문제였던 내용 | 현재 처리 |
|---|---|---|
| 1. 사용 비율 | 옛 C0001은 '내한테: 60대 10, 10대 0', C0002는 '먼: 60대 80, 10대 0'이라는 표 기록 | 사용 수치와 수치만으로 도출한 세대별 선호는 현재 생성용 지식 선정·가중치에서 제외. 원문 감사 기록에는 보존 |
| 2. 우리들 | 본문(C0149)은 두 세대에서 활발하다고 했으나 표(C0109)는 60대 (x), 10대 (100) | 표현 두 종류라는 뜻이 아님. 사용자 지침: 우리들 → 우리들 유지 |
| 3. 니·느·너그 | 세 형태를 묶은 본문 설명과 형태별 표 수치가 다름 | 사용자 확인: 너/네 → 니, 너희 → 너그. 느는 이번 의견에서 확인되지 않음 |
| 4. 니의 증가 | 표에 니는, 니가, 니 신발이가가 따로 있어 세대별 변화 방향이 다름 | 사용자 의견은 반말 2인칭 너의 니 변환을 지지. 세대별 증가·감소는 생성 조건으로 쓰지 않음 |
| 5. 3인칭 | 표준 얘/걔/쟤에 대응한 야/가/자의 10대 값이 각각 0/0/5인데 본문은 5로 요약 | 이 숫자로 형태를 배제하거나 채택하지 않음. 형태 자체는 별도 검토 |
| 6. 머만 | '머만'이라는 방언 단어가 아님. 본문 '머만 많이 쓰인다'에서 머 + 한정 조사 만 | 표에는 뭐도 기재됨. 뭐/머 중 하나만 허용한다는 규칙을 만들지 않음 |
| 7. 저하고 | 표의 표준형 저, 방언 칸 (제), 예문 내하고가 서로 다름 | 사용자 지침 저하고 → 내하고를 기록. 표 전체의 (제)를 내로 수정하지 않음 |
| 8. 판독 | PDF 9/지면 63 본문 '…, 그거, 요거'에서 첫 형태 글자가 추출 시 깨짐 | 확대 화면에서도 해당 표기를 확정하기 어려움. PDF 10 표에 명확한 이것 → 이게는 별도 근거로 사용 가능 |
| 9. 각주 | PDF 9 각주 9가 이리·거리·저리를 나열하며 거리에 대응 방언형이 없다고 씀 | 거리 자체가 오자인지 확정 불가. 일반 명사 거리의 방언이 없다는 주장으로 확장하지 않고 생성용 채택 보류 |
| 10. 기호 | 같은 형태면 비율을 비운다고 했지만 자네→자네, 요것→요것 행에는 값이 존재 | 표 형식의 일관성 문제. 실제 방언 판단을 사용자에게 요청할 항목은 아님 |

사용자 의견은 이 대화에서 제공된 연구 지침·사용 보고이다. 독립 화자 표본 검사나 문헌
주장 승인으로 표시하지 않는다. 아래 선택은 향후 운영 Rule 설계의 입력으로 보존한다.

| 표준 표현 | 선택할 표현 | 근거와 범위 |
|---|---|---|
| 우리들 | 우리들 | 사용자 유지 지침 |
| 너 / 2인칭 네 | 니 | 사용자 사용 보고. 네(긍정 응답)에는 적용하지 않음 |
| 너희 | 너그 | 사용자 사용 보고 |
| 저하고 | 내하고 | 사용자 변환 지침. 1인칭 저+하고에 한정; 지시 표현 저와 구별 |

이 선택은 아직 실행 코드에 적용된 치환 규칙이 아니다. 현재 생성 시스템은 구현 전이며,
최종 Rule에서는 조사 결합과 문장 전체의 높임 조건을 함께 기록한다.

81건은 원문 감사용 추출 기록 수다. 수치 정보까지 포함한 이 수를 활성 생성용 Claim
수로 보고하지 않는다. 형태·용례와 수치가 섞인 행은 후속 정리에서 형태 근거만 분리한다.

### 이전 감사 기록

1. **수치 해석 오류**: 과거 파일럿 C0001/C0002의 ‘사용 비율’은 응답자 비율로 오해될 수 있다.
   새 기록에서는 표의 ‘사용 정도’와 확인자 구성을 붙였다. 이전 C0003~C0005의 ‘몇 %가
   사용’ 표현도 같은 위험이 있으나 해당 절은 이번 검증 범위 밖이다. 재검증 전 재사용 보류.
2. **우리들**: PDF 6 본문은 두 세대 모두 활발한 사용이라 하지만 PDF 7 표는 60대 (x).
   C0149와 C0109를 병존시킨다.
3. **니·느·너그**: PDF 7 본문은 두 세대 약 50%라 하나 PDF 8 느·너그의 10대는 0.
   C0153과 C0119/C0121을 병존시킨다.
4. **니의 증가**: 본문은 증가로 요약하지만 표에서 너는 50→40, 네가 30→55, 네 물건 50→75.
   표면형만으로 합치지 않고 문맥별 세 행으로 남겼다.
5. **3인칭 10대 5%**: PDF 9 본문 요약과 표(야 0·가 0·자 5)를 구분한다.
6. **머만**: PDF 9 본문은 10대에서 머만 많이 쓴다고 하지만 표의 뭐는 100.
   본문과 표를 서로 수정하지 않았다.
7. **저하고**: PDF 7 표준형은 저, 방언 칸은 (제), 예는 내하고이다.
   셋을 동일하게 고치지 않고 C0107에 불일치를 기록했다.
8. **판독 보류 1곳**: PDF 9 본문의 ‘그거, 요거’ 앞 첫 지시형은 추출 글자가 깨지며
   화면에서도 판독이 확실하지 않다. C0170은 확실한 두 형태만 포함한다. PDF 10 표의
   이게와 동일하다고 추정하지 않았다. 따라서 글자 수준의 완전 추출은 아직 주장할 수 없다.
9. **각주 원표기**: PDF 9 각주 9의 ‘거리’를 임의로 ‘그리’로 고치지 않았다.
10. **표 기호 예외**: 표의 같은 표준형·방언형에도 자네·요것 등의 수치가 기재된다.
    각주 4의 일반 설명으로 표를 덮어쓰지 않고 각 칸을 보존한다.

위 항목은 같은 원문에서 AI가 확인한 차이이며, 모두 저자의 오류라고 확정한 것은 아니다.
오류율이나 정밀도·재현율을 계산하지 않았다. 독립 정답 집합이 없고 자체 검토이기 때문이다.

## 작업량과 한계

8개 PDF 페이지에 걸친 구간을 읽고, 표 4쪽과 방법 2쪽은 화면으로 확인했다.
81개 후보를 기록했지만 이 중 44개는 표 행이다. 표 중심 절의 수를 논문 전체에 곱해
총 Claim 수나 비용을 추정하면 과대·과소 추정 모두 가능하다.

정확한 API 입력·출력 토큰 사용량은 이 실행 환경에서 제공되지 않아 측정하지 못했다.
로컬 시각으로 17:49~17:54에 추출·구조화·재대조·형식 검사를 수행했다(약 5분).
이 구간은 최초 파일 탐색 시간과 이후 사용자 검토 시간을 포함하지 않는다.
JSON 규격에 사용된 필수 필드·형식·enum·내부 참조·길이·날짜 등을 로컬 검사하여
81건이 통과했다. 정식 jsonschema 라이브러리 검증을 수행한 것은 아니다.
파일럿 당시의 15건 검사 결과는 새 81건의 검증 결과를 대신하지 않는다.
