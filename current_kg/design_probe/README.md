# 새 Claim → 최소 그래프 설계 점검

작성: 2026-09-10. **현재 사용자가 확인할 결과 문서**.

추가 진행: 최초 그래프 방향에 대한 사용자 확인 후 조사·시제·부정을 보완 점검했다. 보완 결과는 7절, 첫 시험 이력은 1–6절이다. 이후 정식 재추출을 시작했으며 현재 결과는 [첫 구간 검토](../claims/v3/BATCH_001_REVIEW.md)에 있다. 아래 추출 전 문구는 시험 당시의 이력이다.

## 1. 무엇을 했나

승인한 포맷 예시를 실제 JSON으로 작성하고 Python 표준 라이브러리로 메모리 안에 노드·관계 그래프를 구성했다. DB 설치·외부 모델 호출·생성 실험은 하지 않았다. 이전 318건을 읽거나 변환하지 않았다.

T01–T05는 [포맷 문서](../docs/CLAIM_FORMAT_V3_DRAFT.md)의 D01–D05에 대응한다. T06은 예외를 연결할 일반 설명, T07은 논문에 관찰된 같은 형태를 추가한 것이다. **7건은 설계 시험용이지 전체 추출본이 아니다.** 기존 예시와 합산하지 않는다.

| 기록 | 내용 | 원문 위치 |
|---|---|---|
| T01 | 동사/형용사 부르다의 대조 | 상대높임법 PDF 14·33쪽 |
| T02 | 좋니더/좋으이더 복수 허용 | 상대높임법 PDF 14쪽 표 |
| T03 | -구로/-그로의 목적·강조 조건과 제한 | 문법 PDF 48쪽 각주 76 |
| T04 | -구로/-그로 경북 우세, -고로 경남 우세 | 문법 PDF 48쪽 각주 77 |
| T05 | -니이더의 세대·보수적 사용 설명 | 상대높임법 PDF 14쪽 |
| T06 | 형용사 어간 말음에 따른 니더/이더 일반 설명 | 상대높임법 PDF 14쪽 |
| T07 | 안동 자료의 좋으이더 관찰 | 조현준 PDF 90쪽, 예문 40ㄱ |

포맷을 승인한 것과 개별 문법 주장을 정답으로 검증한 것은 다르므로 모든 기록의 언어학적 사용자 검증 상태는 미검증이다. 발췌 문자열은 읽기 위한 선택 발췌·줄바꿈 정리이며 PDF 전문을 대체하지 않는다.

## 2. 어떤 노드와 관계를 만들었나

```text
용법(동사 부르다 / 형용사 부르다)
  ↑ about
주장 세부 항목(허용 예 / 문헌의 X 판정)
  ↑ asserts
Claim ──supported_by──→ 근거 ──from_source──→ 원문 자료
  ├──annotated_by──→ 지역·시대·사용 맥락 주석
  └──asserts──→ 결합 설명 ──condition──→ AND/OR 조건
                                             └──evaluates──→ 조건 검사 대상

T02 좋다 예외 ──exception_to──→ T06 일반 결합 설명
T07 논문 관찰 ──same_form_observed──→ T02 위키 예외
T03 의미 조건 ──distribution_context──→ T04 지역 분포
P01 생성 정책 ──applies_to──→ 안동 중심 니껴형 서술 구성
```

- **용법 노드**: 같은 철자도 뜻·품사가 다르면 구별한다.
- **Claim과 세부 항목**: 사람이 함께 이해해야 할 주장 묶음을 유지하면서 허용 예·거부 예·조건을 각각 조회한다. 세부 항목 수를 Claim 성과로 세지 않는다.
- **조건 노드**: ‘목적 OR 강조’, ‘형용사 AND 자음 말음’처럼 논리와 검사 대상을 명시한다. 아직 자연어 문장에서 이 값을 자동 추출하지는 않는다.
- **근거 노드**: 어떤 문헌의 어느 위치에 기대는지 따라간다. 논문 관찰과 위키 일반 설명을 하나의 사실로 병합하지 않는다.
- **주석·정책 노드**: 문헌의 지역·세대 설명과 우리의 생성 우선순위를 분리한다.

지역명과 문법 범주는 이번에는 주석·속성으로 저장했다. 모든 정보를 별도 노드로 만들어야 KG가 되는 것은 아니다. 추후 하위 지역 관계 조회가 필요하면 지역 노드·관계를 추가하되, 상위 지역에서 하위 전역의 사용을 추론하지 않는다.

## 3. 실제 조회 결과

| 질문 | 확인된 결과 |
|---|---|
| 같은 ‘부르다’를 구별해 찾는가? | 동사: 친구가 부르니더 / 형용사: 배 부르이더. 문헌의 X 예는 별도 조회 |
| 일반 설명만 찾고 예외를 놓치는가? | T06에서 역방향 관계를 따라 T02 예외를 찾을 수 있음 |
| 좋으이더의 논문 근거는? | T07 → e.jo → JO2018, PDF 90쪽. 위키 근거와 구별 |
| -구로의 의미 조건은? | 목적·강조 입력은 일치, 방식 입력은 불일치, 입력 미확보는 null |
| -고로에도 같은 의미 제한을 적용하는가? | 해당 조건 연결 없음. 자동 복사하지 않음 |
| 어간 말음이 없으면 일반 결합을 허용하는가? | null. 정보 부족을 무조건 허용으로 바꾸지 않음 |
| 고령층 설명이 -니더 전체로 퍼지는가? | 아니요. -니이더를 대상으로 한 세부 항목만 조회 |
| 생성 우선순위가 문법 사실과 섞이는가? | 별도 P01 정책으로 조회 |

**조건 일치=true는 생성 허가나 자연스러움 보증이 아니다.** 기록된 한 조건에만 맞는다는 뜻이며 다른 결합·높임 조건은 별도로 필요하다. 불일치도 해당 조건의 불일치이지 모든 경상도에서의 비문 판정이 아니다.

27개 검사 통과: 조회·조건/보존 검사 21개, 일부러 잘못 만든 입력을 거부하는 검사 6개. 후자는 누락 참조·중복 ID·잘못된 PDF 쪽·빈 논리 조건·근거 없는 주석·미확보 사유 누락을 검사한다. 노드 73개/관계 139개는 구현 규모일 뿐 연구 성과 지표가 아니다.

## 4. 아직 검증하지 못한 것

- 시험에 쓰인 품사·의미·말음은 작성자가 지정했다. 자동 문장 분석·형태소 분석기는 아니다.
- 일반 설명과 예외의 관계를 조회했지만, 충돌 시 최종 선택하는 운영 규칙 엔진은 만들지 않았다.
- 모든 필드를 보존하는 검사와 일부 의미 경로의 조회를 수행했다. 모든 주석을 자동 추론하거나 모든 문법 상호작용을 검사한 것은 아니다.
- 현재 검증기는 시험 포맷의 참조·조건·필수 정보 검사다. 모든 필드의 자료형과 미지 필드까지 엄격히 검사하는 범용 JSON Schema는 아직 아니다.
- 원문의 표현에 대한 현대 화자 평가나 독립적인 언어학적 진위 검증이 아니다.
- 조사·시제·부정·보조용언 등이 함께 있는 일반 문장의 생성 가능성을 이 작은 시험으로 증명하지 않는다.
- 서로 인용할 수 있는 위키와 논문을 독립 증거 두 개라고 가중하지 않는다.

## 7. 조사·시제·부정 보완 점검 — 2026-09-10

### 완료한 일

특정 Source ID·지역·PDF 상한을 고정하지 않는 [시험용 JSON Schema](claim_bundle.schema.json)를 추가했다. 실제 PDF 쪽 상한과 자료 사용 가능 여부는 자료 통제표에서 검사한다. 필수 필드·자료형·알 수 없는 필드·참조·조건 논리를 검사하며, 표준 라이브러리만으로 지원 키워드를 검증한다. 지원하지 않는 스키마 키워드는 조용히 무시하지 않고 오류를 낸다.

단, 주장 `content`, 주석 `value`, 문법 대상 `properties`의 내부 의미별 필드는 아직 확장 영역이다. 모든 문법 범주를 위한 엄격한 최종 스키마가 완성됐다고 주장하지 않는다. 전량 추출에서 새로운 내용 유형이 나오면 예시·필드를 먼저 검토하고 버전을 관리한다.

류성기 원문 PDF 10–11쪽, 19–22쪽을 다시 확인하고 아래 네 기록을 추가했다. 기존 318건은 읽거나 변환하지 않았다.

| 기록 | 구조화 내용 | 과잉 일반화를 막는 장치 |
|---|---|---|
| R01 | 초기 방언형 기술에서 안/못과 장형 부정의 사용 여부 | ‘초기 방언형 기술’이라는 맥락에 한정 |
| R02 | 후속 세대의 -지 못- 및 -지 않- 등장 설명 | R01과 사용 변화 관계로 연결. 60대/10대 설명을 구별 |
| R03 | 미래를 -ㄹ 끼다 또는 내일 같은 명사+현재형 -ㄴ다로 표현 | 동반 표현을 보존. 문헌의 미래 표현 목록 전체라고 주장하지 않음 |
| R04 | 목적격 조사 표의 밥을 묵어라 / 밥 무라 | 관찰 가능한 대조만 저장. 모든 목적격 조사를 삭제할 수 있다고 만들지 않음 |

사용비율 수치는 넣지 않았다. R01/R02를 합쳐 ‘함양에서는 장형 부정 금지’라고 만들면 원문의 후속 설명을 잃게 된다. 또한 R04는 묵어라/무라 차이도 있으므로 조사 삭제만 다른 최소대립 예로 취급하지 않는다. 근거의 `excerpt`는 확인 위치를 안내하는 선택 발췌 또는 요약이며 인용문 정확성 검사를 통과한 문자열 필드가 아니다. R01/R02의 발췌는 본문의 요약이다. 원문 표기 보존은 예문 필드와 원본 PDF를 기준으로 확인한다.

### 검사 결과와 한계

- 기존 27개 회귀 검사 통과.
- 새 조회 검사 10개: 부정의 단계별 조회, 세대 구분, 미래의 동반 표현, 조사 생략 조건 미확보, 출처 경로 등.
- 추가 오류 입력·검증기 검사 10개: 필드 오타·자료형·필수 정보·비활성 자료·미지원 키워드 등.
- 합계 47개 통과. 시험 묶음은 기존 7건+신규 4건인 **11건**이다. 두 JSON 파일의 중복 7건을 합산하지 않는다.

이 시험에서 논문의 기술 단계를 사용 맥락의 `description_phase`로 구별했다. 이를 임의의 역사적 연대나 모든 현대 화자의 사용 단계로 해석하지 않는다. 그래프 조회의 빈 결과도 ‘쓰지 않는다’가 아니라 해당 범위의 근거를 기록하지 않았다는 뜻이다.

기계 검사는 우리가 넣은 내용을 올바르게 보존·조회하는지 확인한다. 원문에서 빠뜨린 정보, 잘못된 해석, 현대 자연스러움까지 자동 검증하지 않는다. 전체 문장의 여러 문법 요소를 조합하는 생성 실험도 아직 아니다.

## 8. 전량 추출을 시작하는 방식

추가 파일럿을 끝없이 늘리지 않는다. 다음 작업은 **동남 방언/문법 PDF의 첫 문법 본문(활용·불규칙, PDF 3–7쪽)**부터 새 정식 추출 장부를 시작하는 것이다. 본문에 연결된 각주도 함께 확인한다. 범지역적 활용 정보 후보를 먼저 검토하되, 이 문서에 실렸다는 이유만으로 전역 공통이나 현대 우선 표현으로 확정하지 않는다.

시작 구간이 문헌의 목차·원문 대조상 달라지면 실제 처리 위치를 기록한다. 원문 검토 → 출처·조건·맥락을 담은 추출 → 구조 검사 → 원문 재대조 → 사용자 보고를 한 구간 단위로 수행한다. 문서·절·페이지의 처리/제외/보류와 이유를 별도 장부로 남겨 ‘전체 검토’와 ‘모든 문장 Claim화’를 구별한다.

첫 구간을 마치면 실제 작성량, 사용 시간 측정이 가능한 범위, 판독·조건 문제를 보고한다. 비용 측정 수단 없이 토큰 사용량이나 전량 소요시간을 확정하지 않는다. 의미별 새 필드가 필요한 경우 기존 자료를 무조건 재작성하지 않고 구조 변경의 이유·영향을 설명한다. 전체 여섯 문헌을 검토한다는 범위는 유지하며 조사 배경·통계 수치 등을 억지로 문법 Claim으로 만들지 않는다.
