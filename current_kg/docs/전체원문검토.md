### 중요한 발견

1. **문서 내부 충돌:** 8쪽 표는 -으시- 뒤를 ㄴ계열로 묶지만 11쪽은 -시- 단독의 ㄱ계열 유지를 설명한다. 자동 병합하지 않는다.
2. **각주가 제약을 담음:** 28쪽 -게/-도록→-구로/그로/고로 대응은 48쪽 각주 76에서 목적·강조로 한정하고 ‘빠르게 해라’를 반례로 든다. 대응표만 추출하면 과잉 적용한다.
3. **동일 표면형·서로 다른 기능:** 46쪽 각주 15는 마르다의 ‘말라’와 말루다의 ‘말라’를 강세로 구분한다. 텍스트 생성에서는 의미·구성 정보를 보존해야 하며 철자만으로 모든 구별을 구현할 수 없다.
4. **관찰을 필수조건으로 만들 위험:** 23–25쪽의 세대별 문장 일부는 원문이 직접 ‘예상’이라고 밝힌다. 13쪽 ‘50대 이상’ 및 25쪽의 ‘절대’도 독립 검증된 사용률이 아니다.
5. **범위 유보가 많은 어휘:** 26쪽은 어휘의 지역 차이·출처 불확실성을 스스로 경고한다. 전량을 같은 강도의 규칙으로 만들지 않는다.
6. **평서/의문 단순 대조 충돌 후보:** 49쪽 각주 90은 -지 평서/-제 의문이라고 요약하지만 12쪽은 설명 의문 -지도 제시한다. 범위 제한을 확인해야 한다.
7. **문법 범주 밖으로 확장하면 안 되는 예:** 19쪽은 -웋-이 비사동 동사에도 나타난다고 한다. 형태에 -우/-웋이 있다는 이유만으로 사동 기능을 자동 부여하지 않는다.
8. **표 화면 대조:** 18쪽은 철자행과 발음행을 따로 가진 활용표, 42쪽은 수사·수관형사·순차계수 세 종류의 표다. 열을 펼쳐 일반 대응표로 만들면 기능 구별이 소실된다.

3. 표준어와 같은 형태도 실제 방언 체계 안에서 쓰인다. 방언 생성은 모든 형태를 방언 전용형으로 바꾸는 작업이 아니다.
4. 관찰 빈도, 미출현, 유추한 가능형, 저자의 역사적 분석, 직접 제시된 결합 조건을 서로 다른 근거 종류로 기록한다.
5. 혼용은 곧 오류가 아니다. 문장 기능·대화 관계·자료 범위에 따라 허용되는 실제 교체와 부적절한 결합을 구별해야 한다.

## 7. 전체 문법 범위 — 무엇을 구축할 수 있고 무엇이 부족한가

아래의 풍부/부분/부족은 이번 원문 집합의 서술 범위에 대한 정성 판단이다. 전체 한국어 문법을 분모로 계산한 커버리지 수치가 아니다.

| 영역 | 자료에서 확보할 수 있는 내용 | 연결해야 할 다른 영역 | 남은 공백 |
|---|---|---|---|
| 문장 유형·종결 | 평서/의문/명령/청유, 판정/설명/확인/수사/자문, 감탄·약속 용법. 매우 풍부 | 서술부 종류·선어말·높임·참여자 | 모든 문맥의 의도 추론, 억양 없이 다의성 해소 |
| 높임·대우 | 주체높임과 상대높임, 어체별 형태·요/예/여 결합·교체. 매우 풍부 | 문장 기능·서술부 구성·대화 관계 | 문헌 간 등급 통일, 현대 사용 적합성, 객체높임 전반 |
| 어간·활용·파생 | 특정 어간군, 불규칙/축약, 사동/피동 일부. 풍부하나 어휘별 차이 | 어휘 의미·품사·후행 형태·높임/명령 | 모든 어휘의 활용표, 사동/피동 논항 전환 전체 |
| 조사·명사구 | 격·보조사·접속조사·대명사·의존명사·수량 표현. 부분적 | 참여자 역할·절 구성·말음/계사 | 일반 동사별 필수 참여자, 조사 생략·중출·초점의 전 체계 |
| 연결·내포·인용 | 조건·원인·목적·양보·동시/나열, 인용과 카다, 관형형. 부분적 | 절간 관계·서술부·음운 축약·의존명사 | 임의 복문의 전체 구조, 장거리 연결·중의성 해소 |
| 시제·상·양태·부정 | 과거/회상/미래 구성, 진행/완결/반복·추측/의무·안/못/금지. 부분적 | 보조용언·종결·활용·절별 적용 범위 | 상호작용의 완전한 조합표, 중첩 부정·양태 범위·상대시제 |
| 담화·화용 | 강조·당부·친밀·확인·호칭·담화표지 사례. 부분적 | 문장 형식과 발화 기능·관계/장면 | 숨은 의도·공손 전략의 포괄적 추론 |
| 형태음운·표기 | 모음/자음 변화·탈락·준말·발음과 표기 차이. 부분적 | 어간 활용·인용 구성·어휘 의미 | 운소 체계 전체, 발음 변이의 출력 철자 선택 정책 |

문헌2종은 서로 보완적이다. 류성기는 범주가 넓지만 함양의 좁은 표본·요약표 중심이고, 조현준은 종결/높임을 깊게 다루지만 과거 경북 구술 자료 중심이다. 위키는 더 넓은 현상을 연결하지만 재인용·편집 의견·추정·중복이 섞여 있다. **문헌은 무조건 정답, 위키는 무조건 폐기라는 방식도 적절하지 않다.** 개별 내용과 관계의 근거를 판단해야 한다.

일반 한국어 문법의 공통 틀은 입력과 연결하는 설계 장치로 사용할 수 있다. 그러나 자료에 없는 논항·범위 규칙을 ‘여섯 원문에서 확보한 방언 사실’로 넣어서는 안 된다. 필요하면 공통 문법 기반 지식과 방언 특유 지식을 분리하고, 추가 근거 확보는 별도로 논의한다.

### 노드와 관계의 최소 의미

‘조사/종결어미/부정’ 같은 범주 라벨은 찾아보기와 연결의 출발점이지, 그 자체로 생성 규칙이 아니다. 실제 선택에 필요한 중심은 **용법/구성**이다.

- 형태: -고, -시더, -이, -끼 같은 표면/형태 정보. 같은 철자가 같은 문법이라는 뜻은 아님.
- 용법: 그 형태가 특정 기능과 결합 환경에서 쓰이는 방식. 의문 종결 -고와 연결 -고는 구별한다.
- 구성: 둘 이상의 요소·자리·순서와 전체 기능. 구성요소들의 속성을 전체에 무조건 상속하지 않는다.
- 공유 개념: 질문·과거·완결·사동·목적·계사 등 문헌을 가로지르는 기능과 단위.
- 조건/예외: 어느 용법 또는 어느 결합에 적용되는지 지정한다. 문서 전체에 단일 조건을 달지 않는다.
- 근거: 특정 관계를 어느 쪽의 어떤 서술/예/각주가 뒷받침하는지 추적한다. 단순히 ‘같은 PDF 출신’은 문법 연결이 아니다.

예를 들어 개념 수준 triple 초안은 다음과 같다. 이름은 설명용이며 현재 저장된 새 노드 ID가 아니다.

```text
(설명 의문 기본 용법, 실현형, -(느)ㄴ고)
(요 결합 구성, 기본 용법, 설명 의문 기본 용법)
(요 결합 구성, 추가 요소, 요)
(요 결합 구성, 결과 형태, -(느)ㄴ고요)
(요 결합 구성, 결과 높임 해석, 해요체)
(요 결합 구성, 근거 위치, 상대높임법 PDF34 각주67)
```

실제 구현에서는 조건·순서·근거를 해당 관계/구성에 붙여야 한다. 이 구조라면 기능에서 출발하여 기본형→결합 구성→결과 형태/높임/근거를 연쇄 조회할 수 있다. 그러나 **연결 경로가 있다는 이유만으로 구성 전체의 생성 적합성까지 입증되지는 않는다.**

문헌 사이의 통합은 세 가지로 나눈다: 같은 용법의 추가 근거 / 같은 기능의 다른 실현형 / 서로 다른 설명·충돌. 표면형이 같거나 같은 기능 ID에 연결됐다는 이유로 모두 동의어·상호 교환형으로 만들지 않는다.

| 추출 글자·표 구조 손실 | 류성기9·21, 조현준의 옛한글/통계/부록 | 불명확 부분은 보류, 작성 대상 셀 화면 대조. 기계 추출 그대로 확정 금지 |

이 장부는 발견한 주요 문제이지 모든 오류의 전수 목록이나 오류율 계산 결과가 아니다. 원문에 대한 비판과 기존 KG 작성의 오류를 구별해야 한다.

## 10. 이제 실제 전체 구축을 진행할 방식

### 범위와 순서

1. **전 범위 지도 확보 — 이번에 완료.** 여섯 자료의 범주·연결·부족·충돌을 먼저 함께 보았다. 소수 표본의 성공을 전체의 대표로 삼지 않는다.
2. **전체 초안 작성 — 다음 작업.** 원문 위치별 처리 장부를 유지하면서 위 8절의 문법 묶음별로 여섯 문헌을 함께 참조한다. 문서별 완성 후 마지막에 연결하는 방식이 아니다. 순서는 어간/활용·어휘 의미 ↔ 서술부 기능·종결/높임 ↔ 조사/명사구·절 연결/인용 ↔ 표기/담화 보완으로 잡되, 발견한 교차 관계를 즉시 함께 작성한다. 기존 70건은 정답이 아니라 유지/수정/분리/제외 판정을 받을 초안이다.
3. **전체 통합 검토.** 중복 용법, 공유 개념만 잇는 형식적 연결, 끊어진 구성, 상충 조건, 문헌 종속성, 범주별 공백을 전체 그래프에서 점검한다. 자료가 없는 관계를 억지로 만들어 연결성을 높이지 않는다.
4. **입력과의 연결·조회 구현.** 입력의 관찰/해석, 사용자 또는 시스템의 출력 목표, 선택 후보 자체의 어간/어미 정보를 분리한다. 표준어 입력에 없는 방언 후보의 어간·후행 어미를 입력 분석기가 미리 맞히도록 요구하지 않는다. 현재 analysis_contract의 following_form 등은 이 구별이 부족하다.
5. **생성 연결과 비교.** 이 단계의 지식/조회 범위가 확인되면 동일 로컬 모델에서 지식 없음·같은 근거의 텍스트 활용·KG 활용을 구체화한다. 자연스러움 향상은 여기서 별도 검증하며 이번 독해의 결론으로 주장하지 않는다.

전체 초안을 다 쓴 뒤에야 오류를 처음 검사하는 것은 위험하다. **범위는 전체로, 검사는 작성 중과 전체 통합 후 두 번으로** 한다. 작성 중 검사는 끝없는 설계 승인을 받기 위한 소규모 파일럿 반복이 아니라 오류 누적 방지다. 범주·필드가 부족한 실제 사례가 나올 때만 최소 확장하고 이유를 보고한다.

### 관계 자체를 검증할 항목 — 앞으로 구현/실행할 계획

| 검증 | 무엇을 확인할 것인가 | 과장하면 안 되는 것 |
|---|---|---|
| 관계 근거 대조 | 기능·결합·예외 각각에 원문 근거가 있는지, 근거가 관계 강도를 지지하는지 | 원문 한 개가 관계 전체를 자동 인증하지 않음 |
| 연결 조회 | 위 8절의 질문에 대해 기능→용법→구성→조건/예외·근거가 실제로 반환되는지 | 같은 문서의 문단을 통째로 반환한 것을 다단계 추론으로 부르지 않음 |
| 조건 대조 | 계사/용언, 목적/방식, 본/보조용언, 명령/청유 등을 하나씩 바꿀 때 적절한 용법이 달라지는지 | 모든 대조쌍에 원문 근거가 있어야 하며 ‘원문에 없음’은 부정 정답이 아님 |
| 관계 제거 검사 | 사본에서 필요한 결합·제약 연결을 제거하면 예상 경로가 끊기거나 불완전으로 드러나는지 | 삭제 후 변화는 구현 의존성의 증거이지 문법 정확성 증거가 아님 |
| 통합 검사 | 같은 용법은 근거가 모이고 다른 용법은 분리되는지, 예외·시대·범위가 소실되지 않는지 | 연결 수/최대 연결성분 비율만 높이면 좋은 그래프라는 주장 금지 |
| 보류·공백 검사 | 근거 부족/충돌을 허용·금지로 오인하지 않고 반환하는지 | unknown 반환만 많으면 안전한 고품질 시스템이라는 주장 금지 |
| 독립 검토 | 사람이 검토할 수 있는 근거·경로·판정표를 제공하고 독립 검토자와 이견을 남기는지 | 작성자 검사나 두 모델 합의를 언어학적 정답으로 사용 금지 |

구현 검사는 구축 과정의 품질 관리이고, 비교 실험은 별도 설계다. 동일 근거에서 관계를 유지한 조건/구조를 약화한 조건 등을 비교하려면 평가 단위·정답/판정 근거·보류 처리·개발/평가 분리를 먼저 고정해야 한다. 이번 작업에서 그러한 실험을 수행하지 않았다.
