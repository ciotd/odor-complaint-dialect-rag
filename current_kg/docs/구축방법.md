# 경상도 문법 KG — 연결 원리·구축·검증 방법

작성: 2026-09-17. 이 문서는 대화 로그가 아니라 구축 방법을 설명하는 연구 문서다. **현재 원문 검토로 확인한 내용, 구축 정책, 아직 수행하지 않은 검증 계획을 구별한다.**

목적은 경상도 방언의 문법 체계를 그래프로 표현하고 형태·기능·결합 관계를 활용하여 의미를 유지하는 자연스러운 방언 생성을 시도하는 것이다. KG의 효과는 검증 대상이지 전제가 아니다.

원문별 분석·문제 위치는 [전체원문검토.md](전체원문검토.md), 현재 합의·상태는 [연구미팅.md](../../연구미팅.md)를 따른다. 아래 쪽수는 PDF의 물리적 쪽수다.

## 1. 지금 완료한 것과 앞으로 작성할 것

6종·452쪽 전 범위 텍스트 독해에 기초한 **1차 범위·연결·문제 분석**을 마쳤다. 이것은 모든 문법 진술을 개별 단위로 목록화하거나 모든 관계를 확정한 전수 주석 작업과 다르다. 7쪽은 선별 화면 대조했으나 모든 표 셀·특수 글자·재인용 원전을 독립 검증하지 않았다.

초기 70건 이후 직접 작성을 확대하여 현재 331건을 저장했다. 개별 문법 진술 관계 1,033개와 통합·대조 관계 50개가 실제 그래프에 들어 있다. 전체 원문 독해와 개별 설명의 전수 작성은 다르며, 후자는 아직 미완료다. [전체 작성·연결 점검](../grammar/작성검토.md)에 모든 통합 관계의 근거·이유·한계, 보류, 채택하지 않은 연결을 기록했다. 출처별 작성 수와 쪽 상태는 [progress.json](../grammar/progress.json)이 기준이다.

## 2. 왜 형태만이 아니라 용법과 구성을 중심에 두는가

형태는 관찰되는 어간·어미·조사 등의 모양이다. 용법은 그 형태가 특정 기능과 환경에서 쓰이는 방식이다. 구성은 여러 요소와 그 자리·순서가 함께 특정 기능을 나타내는 구조다. 모든 지식을 반드시 다요소 구성으로 만들지는 않는다.

예컨대 같은 `-고`라도 의문 종결과 인용·연결을 한 용법으로 합칠 수 없다. 반대로 서로 다른 형태가 같은 기능을 나타내더라도 결합 조건까지 같다는 뜻은 아니다. 기본 종결형에 `요`가 더해진 구성의 높임 해석은 기본형의 등급을 그대로 상속해서도 안 된다. 이러한 **동형의 기능 차이와 결합 전체의 기능**을 보존하려고 용법·구성을 명시적으로 둔다.

이는 특정 언어학 이론을 전면 채택했다는 선언이 아니라, 이번 자료의 다의성·결합·조건을 손실 없이 기록하기 위한 설계 선택이다. 논문에서는 실제 사례와 대안 표현 방식의 한계로 정당화해야 한다. 노드 이름을 붙였다는 것 자체가 새 이론이나 실험적 우월성은 아니다.

### 문헌 간 통합의 판단 절차

1. 형태뿐 아니라 기능, 문법적 자리, 결합 환경, 적용 범위, 지역·시대 정보를 함께 비교한다.
2. 같은 용법으로 판단할 근거가 충분하면 공통 용법에 근거를 모은다. 각 자료의 적용 범위는 근거별로 남긴다.
3. 같은 기능의 다른 표현이면 기능 노드를 공유하되 용법과 조건은 별도로 둔다. 자동 상호 대치 관계로 만들지 않는다.
4. 동형이지만 기능·자리가 다르면 다른 용법으로 분리하고 형태 정보만 공유할 수 있다.
5. 복합 구성은 구성요소, 순서, 전체 기능과 전체에 적용되는 조건을 별도로 기록한다.
6. 설명이 충돌하거나 동일성 판단이 불충분하면 억지로 병합하지 않는다. 차이·충돌·검토 필요를 기록한다.

같은 문서에 나온다는 사실, 같은 품사라는 사실, 같은 철자라는 사실은 그 자체로 결합 가능성의 근거가 아니다. 공유 기능을 경유한 경로도 곧바로 의미 동등성이나 실제 결합 가능성을 뜻하지 않는다.

## 3. 연결의 종류 — 현재 필요한 관계 계열 전체

아래는 의미상 관계 계열이다. 최종 영문 edge 이름이나 기존 JSON과의 일대일 대응을 확정한 표가 아니다. 실제 작성 중 새 관계가 필요하면 근거와 이유를 함께 추가한다.

| 관계 계열 | 무엇을 연결하는가 | 해서는 안 되는 추론 |
|---|---|---|
| 범주·하위 유형 | 용법/구성 → 의문·조사·보조용언 등 분류 | 같은 범주이면 자유롭게 결합한다 |
| 기능 | 특정 용법/구성 → 설명 의문·완결·목적 등 | 같은 기능이면 모든 문맥에서 대치된다 |
| 형태 실현·변이 | 용법 → 형태, 근거가 있는 변이형 | 철자가 비슷하면 같은 용법이다 |
| 구성요소·자리·순서 | 구성 → 요소별 자리 → 들어갈 단위와 순서 | 개별 요소가 허용되면 임의의 순열도 허용된다 |
| 결합 허용·제한 | 특정 용법/구성 → 대상·환경을 지정한 결합 관계 | A–B와 B–C가 있으면 A–B–C도 항상 가능하다 |
| 조건·예외·적용 범위 | 조건/예외 → 영향을 받는 용법 또는 특정 결합 | 한 용법의 예외가 동형 표현 전체에 적용된다 |
| 절·참여자·의미 범위 | 구성 → 내포/인용/연결 자리, 참여자 역할, 기능의 적용 대상 | 선형 위치만으로 부정·양태 범위를 확정한다 |
| 어휘 의미·파생·활용 | 특정 어휘 의미 → 파생/활용 과정 → 실현형 | 한 어휘에서 본 변화를 같은 철자의 모든 어휘에 적용한다 |
| 형태음운·표기 | 형태열과 환경 → 축약/교체 → 표기 후보 | 음성 변화 설명을 모든 텍스트의 의무 표기로 바꾼다 |
| 맥락·높임·시대·지역 | 용법/구성 또는 근거 → 사용 범위 | 관찰된 장면을 유일한 허용 장면으로 만든다 |
| 문헌 간 동일성·차이·충돌 | 근거 있는 병합, 대조되는 용법, 충돌 진술 | 근거가 여러 파일에 있으면 모두 독립적 검증이다 |
| 근거·예문·작성 판단 | 개별 지식/관계 → 출처 위치와 근거 유형, 설명용 예문 | 문헌 전체가 인용되면 그 안의 모든 관계가 증명된다 |

여기서 절·참여자 노드는 일반적인 구성의 자리와 역할을 기술한다. **어떤 입력 문장의 실제 절·참여자와 영구 문법 지식을 혼합하지 않는다.** 입력 분석은 이 공통 역할·기능을 통해 KG에 접근한다.

조건이 있는 관계는 단순한 두 노드의 연결선만으로 표현하면 정보가 유실될 수 있다. 관계에 속성을 달거나, 결합/조건 자체를 노드로 만들어 대상·범위·근거를 연결할 수 있다. RDF triple로 구현하더라도 조건부 관계를 명시적인 자원으로 표현할 수 있다. 저장 기술 선택과 문법적 타당성은 별개의 문제다.

## 4. 전체 검토에서 발견한 9개 교차 연결 묶음

이 절은 현재 발견한 **9개 모두**를 설명한다. 모든 개별 어미·용법의 연결 목록이 완성됐다는 뜻은 아니다. 아래 경로는 구축 대상이며 전부 구현·검증되었다고 읽으면 안 된다.

### 4.1 의문 기능 ↔ 서술부 종류 ↔ 선어말 ↔ 종결형

근거: 문법 8–14쪽, 상대높임법 19–25쪽, 조현준 133–147쪽, 류성기 15–17쪽.

질문이라는 기능에서 바로 특정 글자로 이동하지 않는다. 먼저 질문의 해석과 해당 종결 용법을 연결하고, 그 용법이 계사 서술부인지 용언 서술부인지, 어떤 선어말과 결합하는지 확인하여 실현형을 찾는다. 자료마다 나뉜 질문 분류·결합 설명·높임 정보를 한 용법 또는 관련 구성에서 만날 수 있게 한다.

입력 쪽에는 절별 질문 해석, 서술어 종류, 시제·주체높임 등이 필요하다. 후보를 선택한 뒤에는 후보 서술부의 실제 형태열을 검사한다. 질문어가 있다는 사실만으로 설명 의문을 확정하지 않는다. 문법 8쪽과 11쪽의 `-시-` 설명 충돌은 해결 전 해당 관계의 사용을 보류한다.

조회는 ‘이 질문 기능과 서술부 조건에 대응하는 용법, 그 선어말 결합과 예외’를 함께 돌려줘야 한다. 단순히 의문문 문단 하나를 반환하는 것과 다르다.

### 4.2 기본 의문 용법 ↔ 요 결합 구성 ↔ 결과 높임

근거: 상대높임법 34쪽 각주 67, 조현준 212–215쪽과 55쪽의 대립 설명.

기본 의문 용법과 `요`가 추가된 전체 구성을 구별한다. 기본형의 높임 등급을 전체 구성에 복사하지 않고, 결합 결과의 기능·높임을 별도 근거로 연결한다. 기본형 설명과 결합형 설명이 다른 문헌에 있어도 이 구성을 통해 연결할 수 있다.

설명용 개념 triple은 다음과 같다. 현재 저장된 새 노드 ID나 확정된 운영 규칙이 아니다.

```text
(설명 의문 기본 용법, 실현형, -(느)ㄴ고)
(요 결합 구성, 기본 용법, 설명 의문 기본 용법)
(요 결합 구성, 추가 요소, 요)
(요 결합 구성, 결과 형태, -(느)ㄴ고요)
(요 결합 구성, 결과 높임 해석, 해요체)
(요 결합 구성, 근거, 상대높임법 PDF 34쪽 각주 67)
```

전체 형태가 어떤 순서로 구성되는지도 기록해야 한다. 조현준의 부재 진술과 실제 결합 예는 충돌 검토 대상이다. 이 한 사례에서 모든 하게체 어미에 `요`를 자유롭게 붙일 수 있다고 일반화하지 않는다.

### 4.3 완결 기능 ↔ 보조용언 ↔ 어간 활용 ↔ 후행 어미

근거: 류성기 23–26쪽, 문법 15–19쪽.

완결을 나타내는 보조용언 용법을 중심으로 `버리다` 계열과 `삐다/뿌다` 후보를 연결하고, 해당 후보의 활용 정보를 다른 자료에서 연결한다. 기능을 설명한 문헌과 형태 변화를 설명한 문헌이 여기서 결합한다.

본동사 `버리다`와 보조용언을 먼저 구별해야 한다. 다른 의미의 `베리다`도 같은 묶음으로 자동 편입하지 않는다. 조회는 후보만이 아니라 그 어간이 후행 어미와 결합할 때 필요한 정보를 반환해야 한다. 모든 종결형과의 조합이 원문에 확보된 것은 아니므로 미확보 조합을 허용으로 바꾸지 않는다.

### 4.4 인용 절 관계 ↔ 인용 구성 ↔ 하다/카다 ↔ 축약

근거: 류성기 17–19쪽, 문법 30·48쪽, 음운 8쪽, 개요 10–13쪽.

인용되는 절과 보고하는 서술부를 구별하고, 인용 유형에 맞는 구성과 `하다/카다`, 축약 환경을 연결한다. 통사 정보와 음운 정보를 문서별로 따로 두지 않되, 두 정보 사이에 실제 적용 환경을 둔다.

인용·연결의 `-고`와 의문 종결 `-고`는 별도 용법이다. 모든 `카다`를 인용 축약이라고 단정하지 않는다. 입력의 인용절 구조와 후보 형태열이 확인되어야 축약을 선택할 수 있고, 이 경로 전체와 근거를 조회 결과에 남긴다.

### 4.5 사동 파생 ↔ 어휘별 활용 ↔ 명령·높임 구성

근거: 류성기 22–23쪽, 문법 18–19쪽, 조현준 152–155쪽.

사동 의미를 특정 어휘의 파생형과 연결하고, 그 파생 어간이 명령·높임 어미와 결합하는 과정을 연결한다. 예컨대 `낋이이소`를 하나의 불투명한 문자열로만 저장하지 않고 사동 부분과 뒤의 종결 구성을 구별할 필요가 있다.

사동 관계가 있다는 이유만으로 서로 다른 자료의 파생형을 자유 교환하지 않는다. 원래 사건의 참여자와 사동 사건의 참여자 관계도 필요하지만 현재 자료만으로 모든 동사의 논항 전환을 채울 수 없다. 형태 구성의 근거와 참여자 구조의 공백을 함께 반환해야 한다.

### 4.6 목적 절 연결 ↔ -구로 용법; 방식·사동의 -게와 구별

근거: 문법 28쪽·48쪽 각주 76, 류성기 17–19·23–26쪽.

`-게`라는 글자가 아니라 두 절 사이의 목적 관계를 확인해 `-구로` 계열의 해당 용법으로 이동한다. 방식 표현이나 `-게 하다` 사동 구성은 별도 분석 대상이다. 본문의 넓은 설명과 각주의 제한·반례를 한 조건부 관계에 함께 연결한다.

원문의 `빠르게` 반례가 중요하다. 목적형을 찾았다고 방식 용법까지 치환해서는 안 된다. 조회에는 선택 후보, 적용 범위, 제외되는 용법과 그 근거가 함께 나와야 한다. 추가 업로드된 양지현(2021)의 `-거로`는 GYS-Y001~Y015에 편입했고, 위키와 범위가 다른 부분은 INT010으로 보류 연결했다. 박신명·이혁화(2013)는 초록 확인 후보로 남겼다(8절).

### 4.7 관형절 ↔ 의존명사 ↔ 계사 ↔ 축약·양태 해석

근거: 류성기 19–21쪽, 조현준 104–116·138·197–199쪽.

관형형, `것`, `이다`의 결합과 `끼다/낀데` 등의 실현을 구성으로 연결한다. 같은 글자가 나타나는 약속의 `-끼`, 미래의 `-겠-` 등과 표면 유사성만으로 병합하지 않는다.

입력에서는 관형절과 바깥 서술부의 관계, 해석된 시제·양태가 필요하다. `겠세/것가` 등에 관한 역사적·분석적 설명은 현재의 자유로운 생성 규칙과 분리한다. 조회는 관찰된 구성과 분석 제안을 구분해야 한다.

### 4.8 명사구 기능 ↔ 조사 용법 ↔ 말음·표기

근거: 류성기 10–13쪽, 문법 26–27쪽, 개요 21·26쪽.

명사구의 기능에서 특정 조사 용법을 찾고, 체언 말음과 결합한 실현형을 찾는다. 목적격의 `로`와 도구·방향의 `로`는 철자가 같아도 같은 용법이 아니다. 조사 설명과 형태음운 설명은 결합 환경을 매개로 연결한다.

하지만 조사 표를 확보했다고 일반 동사의 목적어를 정확히 판정할 수 있는 것은 아니다. 동사 의미별 참여자 구조는 별도 공통 문법 근거가 필요하다. 이 공백을 조사 지식이 이미 해결한 것으로 포장하지 않는다.

### 4.9 지시·제안 기능 ↔ 행동 참여자 ↔ 명령·청유 ↔ 높임

근거: 류성기 13–15쪽, 상대높임법 4–6·19–20쪽, 조현준 161–190·217–224쪽.

청자에게 행동을 요구하는지, 화자와 청자가 함께 행동하도록 제안하는지 등의 해석을 어미의 특정 용법과 연결한다. `-세/-지/-제`의 동형·다기능을 구별하고 높임·결합 정보로 이어간다.

문장 형식과 실제 의도가 항상 같지는 않다. 문맥 없이 행동 참여 범위를 확정하지 않고 복수 해석이나 판단 보류를 남긴다. 이 조회가 성공했다는 것은 필요한 용법들을 찾았다는 뜻이지 숨은 의도를 정확히 알아냈다는 뜻이 아니다.

### 4.10 위 9개에 대한 범위 제한

9개는 전체 범주 목록도, 모든 교차 관계의 완성 목록도 아니다. 부정·시제·상·양태의 범위, 대명사·지시·수량, 어휘 의미별 활용, 담화표지·억양 등도 전체 작성 대상에서 점검한다. 확보된 관계는 위 관계 계열로 연결하고 부족한 부분은 공백으로 남긴다. 상위 범주 노드를 공유한 것만으로 이 영역들의 상호작용까지 구축되었다고 하지 않는다.

## 5. 확인된 문제의 처리 — 인식과 수정 완료는 다르다

[전체원문검토.md 9절](전체원문검토.md#9-우선-처리해야-할-문제-장부)의 14가지 주요 문제를 구축 시 처리 대상으로 삼는다. **H001의 과도한 장소 제한을 정정하고 은/는·시도/추측·피동/상태변화·종결형 분류 충돌을 실제 기록으로 분리했다. 문제를 기록한 것과 해결한 것은 다르다.** 최신 문제별 상태는 [integration.json](../grammar/integration.json)의 `issues`와 [검토 보고](../grammar/작성검토.md)를 따른다.

- 충돌: 양쪽 근거와 충돌 범위를 기록하고 해당 용법/결합의 확정 사용을 보류한다. 문서 전체를 일괄 폐기하지 않는다.
- 예문과 기능 분류의 불일치: 원문의 명칭과 작성자의 의심을 구분한다. 근거 없이 기능을 확정하거나 조용히 고치지 않는다.
- 통계·부재·경향: 관찰된 범위로 제한한다. 미출현은 불가능 판정의 충분한 근거가 아니다.
- 출판 시기·지역·표본·출처 종속: 사용 범위와 근거 계보를 남긴다. 현대 전역의 자연스러움이나 독립된 복수 확인으로 과장하지 않는다.
- 번역쌍이 아닌 용례·작성 예문: 의미 보존의 평가 정답으로 쓰지 않는다.
- 배경·역사·인물·의식 조사: 생성 지식과 분리하거나 작성 대상에서 제외한다. 원본 자료를 삭제하지 않는다.
- 글자·표 구조 손실: 해당 작성 부분을 화면과 대조하고 미해결 부분을 보류한다. 전 범위 독해와 모든 셀의 검증을 구별한다.
- 음성 의존 판단: 텍스트 자료로 확인 가능한 한계를 남긴다. 외부 음성까지 검토했다고 하지 않는다.
- 과도한 조건: GYS-H001의 장터 예시 등은 관찰 맥락을 필수조건으로 만든 것인지 재검토한다.

처리 이력에는 문제 위치, 영향받는 기록/관계, 판단, 수정 또는 보류 이유, 남은 확인 사항을 남긴다. ‘발견→검토→수정/보류→재검사’를 구별하고 해결하지 않은 문제를 완료로 표시하지 않는다.

## 6. 전체 구축을 연구 방법으로 기록하는 법

### 6.1 실제 작성 절차

1. 자료와 범위를 고정한다. 여섯 파일의 식별 정보·버전·쪽수·출처 관계를 기록한다. 목적 표집이며 경상도 문법 전반의 대표 표본이라고 주장하지 않는다.
2. 원문 위치별로 생성 관련 지식, 배경, 중복 근거, 충돌, 추출 불명확을 구별한다. 모든 문장을 지식으로 만들지 않고 제외 이유를 남긴다.
3. 기능·용법·구성·결합·조건·범위를 구조화하고, 각 관계를 뒷받침하는 근거 위치를 남긴다. 원문 전체를 기록마다 복제할 필요는 없다.
4. 여섯 자료 사이에서 같은 용법의 근거 통합, 다른 실현형의 연결, 다기능의 분리, 충돌 보존을 수행한다. 병합/분리 이유를 기록한다.
5. 작성 중 형식·근거·관계 검사를 수행하고 전체 작성 후 범주별 누락·중복·단절과 조회 경로를 다시 검토한다.
6. 평가에 쓰는 지식·스키마·조회 구현 버전을 고정한다. 이후 변경과 평가셋 사용 이력을 구별한다.

각 작성 단위가 남겨야 할 추적 사슬은 **원문 위치 → 용법/구성 및 개별 관계 → 병합/분리 판단 → 검토·문제 처리 → 조회 경로 → 저장 버전**이다. 과정의 재현 가능성은 같은 LLM이 항상 같은 출력을 만든다는 뜻이 아니라, 최종 판단의 근거와 변경 이력을 다른 사람이 검사할 수 있다는 뜻이다.

### 6.2 논의의 가치와 증거의 경계

사용자와 작성자의 반복 논의는 연구 질문 명료화, 요구사항 도출, 설계 대안 비교, 오류 사례에 따른 정책 개선이다. 연구 준비로서 가치가 있다. 하지만 대화가 길었다는 사실이나 작성자와 사용자의 동의는 문법 정확성·전문가 합의·독립 검증·KG의 효과를 증명하지 않는다.

논문에서는 사람이 목적·범위·정책·주요 선택을 결정하고 LLM이 원문 분석과 구조화 작성을 보조한 역할을 사실대로 기술한다. 실제 사용 모델·버전·지침·수정 과정은 확인 가능한 만큼 기록한다. 사용자의 전문 자격이나 검토 범위를 임의로 덧붙이지 않는다. 수행하지 않은 체계적 문헌고찰·델파이 조사·독립 이중 주석 등의 명칭을 사용하지 않는다.

현재 단계의 정직한 기술 예시는 다음과 같다.

> 경상도 방언 관련 여섯 자료를 대상으로 문법 범위, 문헌 간 연결 후보 및 상충 설명을 분석하였다. 형태의 동형성과 용법의 동일성을 구별하기 위해 기능·용법·구성·결합 조건을 분리하는 지식 표현 방식을 설계하였다. 현재 전 범위의 1차 분석 후 문법 기록 331건과 통합·대조 관계 50개를 직접 작성하였다. 전수 작성·판정 및 독립적인 품질 평가는 미완료이며, 구현 검사는 언어학적 정확성의 검증과 구별한다.

전체 작성·검토 후에는 실제 수행한 절차·수치·판정 결과로 바꾼다. 미래 계획을 완료형으로 쓰지 않는다. 시행착오는 설계 변경 이력·한계·교훈으로 남길 수 있지만 통제 비교 실험으로 바꾸어 서술하지 않는다.

## 7. 연결 검증과 비교 실험 — 구현 점검과 연구 검증의 구별

실행된 범위: 저장 331건 재현과 57개 구현 검사. 함양의 완결 삐다→다른 문헌 활용표→12개 활용형, 조현준의 도가 요청→돌다 활용표의 경로를 확인하고, 연결 엣지를 제거한 복사본에서 경로가 사라지는지 검사했다. 근거 해석 보류 기록과 범위 충돌 관계는 통합 경로에서 차단한다. 이 검사는 연결의 실제 사용을 점검하지만, 관계의 언어학적 정확성·조건 전체 판정·자연스러운 생성·비교 실험의 결과는 아니다. 아래는 그 이후의 연구 검증 계획이다.

### 7.1 검사 단위를 문법 관계와 조회 경로로 확장한다

| 단계 | 검증 대상과 방법 | 얻을 수 있는 결론 / 한계 |
|---|---|---|
| 구조 검사 | 전체 ID·참조·타입·구성요소 순서·필수 근거 연결 검사 | 데이터 구조의 일관성. 언어학적 정답 인증이 아님 |
| 개별 관계 검토 | 연결의 양 끝, 관계 의미, 조건·범위, 원문 근거를 함께 대조 | 해당 관계의 지지 여부. 노드에 출처 하나가 있다고 모든 엣지가 지지되는 것은 아님 |
| 통합 검토 | 같은 용법 병합/다른 용법 분리/충돌 유지가 적절한지 검토 | 문헌 간 통합의 적절성. 연결선 개수는 대체 지표가 아님 |
| 경로 검토 | 기능→용법→구성→조건·예외·근거를 조회하고 각 이동 근거 확인 | 연결을 이용해 필요한 정보를 실제 반환하는지. 경로 길이 자체는 성과가 아님 |
| 조건 대조 | 목적/방식, 본/보조용언 등 근거가 있는 차이를 바꿔 반환 후보 비교 | 관련 조건에 민감한 조회인지. 미기록 사례를 금지 정답으로 삼지 않음 |
| 관계 제거 | 별도 사본에서 필요한 관계를 제거하고 경로·정보 누락 확인 | 구현이 그 관계를 사용하는지. 문법적으로 옳은 관계인지는 별도 검토 |
| 공백·충돌 검사 | 불명확·충돌을 허용 또는 금지로 둔갑시키지 않는지 검사 | 불확실성 처리. 보류만 많이 하는 시스템의 유용성을 보장하지 않음 |

관계 두 개가 각각 맞아도 연쇄 추론이 맞는 것은 아니다. 예를 들어 ‘어떤 용법은 과거와 결합한다’와 ‘같은 용법의 일부 형태가 특정 높임을 나타낸다’만으로 **모든 과거형과 그 높임형의 결합**을 허용할 수 없다. 경로 검토에서는 관계들이 같은 용법·조건 범위를 공유하는지까지 확인한다.

### 7.2 사람의 전수 검수가 어려울 때

자동 구조 검사는 전수 수행하되, 의미 검토는 층을 나눈다. 새 관계 유형, 충돌, 병합/분리, 복합 구성, 근거가 약한 조건 등 고위험 판단은 집중 검토한다. 이와 별개로 자료·문법 범주·관계 유형별 무작위 표본을 마련해 쉽게 보이는 기록만 골라 검토하는 편향을 줄인다. 표본 수와 추출 기준은 평가 전에 정한다.

포함된 지식만 보면 원문에서 빠뜨린 지식을 발견하기 어렵다. 따라서 그래프에서 뽑는 표본뿐 아니라 **원문 구간에서 출발하는 누락 감사**도 둔다. 원문 구간에서 독립적으로 확인한 지식 목록을 기준으로 상대적 포괄성을 측정할 수 있지만, 전체 경상도 문법의 포괄성으로 확대 해석하지 않는다.

LLM 검토자는 근거 확인과 반례 제안을 보조할 수 있다. 작성자와 분리된 검토 지침·입력·출력을 남기되 모델 간 합의만을 정답으로 삼지 않는다. 해결되지 않는 이견은 이견으로 남긴다. 독립 사람 검토를 확보하지 못한 범위는 그 한계를 명시한다.

### 7.3 비교 실험은 별도 질문으로 설계한다

**구축 방법 비교**를 하려면 같은 원문 구간·작성 예산·근거 접근 조건에서 서로 다른 구축 정책을 적용하고, 방법을 가린 상태에서 관계 정확성·잘못된 병합/분리·누락·수정 비용 등을 비교해야 한다. 과거 688건과 현행 직접 작성본의 단순 비교는 이 실험이 아니다. 어떤 구축 대안을 비교할지는 아직 확정하지 않았다.

**관계 활용 비교**는 같은 지식 단위·근거·예문·조건을 가진 상태에서 관계 기반 조회와 비그래프 제공 방식을 비교하는 질문이다. 입력 분석, 정보량, 생성 모델, 프롬프트·토큰 예산 등을 통제하거나 차이를 보고해야 한다. 관계 제거 검사는 이 비교를 돕지만 그 자체로 완성된 성능 비교가 아니다.

**생성 효과 비교**는 의미 보존·문법 적절성·자연스러움에 대한 별도 평가다. KG 품질, 조회 성공, 생성 성공을 하나의 점수로 뭉개지 않는다. 구축 단계에서 본 예문이나 개발 문장을 미사용 평가 사례처럼 보고하지 않는다.

처음부터 완전한 정답 그래프가 있어야만 검토할 수 있는 것은 아니다. 제한된 평가 범위에 대해 독립적으로 판정한 관계·답변·공백 기준이 필요하다. 그 기준도 확보하지 못하면 전체 정확도를 주장하지 않고 사례 분석과 탐색적 결과로 범위를 제한한다. 합격 임계치나 평가자 합의 절차는 아직 확정하지 않았다.

### 실제 실행과 발견한 추가 문제

첫 실행 `20261007T073643613427Z`는 기존 사례 4개와 새 진단 4개에 자동 분석→확장 조회→생성을 수행했다. 첫 결과의 번역 8개는 모두 저장했으나 의미 검토 3개가 결속 검증에서 실패했다. 같은 문헌을 다른 입력 구성의 근거로 쓰는 것을 중복으로 거부한 코드 문제와, 모델이 인용 문자열을 수정하거나 만들어 낸 문제가 있었다. 원래 응답은 보존했다.

두 번째 실행 `20261007T074045678730Z`는 중복 식별을 `(자료 ID, 입력 구성 ID)`로 수정하고 구성 분석 지시를 보완한 뒤 **생성 전 조회만** 수행했다. 이 실행의 모델 생성 번역은 없다. 인용 관련 R007/P016 등, 양보 G038, 조사 G030처럼 기존 기능 입구 밖의 기록에 접근하는 경로를 확인했다. 정확한 전달·차단 여부는 [TXT](../experiments/reports/source_expansion/retrieval_20261007T074045678730Z.txt)와 로컬 원본 JSON에서 확인한다.

관련성 모델의 실제 오판도 발견했다. `더와도·추와도`를 `오다`의 활용 근거로 설명하거나, `거예요`를 `되다`의 활용이라고 설명하고, 인용 구성을 목적 구성과 연결하는 사례가 있었다. 원문 인용문이 실제 존재한다는 검사만으로는 이런 의미 오류를 잡을 수 없다. 따라서 모델이 생성한 **관련성 이유는 감사 기록에만 보존하고 번역 근거로 재전달하지 않도록 수정**했다. 분석값·선택 자체의 의미 오류가 모두 해결됐다는 뜻은 아니다.

추가로 `source_units`의 자유로운 kind/meaning/검색용 풀이도 번역 프롬프트에는 넣지 않고, 원문 문자열·위치·부모 연결만 전달하도록 했다. 자유 설명은 검색과 감사에만 사용한다. 기존 종결부 분석값을 포함한 모든 의미 오류까지 해결한 것은 아니다.

원문에 없는 인용문은 계속 거부한다. 다만 한 선택의 인용 오류 때문에 함께 선택된 올바른 원문 인용까지 전부 버리는 동작은 고쳐, 각 선택을 개별 검증하고 거부 목록을 기록한다. 저장된 두 번째 실행 응답을 같은 요청 그대로 재검증한 결과는 [원문 결속 재검증](../experiments/reports/source_expansion/binding_recheck.txt)에 있다. 모델 재호출·새 번역 없이 코드 검증만 재실행한 것이며, 의미적 적절성이 향상됐다는 실험은 아니다.

## 2026-10-08 조회 설계와 비교 기준

사용자가 승인한 진행 방향은 [연구미팅](../../연구미팅.md#2026-10-08-사용자-승인-방향--이후-작업의-기준)에 고정했다. 아래는 현재 구현 설명이며 개선 효과의 주장이나 임베딩 도입 완료 보고가 아니다.

### 세 층의 구분

- **저장 표현:** `grammar.graph.json`의 노드·관계·속성. `realizes`는 표현 용법이 기능을 나타낸다는 관계 이름이다.

`realizes`의 존재를 확인하는 것과 인용·축약·활용의 전체 경로를 사용하는 것은 다르다. 기존 조회 코드의 범위는 그래프에 저장된 관계의 범위보다 좁다. 조건 수가 많다는 사실은 관련성 점수의 검증된 대체물이 아니다.

### 확장 검색은 현재 임베딩 검색이 아니다

`source_retrieval.tokens`는 한글/영문/숫자 단어와 연속 두 글자 조각을 만든다. `SourceIndex.search`는 이 조각의 겹침에 희소성(IDF), 빈도, 문서 길이를 반영하는 BM25형 점수를 부여한다. 문장 전체의 정확 일치만 보는 것은 아니지만, 표현이 달라 겹치는 조각이 없으면 의미가 가까워도 후보를 놓친다.

```text
기본: 표준어 → Qwen 분석 JSON → 기능 관계 조회 → 조건/선별 → Qwen 생성
확장: 원문 구성 + Qwen 검색 풀이 → 문자/단어 점수 검색 → Qwen 관련성 검토
      → 기존 기능 후보에 관련 문헌/KG 기록 추가 → Qwen 생성
```

확장 경로는 질의별 KG/원문 상위 후보를 합치고 기본 24개(KG 12/원문 12)를 제시해 Qwen이 최대 6개를 선택한다. 원문 위치·근거 인용을 검증하지만 의미 관련성을 인증하지 않는다. 후보 밖의 지식을 Qwen이 복구할 수 있다는 보장은 없다. 기본 실행의 `--retrieval function`과 실험적 `hybrid`를 구분한다. 여기서 `hybrid`라는 코드 옵션은 **벡터+키워드 검색을 뜻하지 않는다.**

임베딩 검색은 별도 모델로 원문/문법 설명과 질의를 수치 벡터로 바꾸고 유사도를 계산하는 방식이다. Qwen이 관련성을 읽고 판단한다는 사실만으로 임베딩 검색이라고 부를 수 없다. 임베딩 도입 여부는 별도 설계/비교 대상이며 자동으로 전환하지 않는다.

### Neo4j·조회문·AI 역할

Neo4j는 그래프 DB이고 Cypher는 조회 언어다. 벡터 검색 없이도 미리 작성한 Cypher에 기능/형태/ID를 매개변수로 넣어 관계를 조회할 수 있다. 벡터 검색을 사용한다면 가까운 노드의 ID를 얻은 뒤 역시 미리 작성한 관계 조회문에 넣을 수 있다. 모델이 매번 Cypher를 작성하는 Text2Cypher는 또 다른 설계다.

| 방식 | 시작점 | 조회문을 누가 정하는가 |
|---|---|---|
| 관계 패턴 조회 | 분석값 또는 형태/ID | 개발자가 작성한 매개변수형 조회문 |
| 검색 후 관계 확장 | 문자열 또는 벡터 검색 결과 | 개발자가 작성한 확장 조회문으로 가능 |
| Text2Cypher | 자연어 입력 | 모델이 스키마를 보고 조회문 생성; 별도 검증 필요 |

공식 근거: [Cypher](https://neo4j.com/docs/getting-started/cypher/), [VectorCypherRetriever와 Text2CypherRetriever](https://neo4j.com/docs/neo4j-graphrag-python/current/user_guide_rag.html). 연구 아이디어: [KAPING](https://aclanthology.org/2023.matching-1.7/)의 관련 지식 제공, [KG²RAG](https://aclanthology.org/2025.naacl-long.449/)의 검색 후 관계 확장. 두 연구를 우리 조건 정렬/6개 상한의 직접 근거로 소급하여 주장하지 않는다.

### 비교와 종료 기준

주 질문은 같은 지식/분석/시작 후보에서 **관계 확장을 사용했을 때의 추가 효과**다. 기본 생성과 원문 검색을 맥락 비교로 두고, 입력 분석 단계·모델 후보 재검토·생성 후 검토는 별도 요인으로 비교한다. 전달 예산·실제 전달량·프롬프트·모델/seed·호출 수·시간을 기록한다. 같은 모델의 여러 호출은 여러 모델 종류와 구분한다.

KG의 조건·예외·출처 저장 자체는 독창성이나 성능 기여의 증명이 아니다. 공유·조회할 필요가 없다면 속성/근거 참조로 충분할 수 있다. 문법적 적용 조건과 감사용 출처를 생성 프롬프트에 동일하게 모두 넣어야 할 이유도 없다.

능력 요구사항은 고정 문장·과거·존댓말만 허용하는 규칙이 아니다. 구성/의미/시제/높임 등이 바뀌어도 필요한 지식을 찾는지 확인하고, 문헌에서 발견한 미예상 범주로 보완한다. [Ontology Development 101](https://protege.stanford.edu/publications/ontology_development/ontology101-noy-mcguinness.html)의 competency questions를 범위·검증 도구로 참고한다.

개발 종료는 문장 출력이 마음에 들 때까지 수정하는 것으로 정하지 않는다. 평가 전에 대상으로 삼을 범주, 필요한 조회 능력, 실패/보류 처리, 개발 종료 기준을 확정하고 코드/KG/입력/설정을 고정한다. 최종 표본 수·평가자·합격 임계치는 아직 확정 전이다. 검토한 문장은 개발 자료로 유지하고 독립 평가 뒤 수정하면 새 독립 자료로 재평가한다. 논문은 구축/조회/생성 품질을 구분하며 혼합 변경 이력을 요인별 효과로 보고하지 않는다.

### 10월 8일 실제 진행 결과: 문헌 복구와 Neo4j 확인용 적재

문헌 자동 검토의 10월 7일 실행은 728/1,064개 단위를 저장하고 336개 미처리 상태로 종료됐다. 10월 8일 `review_source_inventory.py --recover-only`로 저장 응답을 다시 대조하여 **276개를 신규 전송 없이 복구**했다. 한 단위의 형식 오류 때문에 다른 정상 단위까지 버리지 않도록 분리했다. 원문 예문은 기존의 정확 일치/공백만 유일하게 복원하는 규칙을 유지했다. 후보에 없는 KG ID는 승인하지 않고 `record_link_audit.rejected_ids`로 격리했다. 복구 후 1,004개 제안 중 61개는 후보 연결 재검토가 필요했다. 이 수치는 문법 정확도나 KG 포괄률이 아니다.

남은 60개는 기존 Qwen 서버가 응답함을 확인한 후 1개 단위씩, 동시 2요청으로 재처리를 시작했다. 이전 요청·응답은 그대로 보존했으며 이전 실행 코드/상태도 `experiments/archive/runs/source_review_20261007/`에 보존했다. 최신 진행은 `grammar/source_evidence/review_status.json`을 따른다. 검토 결과를 KG 규칙으로 자동 편입하지 않았다.

Neo4j Community **5.26.31**을 공식 tar 배포본과 공식 SHA-256을 대조하여 `current_kg/.runtime/`에 설치했다. 프로젝트 외 시스템 설정은 변경하지 않았다. 기존 JSON을 수정 원본으로 유지하고, 그래프 파일의 SHA-256을 snapshot 속성으로 사용해 기존 ID를 보존했다. 중첩 속성은 `properties_json`에 정확히 보존하고, Browser에서 보기 쉬운 단순 속성은 별도로 노출한다. 별도 벡터 인덱스나 임베딩 모델은 없다.

- [연동 코드](../grammar/neo4j_view.py): `install`, `start`, `load`, `verify`, `status`, `figure`.
- [검증 결과](../experiments/reports/neo4j/verification.json): **6,092개 노드·15,639개 관계의 ID/유형/양 끝/중첩 속성 일치**, `realizes`가 연결된 61개 기능에서 Cypher와 Python의 첫 후보 엣지 집합 일치. 현재 분석기가 61개 기능 모두로 진입한다는 뜻은 아니다.
- [직접 실행할 조회문](../experiments/reports/neo4j/inspection.cypher): 유형별 수, 기능→표현, 기록→진술/조건/근거, 결합·인용·축약 관계, 기능 진입 없는 용법 확인.
- [현재 구조 그림 SVG](../experiments/reports/neo4j/schema.svg): 12개 노드 유형 전체와 주요 관계 계열만 표시. 전체 41개 관계 종류나 실제 실행 경로 전체를 보여주는 그림은 아니다.

Browser는 **서버의** `http://127.0.0.1:17474/browser/`, Bolt는 `bolt://127.0.0.1:17687`이다. 사용자의 다른 PC에서는 해당 서버로 포트 전달이 필요하다. 계정은 neo4j이며 생성한 비밀번호는 `.runtime/neo4j-auth.json`에 0600 권한으로 로컬 보관했다. 이 파일과 DB/배포본은 Git 제외다. 비밀번호를 문서/로그에 복사하지 않는다. 접속 후 `inspection.cypher`의 `:param`을 설정하고 각 조회를 개별 실행한다.

```bash
# 서버가 멈췄을 때 시작 (포그라운드 실행)
.venv/analysis/bin/python current_kg/grammar/neo4j_view.py start
# 현재 그래프 적재 및 일치성 검사
.venv/analysis/bin/python current_kg/grammar/neo4j_view.py load
```

**기존 생성 파이프라인은 여전히 Python 조회를 사용한다.** Neo4j는 현재 확인용 미러이며 조건 판정·최종 후보 순위까지 Cypher로 바꾼 것이 아니다. 형식/복구 관련 실험 코드 검사 57개를 통과했으나 언어학적 검수나 생성 품질의 증거로 사용하지 않는다. 다음은 후보 연결 보류·원문 화면 검토 대상을 구분하고, 실제 수정이 필요한 문법 정보와 조회 결함을 근거별로 분리하는 단계다. 임베딩 도입과 생성 재실험은 아직 수행하지 않았다.

재처리 완료 갱신: 60개 재요청 모두 결과를 저장하여 **1,064/1,064개 모델 제안**이 있다. [검토표 TSV](../experiments/reports/source_expansion/review_units.tsv)는 `review_source_inventory.py --report-only`로 재현한다. 연결 재검토 61개, PDF 화면 검토 표시 307개, 예문 목록에 URL이 포함된 단위 3개이며 이 수들은 서로 중복할 수 있다. 격리된 후보 ID 67회는 모두 전체 KG에 실제 존재했지만 해당 요청에서 제공한 목록 밖이었다. 따라서 '없는 KG ID를 날조했다' 또는 '원문 지식이 KG에 없다'는 결론으로 사용할 수 없다. 관련성 검수도 아직이다. 일부 모델 응답은 설명문/URL을 예문으로 분류하므로 추출 구간 수를 유효한 방언 문장 수로 보고하지 않는다. Neo4j 확인용 Cypher 6개는 실제 실행했고, 조건 판정은 여전히 Python에 남아 있다.

### 10월 8일 후속: 원문 예문 보완과 통제된 개발 비교

앞 절의 “임베딩 미도입 / 6,092노드”는 설치 직후 상태다. 후속 작업에서는 원문 PDF를 직접 읽고 화면으로도 대조한 **3개 기록에 원문 인용 예문 6개**를 연결했다. RYU2014 PDF 19쪽의 `지가 간다꼬 말했다.`, `밥 무라 카네.`와 동남 방언 PDF 12쪽의 카다·캤다·카데 관련 구간이다. 표의 같은 행에 있는 표준어/방언 문장은 내용이 다른 경우가 있으므로 병렬 번역쌍으로 승격하지 않았다. `카데`, `캤다`를 어느 인용 문장에도 치환 가능한 규칙으로 추가하지 않았다.

- 작성 원본: `authored/ryu2014_01.json`의 R007/R008, `authored/namu_overview_expansion_02.json`의 O004.
- 규격/빌드: `source_examples` → `SourceExample` 노드, 기록의 `has_source_example`, 원문 위치의 `supported_at`. PDF 해시를 확인하고 지정 쪽의 정확한 부분 문자열인지 빌드 때 검증한다.
- 작성자가 만든 `IllustrativeExample` 76개와 별도 유형이며, 원문 인용도 평가 정답/생성 승인으로 취급하지 않는다. 원문을 다시 찾아가는 정보와 검색용 본문에 포함한다.
- 현재 **331기록 / 6,098노드 / 15,651관계**. 신규 문법 진술을 임의로 늘린 것이 아니라 원문 예문 6노드·연결 12개를 추가했다. 문법 진술 1,138개와 통합 관계 140개는 유지된다.
- [변경 근거](../experiments/reports/controlled_development/source_repairs.json). 연결 재검토 61개와 화면 검토 표시 307개의 전체 판정 완료는 아니다.

**새 임베딩 경로는 별도의 개발 비교 모듈이다.** 기존 `source_retrieval.py`의 `hybrid` 옵션과 이름이 비슷해도 구별한다. `embedding_retrieval.py`는 로컬 `intfloat/multilingual-e5-small`, revision `614241f622f53c4eeff9890bdc4f31cfecc418b3`을 사용한다. 모델의 [공식 사용법](https://huggingface.co/intfloat/multilingual-e5-small)에 따라 query/passage 접두어, attention-mask 평균 풀링, L2 정규화와 내적을 사용한다. 이 모델이 방언 문법 검색에 적합하다는 검증은 아직 없다. `.venv/retrieval/`과 `requirements-retrieval.txt`로 환경을 분리했다. 문헌 임베딩은 이 서버의 CPU에서 계산하며 외부 임베딩 API로 전송하지 않는다.

검색 대상은 KG 331기록과 원문 1,064단위이며, 384토큰·64토큰 중첩의 원문 부분 문자열로 총 1,685개 검색 조각을 만든다. 긴 기록은 여러 조각으로 검색하고 기록별 최고 점수를 사용한다. 문자 검색과 벡터 검색이 같은 조각을 사용한다. 혼합은 각 상위 50개 결과의 reciprocal rank fusion(k=60)이며 프로젝트의 개발 설정이다. 검색 질의가 길면 두 방식에 같은 480토큰 한도의 질의를 제공하고 절단 여부를 기록한다. 이 토큰 수는 E5 토크나이저 기준이다.

첫 실험에서 분석 JSON 전체를 질의에 포함하자 서로 다른 입력에도 같은 후보가 반복되는 쏠림을 관찰했다. `host_pos` 등 규격 용어가 검색에 간섭했을 가능성이 있으나 개별 필드의 인과 효과까지 분리한 것은 아니다. 그 조회 기록을 `archive/runs/controlled_retrieval_20261008/`에 보존했고 생성은 하지 않았다. 이어 표준어 원문만 질의로 사용한 `controlled_raw_query_20261008`을 별도 개발 비교로 만들었다. 후자는 첫 진단 이후 선택한 개발 변형이며 사전 등록된 최적 방법이 아니다. 입력 분석값을 검색 결과에서 복사하지 않는다. 원문만 검색해도 인용 등 관련 지식이 상위에서 빠지는 문제는 남아 있다.

`run_controlled_retrieval.py`의 네 조건은 다음과 같다. 모든 조건에 **동일한 저장 분석값과 동일한 사용자 지시**가 제공되며, `prompt_only`도 원문만 넣었던 과거 기준선과 다르다.

| 조건 | 달라지는 참고 자료 |
|---|---|
| `prompt_only` | 외부 참고 자료 없음 |
| `source_hybrid` | 혼합 검색한 원문 조각 최대 3개 |
| `record_hybrid` | 혼합 검색한 KG 기록 최대 3개, 관계 확장 없음 |
| `graph_hybrid` | 바로 위와 같은 시작 기록 + 관계를 따라 찾은 기록 최대 3개 |

관계 확장은 공통 기능/출처 노드를 통한 무제한 확장이 아니다. 시작 기록에 속하는 실제 노드에서 **교차 기록 관계 1개**를 양방향으로 따라간다. `has_applicability_constraint`, `has_inflection_description`, `has_construction_component`, `shares_quotative_construction`, `contracts_to`, `combines_with`, `excludes_combination`, `variant_of`, `same_usage_candidate`, `contrasts_in_function` 순으로 검토한다. 보류(`held_scope_tension`) 관계는 제외한다. 문헌의 조건을 다른 기록에 자동 상속하지 않는다. 이 개발 경로는 조건의 완전한 적용 승인을 하지 않고 조건부 자료를 생성 모델에 전달한다. 기존 기능 기반 조건 판정 경로를 대체하거나 그 판정을 통과했다고 주장하지 않는다.

전달 한도는 조건 공통으로 참고 JSON **24,000 Unicode 문자**다. 기록의 조건을 중간에서 잘라 넣지 않고 기록 전체가 한도를 넘으면 제외 이유를 남긴다. 실제 전달량은 달라질 수 있으므로 Qwen 토큰을 맞춘 비교나 내용량을 통제한 순수 그래프 위상 효과라고 부르지 않는다. 이번 C/D 대비는 **관계 확장을 통한 추가 정보 전달의 시스템 효과**다.

생성 조건: Qwen3.8-27B, seed=20260923, temperature=0.3, top_p=0.8, top_k=20, max_tokens=512, thinking=false, 조건별 1회. 30문장×4조건, 동시 요청 2개, 문장별 조건 순서를 순환한다. 분석 모델 추가 호출은 0회이며 과거의 Qwen+Kiwi 분석을 그대로 사용한다. 따라서 그 분석의 오류도 남을 수 있다. `preservation_note`·검토용 `inspection_focus`·분석의 자유 서술 메모는 모델에 전달하지 않는다. 모든 조건에 같은 의미/높임 보존 지시를 사용한다. 서버 seed의 수용과 고정은 절대 결정성을 보장하지 않는다.

비교 실행의 원본 요청·응답·질의·후보·경로·KG/코드 스냅샷은 실행 폴더에 보존한다. Neo4j는 최신 그래프의 ID/속성 전수 일치와, 이번 추가 경로 15회에 쓰인 서로 다른 관계 11개의 일치를 실제 Cypher로 확인했다. 실제 생성 패킷은 Python이 만든다. Neo4j로 DB를 바꿨기 때문에 성능이 향상됐다고 주장하지 않는다.

**본 실험으로 넘어가는 기준(아직 미달):** 주요 기능/인용/연결/높임 범주에서 필요한 지식을 사전에 표시한 검색 평가 세트를 마련하고 누락 및 부적절 후보를 판정해야 한다. 개발 사례의 의미·높임 훼손 원인을 기록하고, 수정에 쓰지 않은 평가 문장과 방언 판단 가능 평가자를 확정해야 한다. 이 조건이 충족되면 설정을 동결한다. 오늘의 실행은 파이프라인과 비교 가능성을 확인하는 개발 진단이며, 120개 응답 저장이나 코드 검사 통과를 종료 기준 충족으로 바꾸지 않는다. 자연스러움 점수는 빈 검토표로 남기고 모델이 대신 채우지 않는다.

실행 결과: 120/120개 응답을 저장했고 재시도는 없었다. 네 조건의 원본 출력은 [비교 TXT](../experiments/reports/controlled_development/comparison.txt), 시작 후보와 추가 경로는 [조회 TSV](../experiments/reports/controlled_development/retrieval.tsv), 실제 입력 토큰/호출 시간/전달량은 [요약 JSON](../experiments/reports/controlled_development/summary.json)에 있다. C/D는 19문장에서 요청이 완전히 같았고 그중 DEV008 한 건의 출력이 달랐다. 관계 확장이 활성화된 11문장 중 출력이 달라진 것은 DEV027 한 건이며 개선으로 판단할 근거가 없다. 빈 [익명 검토표](../experiments/reports/controlled_development/blind_review.tsv)는 독립 평가 완료표가 아니다.

### 10월 8일 후속 결정 정정: 확인된 결함 수정 후 비교·초안

앞서 “초안 전에 실행·기록 오류만 수정한다”고 제한한 것은 사용자 의도를 과도하게 해석한 것이므로 철회한다. 필요한 KG/조회 수정은 실제로 수행하고, 그 효과를 생성 전 조회로 확인한 뒤 비교 생성과 초안으로 진행한다. Neo4j 작업 보류와 끝없는 품질 개선 반복을 피한다는 결정은 유지한다.

현재 `run_controlled_retrieval.prepare`는 원문 혼합 검색을 사용하며 기존 `retrieve`/`retrieve_broad`/`inspect_conditions`를 실행 경로에서 호출하지 않는다. `expansion`은 입력의 적용 조건을 판정하지 않고 관계 유형 우선순위와 ID로 최대 3개 기록을 고른다. `record_card`는 조건은 전달하지만 `application`은 생략한다. 따라서 120개 출력은 이 별도 검색 경로의 진단이며, 이전 기능/높임/조건 보완을 모두 통합한 시스템의 평가가 아니다. 이 점을 해결하지 않고 결과만 확정하지 않는다.

수정 범위는 근거가 확인된 KG 공백, 분석/구성별 후보 발견과 조건 판정의 통합, 입력과 관련된 관계 확장 및 적용 정보 전달이다. 인용/일반 과거·질문 유형·높임·연결 구성을 대조하여 필요한 근거가 실제 전달되고 부적절 후보가 구별되는지 먼저 확인한다. 문장별 정답 ID의 하드코딩이나 자연스러운 출력이 나올 때까지의 무제한 반복은 하지 않는다. 이후 비교에서 남은 문제는 한계로 기록한다. 구체적 범위와 마감 기준은 [연구미팅](../../연구미팅.md#2026-10-08-후속-사용자-결정--실험-정리와-1차-초안-우선)을 따른다. 이 문단은 실행 경로를 확인한 진단과 계획이며 조회 수정 완료 보고가 아니다.

## 2026-10-08 조회 통합과 생성 전 확인

현행 비교 진입점은 `experiments/run_controlled_retrieval.py prepare`이며 `IntegratedRetriever`를 호출한다. 과거 `run_manual_kg_development.retrieve`와 `source_retrieval.retrieve_broad`는 이전 개발 진단 경로로 보존하며 이번 비교를 실행하는 경로와 혼동하지 않는다. 새로운 안내 문서를 늘리지 않고 이 문서와 README/연구미팅/이관을 갱신했다.

| 단계 | 구현과 실제 판단 |
|---|---|
| 입력 위치 결속 | `source_bindings.bind_item`: Qwen의 절 분석, Kiwi의 원문 형태소·문자 위치를 사용한다. 종결절, 연결어미, 인용 표지, 인용+하다 결합, 정확한 보고 서술형을 별도로 묶는다. 이는 문자열 편집 명령이 아니며 형태소가 한 음절에서 겹치면 원문 범위도 겹칠 수 있다. |

| 전달 | 기록 전체를 무조건 넘기지 않고 선택된 문법 진술, 원문 위치, 적용 위치, 조건 판정, 예외 검사, 원문 근거, 범위·공백을 전달한다. 구성별 최대 6개, 전체 패킷 24,000 Unicode 문자이며 전체 카드 단위로 보류하고 사유를 기록한다. 이 수는 그래프 분기 수/조회 횟수가 아니다. |

이 구현은 한국어 전체의 자동 문법 분석기가 아니다. 명시적으로 지원한 형태 결속과 분석값만 공급하며, 아직 지원하지 않는 어휘·조사·활용 위치나 누락된 의미 조건은 미확인으로 남긴다. 조건 일치는 문법적 완성형의 자동 조립이나 자연스러움 승인이 아니다. 원문 높임을 보존하는 목표 후보 정책도 기존 개발 가설을 유지한다.

최초 신규 8문장에서 7개 대조 목표는 충족했지만, `상자를 옮기다가 잠깐 쉬었어요`에서는 모델이 중단 의미를 설명에만 남겨 -다가 지식을 찾고도 전달하지 못했다. 이 실패 요청/응답/조회는 `archive/runs/integrated_probes_20261008/`에 보존했다. 구성별 구조화 의미 공급을 연결한 뒤, 수정에 쓰지 않은 다른 8문장(`integrated_confirmation_20261008`)으로 다시 확인했다. 처음 8문장은 수정에 사용한 개발 자료이며 독립 검증 자료라고 부르지 않는다. 새 8문장도 작은 개발 확인 표본이며 최종 평가셋이 아니다.

이번 30문장은 과거 저장된 Qwen+Kiwi 분석을 재사용하고 네 조건 모두에 같은 분석을 제공한다. 새 8문장은 별도의 Qwen 분석 요청만 실행한다. 분석 규격 오류 시 원래 응답과 오류를 보존해 모델에 재응답을 요청하며 수동 분석으로 대체하지 않는다. 첫 시도/재시도 수는 실행 manifest에서 확인한다. 생성 호출은 수행하지 않았다.
