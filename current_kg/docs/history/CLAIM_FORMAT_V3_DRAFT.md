# 전면 재추출용 Claim 포맷 초안

작성: 2026-09-09. 상태: 사용자 검토용, 스키마·운영 규칙 미확정.

2026-09-10 업데이트: 사용자가 3절의 포맷 방향을 확인했다. 이후 시험 데이터와 최소 그래프를 작성해 [설계 점검 결과](../../design_probe/README.md)에 기록했다. 아래의 ‘아직 수행하지 않았다’는 문구는 최초 초안 작성 시점의 기록이다. 전량 추출과 운영 규칙 승인은 여전히 미완료다.

목표는 경상 방언의 문법체계를 KG로 표현하고 자연스러운 생성에 활용하는 것이다. 건수는 성과 기준이 아니다. 기존 류성기 318건은 신규 KG 입력에서 제외하고 역사 기록으로 보존한다. 아래 예는 기존 Claim을 변환한 것이 아니라 PDF 원문을 다시 확인해 작성했다. 전량 추출이나 그래프 조회 검사는 아직 수행하지 않았다.

## 1. 하나의 Claim에 무엇을 담는가

하나의 Claim은 출처가 제시한 **검토 가능한 문법 주장과 그 주장을 제대로 해석하는 데 필요한 조건**을 담는다. 한 문장당 한 건, 대응형 하나당 한 건으로 기계적으로 나누지 않는다. 반대로 서로 다른 문헌의 주장이나 별도로 참·거짓을 판단해야 할 주장을 한 덩어리로 합치지 않는다.

예: ‘-구로/-그로의 대체 가능 의미’는 목적·강조 조건과 방식 의미에서의 제한을 함께 담는다. 지역별 우세에 대한 주장은 별도 Claim으로 만들어 같은 용법에 연결한다. 그래야 지역 판단을 수정해도 의미 조건을 함께 폐기하지 않아도 된다.

## 2. 제안 필드

| 묶음 | 필드 초안 | 역할 |
|---|---|---|
| 식별·분류 | id, record_type, categories, source_terms | 문법 주장/관찰 예 구별, 문법 범주와 원문의 분류 명칭 보존 |
| 문법 대상 | target | 형태, 뜻·품사별 용법, 필요한 경우 결합 구성의 식별자 |
| 핵심 내용 | assertion | 기능·결합·허용형·제한·변이 등 실제 주장. 요약문만으로 대체하지 않음 |
| 조건 | conditions | 대상, 속성, 비교 방식, 값, 근거. AND/OR를 구별하며 null은 제한 없음이 아님 |
| 예외·관련 주장 | relations | 예외, 적용 범위 보충, 관찰 근거, 잠정 충돌 등 다른 기록과의 명시적 연결 |
| 예문 | examples | 원문 철자, 원문의 O/X 판정, 해당 예문의 근거. 임의 표준어 대응문을 넣지 않음 |
| 출처 | evidence | Source ID, PDF 쪽, 표·각주·예문 위치, 근거 발췌, 직접 설명/관찰/재인용 여부 |
| 적용 범위 주석 | annotations | 지역, 시대, 사용 맥락. 각각 적용 대상·근거·미확보 사유를 보존 |
| 불확실성·검토 | gaps, review | 확인하지 못한 조건, 추출상 문제, AI 점검과 사용자 검토 상태 구분 |

조건의 간단한 표현: `대상=결합 직전 어간 / 속성=말음 / 비교=모음인가 / 값=참`. 기본형의 마지막 글자 ‘다’를 검사한다는 뜻이 아니다. 다만 실제 어간·이형태 분석을 원문이 제공하지 않으면 그 분석이 완료된 것처럼 채우지 않는다.

범주 후보는 조사·종결어미·연결어미·시제/상·부정·사동·피동·보조용언·대명사·수사/수관형·부사·형태음운·높임·담화 등을 포함한다. 하나의 Claim에 주범주와 관련 범주를 함께 붙인다. 모든 자료의 분류를 이 목록으로 덮어쓰지 않으며 최종 분류표는 별도 확정한다.

### 생성 정책은 별도 기록

`policy_id / applies_to / target_profile / priority / rationale / decided_by / decided_on`으로 Claim 또는 용법에 연결한다. 문헌의 설명과 우리의 선택 기준을 분리하기 위해서다. 후순위는 저신뢰·비문·옛말이라는 뜻이 아니다. 자료에 범지역성 근거가 없으면 우선 후보라고 임의 지정하지 않는다.

지역·시대·맥락에는 값뿐 아니라 `basis`(원문 명시/추출 해석 등), 근거 위치, 적용 대상을 둔다. 미확보는 null과 사유로 표현한다. 문서 수정일과 발화 시기는 다르며, 자료 전체의 조사 기간을 개별 예문의 날짜로 복사하지 않는다.

## 3. 원문 기반 작성 예

아래 D01–D05는 설명용 임시 식별자다. 정식 추출 건수에 합산하지 않는다. 사람이 읽는 필드 표현이며 기계 검증된 JSON 스키마는 아직 아니다. 모든 예의 사용자 검토 상태는 미검토다.

### D01 — 같은 ‘부르다’의 뜻·품사에 따른 결합 대조

```yaml
id: D01
record_type: grammatical_assertion
categories: [종결어미, 품사별 결합]
target:
  construction: 니껴형 서술 용법
  usages:
    - {form: 부르다, sense: 사람을 부르는 행동, pos: 동사}
    - {form: 부르다, sense: 배가 찬 상태, pos: 형용사}
assertion:
  contrasts:
    - {usage: 동사 용법, accepted: 친구가 부르니더}
    - {usage: 형용사 용법, accepted: 배 부르이더, rejected: 배 부르니더}
conditions:
  scope: 위키의 안동 중심 니껴형 설명
  distinction: 같은 철자가 아닌 뜻과 품사를 기준으로 용법을 식별
evidence:
  source_id: NAMU_HONORIFICS_20260908
  locations: [PDF 14쪽 대조 예, PDF 33쪽 각주 41]
  kind: 문헌의 설명과 문헌이 제시한 예문 판정
annotations:
  region: {value: 안동 중심 설명 맥락, exclusivity: null}
  period: {value: null, reason: 해당 예의 실제 발화 시기 미확보}
  context: {value: 문법 설명용 서술 예문, speaker_listener: null}
gaps: [다른 지역의 동일 용법 분포, 현대 화자의 선호, 다른 시제형과의 결합]
```

이 대조는 어휘 전체를 치환하는 규칙이 아니다. 별도의 일반 결합 주장과 연결할 수 있지만 이 예만으로 동사 전체의 활용을 증명하지 않는다. X는 해당 문헌·설명 범위의 판단이다.

### D02 — ‘좋다’의 복수 허용형

- 유형·범주: 문법 주장 / 종결어미, 활용 예외.
- 대상: 해당 문헌의 형용사 ‘좋다’ 니껴형 서술 용법.
- 주장: 원문 예외 표가 `좋니더`, `좋으이더` 두 형태를 모두 허용한다.
- 관계: 별도 추출할 ‘형용사의 자음/모음 환경별 니더/이더 일반 설명’에 `exception_to`로 연결한다. 아직 없는 정식 Claim ID를 만들어 연결된 척하지 않는다.
- 근거: NAMU_HONORIFICS_20260908 PDF 14쪽 ‘불규칙 활용’ 표.
- 지역: 안동 중심 설명 맥락. 안동 전용이라는 의미는 아니다.
- 시대·구체적 화자 관계: 미확보.
- 미확보: 두 형태의 상대 빈도, 현대 자연스러움. 50:50 선택 정책을 도출하지 않는다.

### D03 — ‘-구로/-그로’의 의미 조건과 제한

```yaml
id: D03
record_type: grammatical_assertion
categories: [연결어미, 의미별 결합]
target: 표준어 -게에 대응하는 -구로/-그로 용법
assertion:
  relation: conditional_correspondence
  source_form: -게
  target_forms: [-구로, -그로]
conditions:
  any_of:
    - {target: 해당 -게 구성의 의미, equals: 목적}
    - {target: 해당 -게 구성의 의미, equals: 강조}
examples:
  accepted: [낼 하구로 준비 하이소, '아유, 찝찝하구로...']
  restricted_input: 빠르게 해라
  restriction: 이 예의 -게를 -구로/-그로로 바꿀 수 없다는 원문 판단
evidence:
  source_id: NAMU_GRAMMAR_20260908
  locations: [PDF 28쪽 대응표, PDF 48쪽 각주 76]
  kind: 문헌 명시
annotations:
  region: {value: 경상도 자료의 용법, finer_distribution: 별도 D04 참조}
  period: {value: null, reason: 해당 설명의 실제 조사 시기 미확보}
  context: {semantic_uses: [목적, 강조], speaker_listener: null}
gaps: [-고로에 같은 제한이 적용되는지, 전체 결합 환경, 현대 선호]
```

표에는 -고로도 있지만 각주 76이 명시한 제한 대상은 -구로/-그로다. 같은 표에 있다는 이유로 -고로에 제한을 복사하지 않는다. 강조 용법의 문법 분류는 후속 대조 대상이며 범주 라벨 자체를 원문의 확정 분석으로 취급하지 않는다.

### D04 — 위 표현들의 지역별 우세 설명

- 유형·범주: 사용 분포에 관한 주장 / 연결어미 관련.
- 대상·내용: `-구로/-그로 → 경북 우세`, `-고로 → 경남 우세`라는 문헌 설명.
- 근거: NAMU_GRAMMAR_20260908 PDF 48쪽 각주 77, 28쪽 대응표.
- 관계: D03의 해당 용법에 지역 분포 정보를 보충한다. 의미 제한과 분포를 같은 주장으로 합치지 않는다.
- 지역 주석: 원문 명시. ‘우세’는 ‘그 지역에서만 사용’도 ‘도내 모든 지역에서 사용’도 아니다.
- 시대·표본·정량 비율: 해당 각주에서 미제시. 수치를 만들지 않는다.
- 생성 정책: 범지역적 우선 표현인지는 판단 보류. 이 분포 설명만으로 현대의 보편적 사용을 확정하지 않는다.

### D05 — ‘-니이더’에 붙는 세대·사용 맥락

- 유형·범주: 사용 맥락에 관한 주장 / 종결어미, 발음 변이 관련.
- 대상: 원문이 ‘-니더’를 길게 발음한 것으로 설명한 ‘-니이더’.
- 내용: 원문은 이를 고령층이 사용하는 보수적인 형태로 설명한다.
- 근거: NAMU_HONORIFICS_20260908 PDF 14쪽 ‘니이더’ 설명. 원문 표현은 ‘늙은 사람들이 사용하는 보수적인 형태’.
- 지역: 해당 안동 중심 니껴형 설명 맥락.
- 세대 주석: 고령층이라는 문헌 설명. 정확한 연령 범위는 null.
- 시대 주석: 실제 관찰 시점은 null. 문서가 최근 수정됐다는 이유로 현재 조사 결과로 기록하지 않는다.
- 관계: ‘-니더/-니이더’ 변이 관계에 사용 맥락을 연결한다. ‘-니더’ 자체나 모든 니껴형이 고령층 전용이라는 뜻으로 확대하지 않는다.

### 정책 예 P01 — 일반 경상도 생성에서의 니껴형 우선순위

- 적용 대상: 이번 안동 중심 니껴형 용법 묶음(D01·D02·D05 관련).
- 목표: 세부 지역 미지정의 일반적인 경상도 방언 텍스트.
- 우선순위: 후순위.
- 이유: 범지역적 사용 근거가 확인된 표현을 먼저 사용한다는 사용자 정책. 이번 근거는 특정 지역 중심이다.
- 결정 주체·일자: 사용자와의 합의, 2026-09-09.
- 제한: 틀린 표현이라는 판정이 아니며 안동 지정 프로필의 우선순위를 결정하지 않는다. 문법·의미·높임 조건을 통과한 후보 안에서만 정책을 적용한다.

## 4. KG로 옮길 때의 예상 대응 — 아직 구현 전

| Claim 정보 | 그래프 표현 후보 |
|---|---|
| 뜻·품사별 대상 | 용법 노드. 동사 부르다와 형용사 부르다를 구별 |
| 어미·기능·구성 | 형태/기능/구성 노드와 결합 관계 |
| AND/OR 조건 | 대상이 명시된 조건 구조. 관계에 단순 문자열로만 숨기지 않음 |
| 일반 설명·예외 | 각각의 주장 노드와 exception_to 관계 |
| 출처·위치·관찰 | 주장→근거→Source 연결. 관찰과 일반화를 구별 |
| 지역·시대·맥락 | 해당 주장/용법/예문에 한정된 주석. 다른 출처로 자동 전파하지 않음 |
| 생성 정책 | 별도 정책 기록→적용 용법 연결 |

이 표는 표현 가능성에 대한 제안이지 구현·검증 결과가 아니다. 형식 검사는 필드·참조 무결성을, 원문 검토는 의미 보존을, 그래프 조회는 필요한 조건과 근거를 실제로 꺼낼 수 있는지를 확인한다. 어느 검사도 자연스러운 생성 성능을 대신 증명하지 않는다.

## 5. 전량 재추출 전 확인할 것

1. 사용자가 위 예를 읽고 대상·조건·근거·한계를 이해할 수 있는지 확인한다.
2. 포맷에 대한 피드백을 반영해 기계 판독 스키마와 작은 실제 데이터 묶음을 만든다. 논문 관찰 예와 다른 문법 범주도 포함해 점검한다.
3. 필수 필드·출처 위치·조건 대상·관계 참조를 검사하고 최소 그래프 조회로 정보 손실을 확인한다.
4. 확인된 포맷으로 여섯 PDF 전체를 원문에서 재추출한다. 문서·절별로 처리/제외/보류 및 이유를 기록한다. 배경·조사 방법은 출처 맥락으로 분리한다.

이번 완료 범위는 포맷과 원문 기반 작성 예시다. 기존 318건과 기존 스키마의 내용은 수정하지 않았고, 새 정식 Claim이나 운영 Rule로 승인하지 않았다.
