# 세 문헌의 문법 범위와 KG 노드·관계 설계 초안

작성일: 2026-09-08

최신 상태(2026-09-09): 상대높임법·음운을 포함해 현재 활성 자료는 **6종**이다.
[여섯 자료 통합 검토·KG 구성 가능성](KG_FEASIBILITY_2026-09-09.md)을 먼저 읽는다.
아래 3종·4종 표기는 당시 검토 이력이다.

추가 업데이트: 같은 날 사용자가 제공한 `동남 방언_문법.pdf`를 별도 Source로 등록했다.
**현재 활성 자료는 4종**이다. 아래 1–9절은 기존 세 자료 검토 기록이며,
추가 자료의 범위·설계 보완·주의점은 **10절**에 기록한다.

## 1. 결론과 이번 작업의 범위

목표는 **경상 방언의 문법체계를 KG로 구성하여, 의미와 발화 의도를 보존하는 자연스러운 경상 방언 텍스트를 생성하는 것**이다. Claim 수나 방언형 치환 수를 늘리는 것이 목표가 아니다.

세 문헌을 함께 검토한 결과, 다양한 문법 범주와 일부 중요한 상호작용을 표현하는 KG를 설계할 근거는 있다. 특히 종결어미와 서술어 종류·시제·높임의 결합은 실제 문헌에 설명되어 있다. 단순한 어휘·어미 대응표 이상으로 구성할 수 있다.

다만 다음 세 판단은 구분해야 한다.

| 판단 대상 | 현재 판단 |
|---|---|
| 문헌의 문법 지식을 노드·관계로 표현할 수 있는가? | 가능. 아래에 실제 근거에 기반한 초안을 제시한다. |
| 여러 범주가 결합하는 문장을 지원할 근거가 있는가? | 일부 있다. 종결어미 주변이 강하고, 복문 전체의 의미·제약은 빈틈이 크다. |
| 이 KG가 일반 문장에서 자연스러운 생성을 개선하는가? | 아직 검증하지 않았다. 표현 가능성과 생성 효과는 별개다. |

이번 작업은 세 PDF의 목차·절 구성과 관련 본문·표·예문·각주를 대조한 **문헌 전체 범위 조사와 설계 가능성 검토**다. 총 358 PDF쪽의 모든 문장과 표 셀을 전수 판독·검증했다는 뜻은 아니다. 조현준 논문은 각 문법 분석 절과 결론, 결합 제약이 제시된 구간을 중심으로 확인했다. 복잡한 결합 도식인 그림 2·3은 PDF 화면도 확인했다. 나무위키의 인물·작품 목록 등은 문법 추출 대상과 분리했다.

기존 318건의 재추출·승인, 전체 KG 구현, 생성 실험은 하지 않았다. 아래 항목 식별자 E01 등은 이 보고서의 근거 찾기용이며 새 Claim ID가 아니다. 설계안 역시 확정 스키마나 승인된 운영 Rule이 아니다.

PDF쪽은 뷰어에서 세는 1부터 시작하는 쪽 번호다. 조현준 본문 인쇄쪽은 PDF쪽−12, 류성기 인쇄쪽은 PDF쪽+54다.

|---|---|---|---|
| JO2018, 조현준(2018) | 경북방언 종결어미 연구 ([문헌 등록표](../../grammar/source_registry.json), JO2018; PDF 로컬 보관), 265쪽 | 종결어미 체계, 높임, 결합 제약, 의미 기능, 지역 분포의 깊이 | 논문 발행은 2018년이나 주된 분석 대상은 1980년대 채록 구비문학 자료다. 현재 청년 일상어로 바로 일반화하지 않는다. |

| NAMU20260901 | 동남 방언 PDF ([문헌 등록표](../../grammar/source_registry.json), NAMU20260901; PDF 로컬 보관), 55쪽 | 지역별 변이, 실제 표현·대역, 오용 설명, 형태·음운 접점 | 학술 논문과 증거 방식이 다르다. 문장별 근거·범위를 확인한다. 링크된 별도 문서까지 확보된 것은 아니다. |

함양 논문의 문법 조사와 세대별 사용 확인, 방언 의식 설문은 서로 다른 조사다. PDF 4–5쪽의 사용 확인자는 60대 1명과 10대 2명이며, PDF 28쪽의 40명·45명은 의식 조사 대상이다. 이 둘을 합쳐 문법 사용 비율의 표본 수로 쓰면 틀린다. 이번 설계에는 해당 비율을 생성 확률·가중치로 사용하지 않는다.

나무위키 PDF 2쪽의 ‘문법’, 48쪽의 관련 문서 목록은 링크다. `동남 방언/문법`, `/음운`, `/상대 높임법`의 별도 본문을 이 PDF에서 읽었다고 간주해서는 안 된다. 외부 링크·동영상·논문에서 재인용한 원자료는 이번에 새로 수집하지 않았다.

| E11 | RYU PDF 19–21 / 인쇄 73–75 | 미래를 ‘-ㄹ 끼다’ 또는 ‘내일’과 현재형으로 표현, 관형사형을 시제·서술어 종류별로 제시 | 시간 의미와 표면 형태를 분리. ‘ㄴ’=과거 등 단일 대응 금지. 표의 예문은 엄밀한 평행 번역이 아닐 수 있음 |
| E12 | RYU PDF 21–22·25–26 / 인쇄 75–76·79–80 | 부정·금지와 보조용언의 연결, 원래 방언형과 후속 사용 확인의 차이 | 부정 형태+보조용언을 연결하되 조사 단계·동사/형용사 구별 필요. 본문 간 불일치도 보존 |
| E13 | RYU PDF 22–23 / 인쇄 76–77 | 사동 ‘우/구/추’와 명령형 결합의 축약 ‘깨아라/돋가라/낮차라’ | 사동·명령·형태 실현의 공동 구성. 세 예에서 모든 어휘의 활용 규칙을 자동 확장하지 않음 |

| E15 | NAMU PDF 4·27–28·53 각주 92 | 의문 어미·회상/시제형의 결합, 수사의문문에서 의문사 생략 설명 | 글자 수준의 의문사 유무만으로 용법을 결정하지 않음. 지역 범위와 해석된 질문 유형을 함께 기록 |
| E16 | NAMU PDF 21·26 | 포항의 명사 끝소리×조사 ‘에’ 실현 설명, 진주의 목적격 ‘로’와 ‘(으)로’ 중의성, 연결형 뒤 ‘로/나’ | 음운 환경·명사구 역할·지역을 함께 연결. 진주의 관찰을 경남 전역의 무조건적 규칙으로 만들지 않음 |
| E17 | NAMU PDF 15–16·51 각주 58 | 오역 대조와 맥락에 따른 ‘머라꼬예’ 등의 의미 차이 | 예문·대역·문맥·평가 이유를 따로 연결. 짧은 표현에 원문에 없는 의도·정보를 추가하지 않음 |
| E18 | JO PDF 174·180·226; NAMU PDF 28 | 높임 등급의 혼용·지역/상황별 설명 | ‘일관된 프로필’≠‘항상 같은 어미 등급만 사용’. 허용된 문체 변화와 무근거 지역 혼합을 구별 |

### 자료 간 차이는 무엇을 뜻하는가?

1. **분류 체계 차이:** 류성기는 감탄형을 별도 항목으로 다루고, 조현준은 감탄을 서술법에 포함한다. 나무위키 높임표에는 약속법도 있다. 우선 문헌별 분류를 보존하고 공통 기능 태그를 별도로 연결한다. 서로 다른 체계의 등급 이름을 바로 동치로 합치지 않는다.
2. **범위가 다른 관찰:** 함양의 원래 방언형에 대한 부정형 설명을 경북의 다른 시대 자료와 직접 충돌로 판정하면 안 된다. 지역·시기·조사 단계부터 비교한다.
3. **강한 일반화와 반례 후보:** 나무위키 PDF 27–28·53쪽의 계사·의문 어미에 대한 단정과 JO의 E02를 나란히 보존한다. E02 하나가 모든 현대 지역에서 해당 표현을 허용한다는 증거도 아니고, 위키의 단정이 옛 관찰 예를 삭제할 이유도 아니다.
4. **원문 내부의 문제:** RYU PDF 24쪽 ‘시행 (-어) 보다’ 행의 예문은 ‘안 오는 가 배’이며, PDF 26쪽에는 추측의 ‘(-ㄴ가) 보다’가 별도 제시된다. 원문 분류와 추출자의 문제 제기를 분리해야 한다. 문헌을 충실히 옮겼다는 것과 문법 분석이 타당하다는 것은 다르다.

## 5. 잠정 노드·관계안

### 5.1. 기본 생각: 형태가 아니라 ‘그 형태를 사용하는 문법적 용법’을 중심에 둔다

`-고`라는 글자만 노드 하나로 만들면 의문 어미·명령 어미·인용 표지·연결 어미가 섞인다. 반대로 예문마다 아무 관계 없는 노드를 만들면 같은 문법 지식을 재사용할 수 없다.

따라서 다음처럼 **표면 형태는 공유하되, 용법은 분리하고, 용법에 관한 판단을 Claim으로 기록**하는 구조를 제안한다. 이는 이번 프로젝트의 설계 초안이지, KG에 반드시 존재하는 표준 노드 명칭은 아니다.

```text
출처 문서
  └─ 원문 근거 구간 ── 근거가 됨 ──> Claim
                                      ├─ 무엇에 대한 주장인가? → 문법 용법
                                      ├─ 어떤 관계·값을 주장하는가?
                                      ├─ 어떤 조건에서인가? → 조건식
                                      └─ 어느 지역·시기·조사 단계인가? → 적용 범위

문법 용법 ── 표면 형태 ──> '-고'
           ├─ 문법 범주·기능
           ├─ 결합 자리와 순서
           └─ 예문·문맥
```

마지막 세 관계도 실제 저장할 때는 근거 Claim에 연결한다. 근거 없는 확정 사실로 그래프에 따로 중복 저장하지 않는다. 검색용으로 펼친 관계가 필요하다면 원래 Claim ID와 조건·범위를 잃지 않게 한다.

### 5.2. 노드의 역할

| 노드 유형(잠정명) | 쉽게 말하면 | 담을 정보 |
|---|---|---|
| Source | 어떤 자료인가 | 문헌 식별자·파일·버전·발행 시기. 실제 채록 시기는 별도 |
| EvidenceSpan | 자료의 정확히 어느 부분인가 | PDF쪽·인쇄쪽·절·표/행·각주·원문. 문헌이 인용한 원자료 위치도 구별 |
| Claim | 원문이 무엇을 주장하는가 | 주장 대상·관계·값, 조건·범위·근거, 명시적 설명/관찰/추정/재인용 구분 |
| GrammarUse | 어떤 문법적 용법인가 | 예: 명령의 ‘-고’, 의문의 ‘-고’, 추측의 ‘-ㄴ가 보다’. 형태와 사용 의미를 연결하는 중심 |
| Form | 어떻게 나타나는가 | 원표기·정규화 표기·변이형. 같은 철자가 같은 형태소라는 뜻은 아님 |
| Construction / Slot | 무엇이 어떤 자리에 결합하는가 | 구성 전체, 어간·보조용언·어미 등의 자리, 순서·선택 가능성. 복합적인 GrammarUse에서만 필요 |
| ConditionExpression | 여러 조건이 어떤 논리로 묶이는가 | 모두 충족/하나 이상/부정, 검사 대상 자리·절·발화. 원문 미기재는 제한 없음으로 처리하지 않음 |
| Category / Function | 무엇을 분류·표현하는가 | 조사·종결어미·부정 등의 범주와 질문·금지·추측 등의 기능을 구분 |
| Scope / AnalysisSystem | 어디까지, 누구의 분석인가 | 지역·시기·세대·장르·조사 단계, 문헌의 분류 체계 |
| Example | 실제 문장에서는 어떤 모습인가 | 원문 예문·대역·대화 맥락, 분석 대상 구간. 관찰된 예/저자 작성 예/오용 예 구분 |

모든 값을 노드로 만들 필요는 없다. 쪽 번호, 기록 일자, 표기 문자열, 검토 상태는 속성으로 두면 된다. 다른 지식과 반복해서 연결하거나 별도로 근거를 검토해야 하는 대상만 노드화한다. RDF/속성 그래프 중 무엇을 사용할지는 아직 확정하지 않는다.

### 5.3. 관계와 연결 대상

| 관계(잠정명) | 출발 → 도착 | 역할 |
|---|---|---|
| `partOfSource` | EvidenceSpan → Source | 근거를 원문까지 추적 |
| `supportedBy` | Claim → EvidenceSpan | 문법 주장과 근거 연결 |
| `aboutUse` | Claim → GrammarUse | 여러 주장을 동일 용법 아래 모음 |
| `hasSurfaceForm` | GrammarUse → Form | 동일 표기·다른 용법을 구별 |
| `classifiedAs` / `hasFunction` | GrammarUse → Category / Function | 문법 범주와 의미·화행을 분리 |
| `hasSlot` / `precedes` | Construction → Slot / Slot → Slot | 결합 자리와 순서 |
| `hasCondition` / `inScope` | Claim → ConditionExpression / Scope | 조건과 관찰 범위 |
| `analyzedWithin` | Claim → AnalysisSystem | 문헌별 분석 체계 보존 |
| `illustratedBy` | GrammarUse → Example | 용법을 실제 예문과 연결 |
| `realizesAs` | Construction → Form | 결합 구성의 축약·표면 실현. 적용 조건·근거 필요 |
| `correspondsTo` | GrammarUse → GrammarUse | 표준어와 방언 등의 대응. 동의·부분 대응·예문 대역을 구별 |
| `potentiallyConflictsWith` | Claim → Claim | 범위 대조가 필요한 충돌 후보. 자동 기각 아님 |

위 표의 문법적 관계(`hasFunction`, `precedes`, `realizesAs` 등)는 아래와 같이 Claim을 통해 주장한다. 관계 이름만 만들었다고 그 관계가 검증되거나 실행되는 것은 아니다.

```text
Claim = {
  대상: 문법 용법 또는 구성,
  주장: 관계와 그 값,
  조건: 조건식 또는 원문 미기재,
  범위: 지역·시기·조사 단계 등,
  근거: 원문 구간,
  근거 성격: 명시 설명 / 관찰 예 / 저자 추정 / 재인용,
  검토 상태: 별도 기록
}
```

### 5.4. 실제 근거를 옮기는 예

#### 예 A. 같은 형태가 결합 환경에 따라 다른 기능을 갖는 경우

E05의 ‘-구려’ 설명을 다음처럼 보존할 수 있다. 아래는 생성기의 실행 규칙이 아니라 원문 분석을 옮기는 예다.

```text
공유 형태: -구려

용법 A: -구려의 서술·감탄 용법
  조건 묶음: 앞에 선어말어미 -었- 또는 -겠-가 결합
  기능: 서술(감탄)
  분석 체계: JO2018의 문장 종결법 분류
  근거: PDF 106 / 인쇄 94

용법 B: -구려의 명령 용법
  조건 묶음: 동사 어간과 직접 결합
  기능: 명령, 완곡한 권유
  분석 체계·근거: 위와 같음
```

`-구려 → 감탄` 하나만 저장하면 용법 B를 잃는다. `-구려 → 명령`도 함께 붙여 놓기만 하면 언제 어느 기능인지 알 수 없다. **기능에 조건이 붙어 있어야 한다.** 문헌이 적지 않은 현대 사용 연령·권장 빈도는 채우지 않는다.

#### 예 B. 여러 조건이 동시에 필요한 경우

E01의 재인용된 설명을 구조화한다면, 한 가지 분기는 다음과 같다.

```text
주장 대상: 해당 분석에서의 -가 의문 용법
조건: ALL(
  대상 절의 서술어 = 체언 서술어,
  해당 설명에서 시제/상 선어말어미가 통합되지 않은 환경,
  원문 분석의 의문사 유무 = 없음
)
기능 분류: 판정 의문
범위: JO2018 해당 절의 설명 범위
근거 성격: 다른 연구의 분석을 재인용
주의: E02와 적용 범위를 비교해야 하므로 무조건적 생성 Rule로 승인하지 않음
```

‘체언’, ‘의문사 없음’, ‘선어말어미’와 각각 연결하는 것만으로는 AND 조건을 표현하지 못한다. 또한 ‘선어말어미가 없다’와 ‘기록에 선어말어미 정보가 없다’는 다르다. 정보 누락으로 조건을 충족했다고 판정해서는 안 된다. 이 분석의 의문사 조건을 E15의 의문사 생략 설명과 대조하지 않은 채 문자열 검사로 실행해서도 안 된다.

#### 예 C. 사동과 명령이 결합하여 표면형이 달라지는 경우

E13은 다음과 같은 구성으로 연결할 수 있다.

```text
구성: 사동형 + 명령 어미의 축약
문법 범주: 사동, 종결어미, 형태음운
자리 순서: 어간 → 사동 접미사 → 명령 어미
원문 설명: 우/구/추와 -아라의 결합 축약
예시 실현형: 깨아라 / 돋가라 / 낮차라
범위: 함양 논문의 조사 범위
근거: RYU PDF 22–23 / 인쇄 76–77
미확보: 다른 모든 어휘의 활용, 예외 전체, 다른 종결어미와의 실현형
```

이때 ‘깨아라’는 사동과 명령이 연결된 결과다. 두 범주의 존재를 서로 무관하게 저장하는 것과 다르다. 원문 표의 표준어 예문과 방언 예문은 어휘·논항까지 달라지는 행도 있으므로 그대로 정답 번역쌍으로 쓰지 않는다.

### 5.5. Claim 단위는 어떻게 잡을 것인가?

하나의 용법 아래 형태·기능·결합·예문에 관한 Claim을 모은다. 조건이나 예외를 떼어 내서 주장의 뜻이 달라지게 쪼개지 않는다. 반대로 독립적으로 참·거짓을 검토해야 하는 서로 다른 용법을 한 Claim에 몰아넣지도 않는다.

사람에게 보여주는 검토 문서는 **용법 한 묶음** 단위로 구성하면 된다. 예를 들어 ‘-구려’ 묶음에서 두 용법, 각 조건, 원문, 미확보 사항을 한 번에 읽게 한다. 내부 Claim 수와 사람이 검토할 카드 수가 반드시 같을 필요는 없다.

기존 318건을 폐기하거나 곧바로 전면 개편할 필요는 없다. 먼저 대표 근거 묶음으로 위 구조가 정보를 잃지 않고 작동하는지 확인한 뒤, 필요한 필드와 연결만 결정하는 편이 낫다. 사용자 선호에 따른 표현 정책은 원문 Claim과 별도로 유지한다.

## 6. 세 자료만으로 아직 확보했다고 말할 수 없는 것

1. **문장 전체의 통사 체계:** 모든 서술어의 논항, 격 선택, 관계절·명사절·인용절 중첩, 주어 생략·복원에 대한 체계적 지식은 확인되지 않았다.
2. **의미 범위와 조합 제약:** 부정+추측, 사동+부정, 보조용언 연쇄, 연결절+종결절의 시제 관계 등 모든 조합의 의미와 허용성을 확보한 것은 아니다. 각 항목을 아는 것만으로 조합의 적절성을 보장할 수 없다.
3. **현재의 자연스러움:** 옛 경북 구술 자료, 함양의 특정 조사, 위키의 혼합된 서술을 모았다고 현대 경남/경북의 대표성이 생기지 않는다. 발행·업데이트 일자는 실제 발화 시기와 다르다.
4. **텍스트만으로 드러나지 않는 차이:** 억양으로 갈리는 문장 유형과 태도는 철자만으로 완전히 표현되지 않는다. 이번 목표는 텍스트이며, 음성 자연스러움까지 검증했다고 보고하지 않는다.
5. **지식의 독립성:** 두 문헌이 같은 선행연구를 재인용하면 독립된 두 증거로 신뢰도를 올릴 수 없다. 위키에 실린 장문 예시를 KG에 활용한 후 독립 평가 정답으로 재사용해서도 안 된다.

한국어 공통 문법까지 전부 새로 규칙화해야만 방언 KG를 시작할 수 있는 것은 아니다. 다만 공통 문법은 LLM이나 별도 분석기가 처리하게 한다면, 그 역할을 명시해야 한다. 그 성공을 ‘KG 자체가 전체 문법을 해결했다’고 설명하면 안 된다. 공통 문법 자료를 추가하는 것은 현재 세 문헌의 범위를 넓히는 결정이므로 별도 논의한다.

## 7. 지역 프로필에 대한 수정 의견

사용자 요청을 ‘경상도 방언’으로 단순하게 유지하고 내부에 프로필을 기록하는 방향은 유지할 수 있다. 다만 **경남/경북은 검색·보고용 상위 분류이지, 그 안의 모든 표현을 자유롭게 섞어도 된다는 허가가 아니다.**

함양 자료를 경남으로 분류하더라도 원래 지역인 함양·조사 마을을 남겨야 한다. 진주·포항의 특성도 각각 보존한다. 행정구역 계층과 문헌의 방언 구획은 다른 관계로 둔다. 울산처럼 행정적 분류와 언어적 유사성이 다를 수 있는 사례를 단순한 행정 포함 관계만으로 처리하지 않는다.

세부 지역 미상은 ‘경상 전역에서 공통으로 사용’과 다르다. 경남과 경북 각각에서 관찰되었다는 이유만으로 전 지역의 공통 규칙으로 올리지도 않는다. 나중에 내부 프로필을 고를 때에는 근거가 맞물리는 지역·시기·문체 묶음을 선택하고, 지역 미상 자료를 무조건 보충 재료로 섞지 않는다.

반면 **일관성을 이유로 높임 등급의 혼용을 전부 금지하는 것도 잘못**이다. E18처럼 문헌 자체가 혼용을 관찰한다. 근거 있는 문체 변화와 근거 없는 혼합을 구분해야 한다.

## 8. 다음 단계 제안: 범위를 정한 뒤, 생성보다 먼저 설계를 점검한다

이번에 확인한 정보로 잠정 설계를 논의하는 것은 타당하다. 다음은 모든 문헌에서 임의로 몇 개씩 뽑는 파일럿보다 **서로 다른 설계 문제를 대표하는 용법 묶음**을 선정하는 것이 낫다.

| 점검 묶음 | 확인할 질문 |
|---|---|
| 의문형 선택·계사 예외(E01–02·15) | 복수 조건과 예외 후보를 동시에 보존하는가? |
| 종결어미·시제·높임(E03–09) | 결합 순서와 동형이의 용법을 구별하는가? |
| 조사·명사구·지역(E10·16) | 동일 표면형의 다른 기능과 지역 제한을 유지하는가? |
| 부정·보조용언(E12) | 조사 단계 차이·원문 불일치·의미 범위의 공백을 드러내는가? |
| 사동·명령 축약(E13) | 여러 범주가 함께 만든 표면형을 설명하는가? |
| 인용·담화(E14·17–18) | 절/발화 단위의 맥락과 원문의 대응 강도를 남기는가? |

이 단계의 성공 기준은 생성 문장이 그럴듯한지가 아니다. 다음 질문에 구조화된 조회로 답하면서 원문으로 돌아갈 수 있어야 한다.

- 이 형태의 용법들이 어떻게 다른가?
- 어떤 조건들이 동시에 충족되어야 하는가? 조건은 어느 절·요소에 걸리는가?
- 자료에 없는 조건은 무엇인가?
- 이 제약은 저자의 명시적 설명인가, 관찰 예뿐인가, 추정인가?
- 문헌 간 차이가 지역·시기·분류 차이인가, 실제 충돌 후보인가?
- 이 결합을 선택한 근거와 아직 미검증인 부분은 무엇인가?

그다음 범주가 복합적으로 결합한 문장을 대상으로 생성 실험을 설계할 수 있다. 단문은 특정 제약의 오류를 찾는 진단용으로, 일반 문장은 여러 범주의 결합과 의미 보존을 보는 통합 점검용으로 구분한다. 실패 시 자료 부족·스키마 표현력 부족·검색 누락·생성기 오적용을 나눠 분석해야 한다.

나중에 KG 효과를 주장하려면 같은 근거를 일반 텍스트로 제공한 조건 등과의 비교도 필요하다. KG가 정보를 담을 수 있다는 사실만으로 그래프 방식이 더 유효하다고 결론 내리지 않는다. 문헌 준수 점검은 사람의 자연스러움 평가를 대체하지 않으며, LLM 평가 하나만을 정답으로 두지도 않는다.

여기서 N01 등은 보고서 내부 참조 번호이며 신규 Claim ID가 아니다.

**N01 — 의문사처럼 보이는 단어가 있어도 질문 해석이 다르다.**
9쪽은 ‘머 무웄나?’와 ‘머 무웄노?’를 각각 먹었는지 여부와 무엇을 먹었는지에 대한 질문으로 설명한다. 따라서 ‘머/어데라는 문자열 있음→노’ 식의 규칙으로는 부족하다. 기존 초안의 ConditionExpression은 표면 문자열과 문맥에서 해석된 질문 유형을 구분해야 한다. 입력 표준어만으로 두 해석을 구별할 수 없다면 정보 부족을 드러내야 한다.

**N02 — 결합 조건 사이에 우선 관계가 있다.**
11쪽은 계사/아니다에 시제·회상 요소가 결합하는 경우와 ‘-시-’만 결합하는 경우를 구분하고, 둘이 함께 있으면 전자의 처리를 우선한다고 설명한다. ‘그분 아이시가?’와 ‘그분 아이시더나?’를 예로 든다. 원문에 명시된 이런 우선 관계는 조건식과 관련 Claim 사이에 기록할 수 있다. 모든 규칙에 공통의 임의 우선순위를 부여하는 근거는 아니다. 아래 8쪽 표와의 불일치가 있어 즉시 운영하지 않는다.

**N03 — 어휘 의미에 따라 문법적 역할과 실현형이 달라진다.**
17쪽은 표준어 ‘버리다’를 처분의 ‘버리다’, 오염의 ‘베리다’, 보조동사의 ‘삐다/뿌다’로 구분한다. 기존 GrammarUse를 본용언 의미와 보조용언 용법에도 연결하면 이 차이를 표현할 수 있다. 별도 `LexicalSense` 노드가 필요한지는 실제 구조화 시 판단하되, 최소한 **표제어·뜻·문법 역할은 분리**해야 한다. 이 사례는 어휘 자료 전체를 제외할 이유가 없음을 보여주지만, 기존 네이버 어휘 JSON의 항목별 정확성을 검증해 주지는 않는다.

**N04 — 대응표보다 각주에 더 중요한 조건이 있다.**
28쪽 표에는 표준어 ‘-게/-도록’과 방언 ‘-구로/그로/고로/게’가 대응한다. 하지만 48쪽 각주 76은 ‘-구로/그로’가 목적·강조 의미에서 가능하며 ‘빠르게 해라’ 같은 용법에는 쓸 수 없다고 설명한다. 그러므로 이 표를 무조건 치환표로 가져오면 핵심 조건을 잃는다. 하나의 용법 묶음에 표 행과 각주를 함께 연결해야 한다. 여기서 각주의 제한을 명시되지 않은 ‘고로’까지 자동 확장하지 않는다.

**N05 — ‘3’을 나타내는 형태는 문장 안의 역할과 세는 상황에 따라 다르다.**
42–43쪽은 수사·수관형사·차례로 세는 수사를 구분하고 ‘서이/시/시나’ 등의 형태와 ‘석 냥’ 같은 결합을 제시한다. 이는 숫자→방언 문자열 대응으로 충분하지 않다. 수량 값, 수식 대상/단위, 문장 내 역할, 계수 상황에 연결해야 한다. 모든 단위 명사의 허용 목록이 확보된 것은 아니다.

**N06 — 같은 철자라도 원형·의미·발음이 다를 수 있다.**
46쪽 각주 15는 ‘마르다’의 ‘말라’와 사동 ‘말루다’의 ‘말라’가 강세 위치에서 다르다고 설명한다. `Form`의 철자가 같다는 이유로 `GrammarUse`를 합치지 않아야 한다. 원표기·형태 분석·발음 주석·생성 출력 표기를 분리해야 하며, 문서의 자체 표기법을 사용자가 읽기 자연스러운 최종 표기로 자동 채택하지 않는다.

8쪽과 11쪽의 불일치는 새 자료를 버릴 이유가 아니라 **Source→Claim 단계에서 충돌을 보존해야 하는 실제 사례**다. 출처를 충실히 추출한 Claim과 생성에 사용할 수 있는 Rule은 계속 구분한다.

### 10.5. 다음 단계의 보완

기존 용법 중심 노드·관계안은 유지할 수 있다. 다만 설계 점검 묶음에 아래 네 항목을 더 포함한다.

1. 어간 특징×어미 계열×지역에 따른 활용 묶음: 기본형·활용형·발음 구분.
2. 버리다의 의미와 본용언/보조용언 역할: 단어 의미와 문법 지식의 접점.
3. ‘-게→-구로/그로’의 조건부 대응: 표·각주를 함께 읽었을 때만 확보되는 제한.
4. 수사·수관형사·계수 표현: 문장 내 자리와 사용 상황을 표현할 수 있는지 확인.

이 보완으로 설계 가능성에 대한 근거는 강해졌다. 하지만 모든 자료를 새 Claim으로 대량 변환하기 전에, 네 문헌에서 선정한 이런 묶음으로 조건·예외·출처·분석 차이가 실제 구조에 남는지 확인한다. 추가 PDF의 Claim 전수 추출이나 생성 실험은 아직 수행하지 않았다.
