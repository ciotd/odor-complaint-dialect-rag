1. 결론

현재 결과는 'KG가 본질적으로 번역을 나쁘게 만든다'는 증거가 아니다.
같은 Qwen에서도 KG가 높임·어휘를 보완한 사례와 불필요한 치환·어색한 생성으로 이어진 사례가 함께 있다.
확인된 문제는 (a) Qwen의 문장만 입력한 생성에서도 나타나는 보존 실패,
(b) 분석 결과를 조회에 연결하지 못하는 구현,
(c) 문헌에 존재하는 표현을 현 문맥에 적합한 표현으로 과도하게 취급하는 선택 정책,
(d) 많은 인용문·검사 로그·대안이 포함된 생성 입력이다.
추출 진술 수를 늘리는 것만으로 이 네 문제가 해결되지는 않는다.

2. 비교 범위와 공정성

38개 같은 입력을 다음 7개 열로 정렬했다.
  - Astra high: 이전 별도 작업자의 원출력. 외부 근거와 대화 이력 없이 38개를 한 번에 요청.
  - Sonnet: 사용자가 제공한 38개 출력. 정확한 모델 버전, 프롬프트, 도구 사용, 추론 설정은 미확인.
  - Qwen 문장만: 이번에 새로 실행. 기존 Qwen 시스템 프롬프트·모델·디코딩 설정을 유지하고 사용자 메시지만 원문으로 바꿈.
  - Qwen 분석 포함 no_kg: 기존 분석 JSON·Kiwi 형태소 JSON은 전달하고 KG 참조만 비운 조건.
  - Qwen legacy_graph / v2_direct / v2_graph: 최신 ending_repair 실험의 기존 출력.

모델, 프롬프트, 추론량, 요청당 입력 수가 다르므로 Astra/Sonnet과 Qwen의 차이를 KG 효과로 계산하지 않는다.
특히 no_kg라는 이름이 '원문만 전달'을 뜻하지 않았다는 점이 중요한 비교상의 공백이었다.
이번 Qwen 문장만 기준선으로 공백을 일부 보완했지만, 완전한 모델×KG 요인 실험은 아직 아니다.
38개는 이미 관찰한 개발 입력이다. 독립 시험 세트나 인간 정답이 아니다.

따라서 문헌의 거짓 사실로 삭제할 문제가 아니라, 어느 지역·세대·문맥에서 생성에 사용할지 정해야 할 문제다.
생성하지 않아도 되는 선택적 어휘 치환을 높임·의문·시제보다 먼저 전달하는 정책도 재검토해야 한다.

4. 코드에서 확인한 분석·조회 문제

DEV006: Kiwi는 계세요를 계/NNG + 이/VCP + 세요/EF로 분석한다.
조회기는 이를 근거로 host=이다를 선택한다. Qwen 의미 분석의 복합 서술어 정보와 대조해 충돌을 처리하지 못한다.

DEV011: Qwen 분석의 host_form은 출발하다지만 Kiwi의 하/XSV가 PRED 목록에서 제외된다.
결과적으로 KG 참조가 0개다. 이 입력에서 v2_graph와 분석 포함 no_kg의 요청은 완전히 같다.
이 오류는 '나쁜 KG가 전달됐다'가 아니라 '조회로 연결되지 않았다'에 해당한다.

DEV013: request로 분류된 의문문은 포괄적 기능 조회를 막는 보호 로직 때문에 어미 후보가 전달되지 않는다.
되다의 어휘 변이와 낼은 전달되지만 될까요의 높임·의문 구성은 남겨진다.

DEV019: 으세요라는 융합 종결형의 구체 대응 대신 명령형 어미 목록만 전달된다.
조회에 높임 후보가 존재한다는 것과 실제 걷다+높임+명령을 조합할 수 있다는 것은 다르다.

이들은 개별 입력을 하드코딩하지 않고 파생 서술어, 복합 서술어, 융합 어미, 간접 요청을 다루는 공통 분석 계약으로 고쳐야 한다.

6. 수정·보완 우선순위

1순위: 평가 기준과 조건을 정리한다.
  의미·시제/부정·주체 높임·청자 높임·발화 의도·문법·지역 자연스러움을 따로 평가한다.
  Qwen 문장만 / 분석만 / 기존 KG / 개선된 KG를 같은 설정으로 비교한다.
  Astra+KG 비교를 추가해야 강한 모델에서도 KG가 도움/방해가 되는지 분리할 수 있다.
  다른 모델 출력과의 문자열 일치율, 바뀐 단어 수, -예 빈도는 정확도로 쓰지 않는다.

2순위: 생성기에 보내는 자료를 바꾼다.
  문헌 보관용 긴 인용문·검사 이력은 저장소에 남기고, 생성에는 필요한 적용 단위만 전달한다.
  각 절의 대상 구간, 원형/선어말/종결형, 보존 조건, 적합한 대안, 출처 ID를 명확히 한다.
  예: 나오 + 었 + 어요 → 나오 + 었 + 어예. 이 조합은 문헌의 완성형 인용과 구별한다.
  어휘 대안 여러 개가 절의 높임·의문 후보를 밀어내지 않게 배분한다.
  이번 compact 실험은 초기 근거이지 곧바로 운영 품질이 보장된 구현은 아니다.

3순위: KG의 '존재'와 생성의 '적합성'을 구별한다.
  먼저/앞에, 마무리/시마이, 쉬다/시다 등이 문헌에 있다는 사실은 보존한다.
  시대·지역·화자·말투·의미 조건과 현재 번역 대상의 적합성을 별도로 판정한다.
  근거가 약하거나 적용 범위가 불명확한 선택적 치환은 보류하고 원문 어휘를 유지할 수 있게 한다.
  운영 대상 지역/말투를 정한 뒤 후보의 우선순위를 평가한다. 원문 없는 새로운 금지 규칙을 사실처럼 넣지 않는다.

4순위: 분석과 결속의 공통 오류를 고친다.
  XSV/XSA 파생 서술어와 복합 서술어를 원문 구간으로 묶는다.
  Kiwi·Qwen 분석이 충돌하면 그대로 확정하지 않고 충돌을 기록하고 제한된 대응만 허용한다.
  융합 세요/죠/까요 및 인용 구성을 처리하되 주체 높임과 청자 높임을 분리한다.
  관형절 ETM, 인용절, 절 경계 등 바뀌면 안 되는 구조를 생성 계획에 표시한다.

5순위: 생성 후 보존 검사를 추가한다.
  원문에 있던 높임·과거·부정·주어·이동 방향·내용이 사라졌는지 점검한다.
  위반은 해당 구간 재생성 대상으로 삼고, 추정만으로 자동으로 예를 덧붙이지 않는다.
  방언 어미는 표준어 형태소 분석기가 오분석할 수 있으므로 검사기 자체의 오류도 검증한다.

6순위: 모델 개선의 필요성을 분리 평가한다.
  간결하고 올바른 근거를 줘도 보존 실패가 남으면 생성 모델·추론 설정 또는 학습을 검토한다.
  Astra/Sonnet은 개선 후보와 실패 유형을 찾는 데 활용하되, 원출력을 검증 없이 정답/문헌 근거로 삼지 않는다.
  학습 자료로 사용할 경우 독립 검토와 별도 개발/시험 분리가 필요하다.

7. 다음 검증 설계

동일 입력·모델·프롬프트·디코딩을 고정하고 하나씩 비교한다.
  A. 기존 전체 KG 패킷
  B. 의미 내용은 유지한 간결한 적용 계획
  C. B + 적용 범위가 확인된 어휘 후보 선택
  D. C + 분석 결속 수정
  E. D + 생성 후 보존 검사

여러 seed/반복과 새로운 최소대립 입력에서 평가한다.
예: 계세요/계셨어요/계셨나요, 출발해요/출발했어요/출발했나요, 부탁형/순수 질문형,
가는 길/갔던 길/어디 가노, 나는/나의/나한테, 먼저의 시간적·공간적 문맥.
모델 출력을 보고 정답을 끼워 맞추지 않고, 독립 화자가 먼저 보존 조건과 허용 변이를 정의한다.
