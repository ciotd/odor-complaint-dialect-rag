KG v2 조회 방식 × 생성 입력 형식: 실험 결과
2026-10-12

1. 결론

50개 입력에 대한 A/B/C/D 200개 번역을 모두 완료했다.
이번 구성에서 벡터 검색과 구간별 변환 계획은 일부 오류를 개선했지만 일관된 품질 향상을 보이지 않았다.
D(두 개선안의 결합)를 현재 방식의 대체안으로 채택할 근거는 아직 부족하다.
KG v2·기존 파이프라인은 수정하지 않았고, 실험 코드는 이 폴더 안에 분리했다.

개선과 악화가 모두 관찰된다.
- DEV006: A의 '계셔'가 B/C/D에서 '계세요'로 바뀌어 청자 높임 보존 개선.
- DEV019: A의 '걸으세'가 B/C/D에서 '걸으세요'로 바뀜. 방언성 향상과는 다름.
- LONG006: A/B의 '가노 길/좋아하노 빵'이 C/D의 '가던 길/좋아하는 빵'으로 바뀜.
  관형절 구조는 개선되지만 원문 '가는'에서 '가던'으로 바뀐 상적 차이는 남음.
- NEW005: A '될래예', B '대예', C/D '될까예'. 문의 표현 보존의 국소적 개선.
- NEW009: A '좋아허 과자', B '좋아하난 과자', C '좋아허는 과자', D '좋아하는 과자'.
  C/D에서 관형절 구조가 개선됨. 나머지 어형의 자연스러움까지 검증된 것은 아님.
- DEV008 C: '비가 마이 모 나가겠어예'로 강우 서술이 빠지면서 구조가 손상됨.
- LONG002 C: '맛있더라'가 '맛있대'로 바뀌어 경험 서술과 전언이 혼동됨.
- NEW011 C/D: A/B가 보존한 '먼저 갈게요'를 '앞에 갈게요'로 치환함.
- DEV011/NEW004: 네 조건 모두 '출발했나?/시작했나?'로 청자 높임을 잃음.

이는 한 seed의 탐색적 결과이며 독립 방언 화자에 의한 우열 판정이나 정답률이 아니다.

2. 실제 실행 범위

입력: 기존 DEV 30개 + LONG 8개 + 새 NEW 12개 = 50개.
NEW 문장은 출력 확인 전에 고정했지만 기존 실패 유형을 고려하여 만든 도전 문장이다.
독립적으로 수집한 완전한 held-out 평가셋이라고 부르지 않는다.

A: 기존 v2_graph 조회, 기존 생성 입력.
B: 형태·관계 조회 + 조건부 지식 진술 벡터 검색, 기존 생성 입력.
C: A와 같은 후보를 구간별 변환 계획으로 전달.
D: B와 같은 후보를 구간별 변환 계획으로 전달.

Qwen3.8-27B, seed 20260923, temperature 0.3, top_p 0.8, top_k 20,
max_tokens 512, enable_thinking false를 공통 사용했다.
실제 요청과 응답의 모델 ID는 일치했지만 서버 내부 체크포인트의 불변성까지 확인한 것은 아니다.
조건별 system prompt와 원문 분석·형태소 분석을 동일하게 유지했다.
기존 38개의 A 요청은 직전 v2_graph 요청과 완전히 같으며 이번에 새로 생성했다.

새 문장 분석은 12개 모두 규격 검증을 통과했다. 분석 호출은 총 15회였다.
NEW010은 필수 필드 누락으로 총 3회, NEW012는 허용되지 않는 라벨로 총 2회 호출했다.
형식 오류만 피드백했으며 정답 번역이나 사람이 작성한 문법 분석값을 넣지 않았다.
형식 검증 통과가 의미적 분석 정확성을 보장하지 않는다.

번역은 200개 모두 성공했다. 실제 호출 시도는 202회였다.
DEV016 A/D가 각각 60초 시간 초과 후 한 번씩 재시도했다. 품질을 보고 재생성한 경우는 없다.
원문·KG·기존 코드·이전 결과의 해시 및 모든 실제 요청과 응답을 보존했다.

3. 벡터 검색의 구현과 효과

로컬 intfloat/multilingual-e5-small의 기존 고정 모델을 사용했다.
KG의 3,761개 진술을 3,783개 청크로 임베딩했다. 22개 긴 진술은 여러 청크로 나눴다.
검색용 텍스트는 입력/출력 표현, 문법 기능, 조건, 사용 범위, 자연어 제약이다.
원문 인용 본문은 임베딩하지 않았고 출처 페이지는 색인에, 전체 인용은 KG와 조회 기록에 보존했다.
어휘에는 기본형과 구간 의미를, 문법에는 품사·기능·어미·시제·높임·화행을 질의로 사용했다.

관련성이 있다는 이유만으로 다른 단어의 대응을 적용하지 않도록 어휘 기본형 일치 조건을 유지했다.
문법 기능과 높임 필터, 구조화된 조건 검사도 유지했다.
각 구간에서 의미 검색 상위 12개를 추가 검토하고 기존 경로/말투 우선순위 안에서 유사도로 순위를 정했다.
따라서 B는 전체 KG에 대한 무제한 벡터 검색이 아니라 제약이 있는 혼합 검색 실험이다.

50개 중 37개에서 최종 후보 집합이 달라졌다.
순서까지 포함하면 기존 38개 중 35개, 새 12개 중 9개에서 조회 결과가 달라졌다.
전체 구간 결속 참조는 A 412개, B 439개였다. 서로 다른 구간에 같은 진술이 쓰이면 별도로 센다.
추가와 제거가 함께 일어나므로 순증 27개만으로 검색 효과를 설명할 수 없다.
A/B의 최종 출력 문자열은 50개 중 20개에서 달랐다. 이 수치는 개선율이 아니다.

주목할 사례는 LONG008이다. 혼합 검색은 첫 질문에 '-지예' 후보를 전달한다.
그럼에도 B는 '힘드셨제?', D는 '힘드셨죠?'를 출력한다.
적절해 보이는 후보의 노출 증가가 곧 올바른 형태 생성으로 이어지지는 않는다.

4. 변환 계획의 구현과 효과

같은 구간의 후보를 묶고 시제·청자 높임·주체 높임·문장 기능의 보존 정보를 명시했다.
표현 패턴, 조건, 자연어 제약, 범위, 주석, 주장 상태, 출처 페이지, 관계 경로는 유지했다.
원문 인용 본문과 행정적 검사 로그는 생성 입력에서 생략했으며 원본 조회 기록에는 남겼다.
따라서 후보 내용의 중요 필드는 유지하지만 완전한 무손실 압축이나 순수 길이 실험은 아니다.
원문 인용을 읽을 기회 자체가 줄어드는 점도 결과에 영향을 줄 수 있다.

변환 계획은 구간에 결속된 조건부 후보 목록이다.
모든 후보에 대해 하나의 최종 활용형을 확정하는 규칙 실행기는 아니다.
기존에 명시적으로 지원한 어미 조합 계획만 유지했고 새 활용형을 임의로 합성하지 않았다.
따라서 이번 결과는 '정답 활용형을 항상 제공하면 Qwen이 어떻게 행동하는가'를 검증한 실험이 아니다.

생성 user 입력 문자 수 중앙값:
A 13,310.5 / B 13,840.5 / C 11,113.5 / D 12,003.5.
50개 전체 입력 길이 합계는 A→C 약 15.9%, B→D 약 14.4% 감소했다.
분석 정보와 다수 후보는 유지되어 계획 조건에서도 입력이 상당히 길다.
A/C 출력 차이는 25문장, B/D는 20문장이다. 차이 수는 품질 점수가 아니다.

LONG006·LONG007·NEW005·NEW009에서는 계획 입력의 국소적 이점이 보인다.
반대로 DEV008·LONG002·NEW011에서는 내용 손실이나 원하지 않는 치환이 생긴다.
이 결과는 '자료를 짧게 만들면 항상 좋아진다'는 주장을 지지하지 않는다.

5. 원인에 대해 더 분명해진 점

5-1. 분석-조회 연결의 막힘은 벡터 검색만으로 해결되지 않았다.
DEV011의 출발하다는 출발/NNG + 하/XSV로, NEW004의 시작하다는 시작/NNG + 하/XSV로 분석된다.
현재 서술어 호스트 목록에서 XSV가 빠져 있어 두 문장 모두 A/B 후보가 0개이다.
이번에는 동일한 호스트 분석을 공유했으므로 의미 검색을 붙여도 누락이 남는다.
DEV018도 후보가 0개이지만 '도와줄래?'라는 공유 표현의 유지 자체를 오류로 판단하지 않는다.

5-2. '조건 검사 통과'는 적용 가능성을 완전히 증명하지 않는다.
A의 구간 결속 참조 412개 중 347개, B의 439개 중 362개에는 구조화된 conditions가 없다.
자연어 constraints가 있는 참조는 각각 410개, 434개이다.
일부 어휘 진술은 추가 조건이 없어도 되므로 이 숫자를 잘못된 지식의 비율로 해석하면 안 된다.
그러나 자연어로 남은 결합·화용 제약을 검사 코드가 충분히 확인하지 못한다는 한계는 크다.

예: LONG008의 B/D에 들어간 JO2018:v2:informal:0032는 '-래예'가 형태 목록에 있다는 진술이다.
functions는 declarative, conditions는 빈 목록이다. 근거는 JO2018 PDF 203쪽의 어미 목록이다.
주석은 결합·화용을 별도 진술과 함께 검토하라고 적고 있다.
이는 '말씀드릴게요 → 말씀드릴래예'라는 구체적인 대응의 근거가 아니다.
D 출력에 '말씀드릴래예'가 나온 것은 이런 불충분한 후보 적용 가능성을 보여주는 사례다.
해당 진술 하나가 원인이라고 확정하려면 제거 실험이 추가로 필요하며 이번에는 실시하지 않았다.

5-3. 잘못 적용되기 쉬운 후보를 그대로 두면 계획 형식도 그 문제를 물려받는다.
먼저→앞에 진술은 이번 실험에서 그대로 유지했다.
LONG001·LONG005·LONG008에서는 네 조건 모두 문제 치환이 반복된다.
NEW011에서는 A/B가 먼저를 보존했는데 C/D가 앞에를 사용했다.
즉 생성 지침을 명료하게 전달하는 것만으로 후보의 문맥 적합성이 보장되지 않는다.
근거의 존재와 현재 문장에서의 대체 가능성을 구분하는 작업이 계속 필요하다.

5-4. 생성기의 실제 활용·보존 능력도 남은 문제다.
네 조건 모두 저→나 겸양 손실(NEW002), 께서는→께는 조사 변화(NEW003)를 보인다.
구간별 보존 정보를 추가해도 일부 문장에서는 반복·상 변화·전언 변화가 발생했다.
이를 Qwen 계열 전체가 불가능하다는 결론으로 확대할 수는 없다.
이번 모델 ID와 설정·프롬프트에서의 관찰이다.

6. 검증과 해석 한계

기존 생산 코드 테스트 31개 통과.
200개 요청의 공유 분석·설정·system prompt 동일성, A/C 및 B/D의 후보 내용 동일성 검증 통과.
후보 원문 구간, 구조화 조건, 패킷 예산, 그래프 양끝 포함 여부도 검증했다.
이 검사는 언어적 자연스러움의 정답 검증이 아니다.

기존 38개 A 결과는 이전 동일 요청의 결과와 모두 같았다.
이번 실험 내부에서 완전히 같은 요청이 반복된 12개 그룹도 그룹 내 출력이 같았다.
이 관찰은 이번 결과 비교의 안정성을 보조하지만 항상 결정적이라는 보장은 아니다.

전체 50문장에 대한 검토 메모는 qualitative_review.json에 있다.
독립적인 원어민 평가가 없으므로 전체 정확도나 승률을 임의로 제시하지 않았다.
blind_review.tsv와 blind_key.json은 후속 독립 평가에 사용할 수 있다.

7. 다음 수정의 우선순위 제안

첫째, 서술어 호스트 복원과 복합 서술어·간접 요청 분석을 수정하고 공통 회귀 검사를 추가한다.
둘째, 형태의 존재만 알려주는 목록형 진술과 구체적 변환 근거를 구별한다.
      결합·화용 조건이 부족한 후보는 직접 치환 후보로 취급하지 않도록 조회 정책을 보완한다.
      필요한 조건이 문헌에 있으나 KG에 없다면 그 부분은 KG 보완 대상으로 기록한다.
셋째, 먼저/앞에 등 문맥별 적합성을 해결한 뒤 후보 수를 줄이고 실제 적용 가능한 변환 계획을 구성한다.
넷째, 생성 후 의미·부정·시제·주체/청자 높임·관형절·이동 방향의 보존 검사를 별도 단계로 구현한다.
다섯째, 벡터 검색은 후보 순위 보완 수단으로 유지할지 검토하되 이번 D를 즉시 기본 경로로 채택하지 않는다.

이번 실험은 완료되었다. 위 후속 수정은 이번 실행에 섞지 않았으며 기존 KG와 파이프라인을 대체하지 않았다.
