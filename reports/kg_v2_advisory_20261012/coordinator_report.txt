KG v2 변환 조언·반례·문헌 대조 통합 보고서
작성일: 2026-10-12

1. 이번에 수행한 작업

변환 조언자, 반례 검토자, 문헌 대조자를 별도 작업자로 실행하고 주 세션이 조정·통합을 담당했다. 작업자는 세션 모델을 상속했으며 별도의 모델명·추론 수준을 지정하지 않았다. 역할 분리는 독립적인 사람의 검증을 뜻하지 않는다.

변환 조언자는 저장된 Astra/Sonnet 비교 결과와 최근 A/B/C/D 실험을 토대로 재사용 가능한 제안 9개를 작성했다. 반례 검토자는 10개 문제군과 새로운 대조 입력 20개를 작성하고 제안 9개를 검토했다. 문헌 대조자는 10개 쟁점을 원문·KG·실제 조회 기록과 대조했다. 조정자는 인용 22개의 해당 페이지 문자 일치, 지식 ID 실재, 누락 예문의 공백 정규화 검색, 이전 실험 파일의 해시를 검증했다. 중요 표와 예문은 원문 PDF 이미지로 추가 확인했다.

문헌 대조자가 실제 PDF 7종의 SHA256을 등록대장과 대조했다. 이번 검토는 문제와 관련된 원문 구간 검토이며, 474쪽 전체 의미 전수 재검수가 아니다.

2. 통합 결과와 반영 상태

reviewed_advice.json은 모델 조언과 원문 근거의 연결을 별도로 저장한 보완 제안 자료이다. 각 항목에 제안 내용, 적용 조건, 보존 사항, 반례 검토, 관련 문헌 쟁점, 불확실성, 생산 KG 적용 여부가 있다.

반례 검토 기준 설계 수용 3건: 파생·복합 서술어 분석(ADV001), 높임·겸양·주어/호격 보존(ADV006), 관형절 보존(ADV007). 이는 진단·설계 방향을 수용한 것이며 모든 방언 예문의 정확성이나 생산 적용을 승인한 것은 아니다.
나머지 6건은 의문 유형, 요청/명령, 죠/네요, 종결어미 결합, 어휘의 의미 역할, 인용/회상 구분의 조건을 더 좁혀야 한다.

생산 KG·조회기·생성기와 기존 실험 출력은 이번 작업에서 수정하지 않았다. 새로운 20개 입력은 기존 50개와 문자열 중복이 없지만 아직 번역을 실행하지 않았다. 모델 작성 진단 자료이며 사람의 정답은 없다. 따라서 이번 결과를 번역 품질 개선 실험으로 보고하지 않는다.

3. 원인별로 구분한 발견

(가) 원문에 있으나 KG에 해당 예문이 빠져 있는 경우
NAMU_HONORIFICS_20260908 PDF26에 가세예, 보실래예가 있다. facts.jsonl의 모든 문자열을 공백 정규화하여 검색해도 두 예문은 발견되지 않았다. 원문 사례를 추가 추출할 구체적 대상이다. 다만 문자열이 없다는 사실이 모든 동등한 추상 규칙의 부재를 증명하지는 않는다.

(나) KG에 있으나 적용 지식으로 연결되지 않거나 조회되지 않는 경우
맛있지예는 문법 문헌 PDF37의 어휘 근거와 높임 문헌 PDF4의 reference_only usage 근거에 존재한다. 표현 자체가 KG에 없다는 주장은 틀리다. 다만 PDF26 해예체 문맥의 사례를 독립적인 적용 지식으로 구성한 항목은 확인하지 못했다.
RYU2014:v2:full:0098에는 관형형 보존 정보가 있지만 LONG006의 baseline/hybrid 조회에서 선택되지 않았다. 근거의 원문 범위를 존중하면서 변환 후보와 별도로 보존 지침을 전달할 통로가 필요하다. reference_only 항목을 전부 치환 후보로 바꾸는 방식은 적절하지 않다.
DEV013은 관련 의문형 정보가 KG에 있는데도 baseline/hybrid 문법 후보가 0개였다. 형태·의문 구조·간접 화행을 연결하는 분석/조회 문제를 조사할 구체적 사례다.

(다) 이미 필요한 활용이 조회되는 경우
LONG001에서는 먹다→묵다 관련 정보와 묵고 활용이 실제 전달된다. 현재도 먹고→묵고 경로가 없다고 말할 수 없다. 이 경우 다른 문장으로 범위를 확대해 검증하되, 이미 전달된 지식을 생성기가 쓰는지부터 분리해 봐야 한다.

(라) 문헌 정보만으로 일반 적용을 확정할 수 없는 경우
종결어미 목록에 -래예가 있다는 사실만으로 약속 표현 -ㄹ게요에 적용할 수는 없다. 명사서술 모양이래예와 의향 질문 보실래예는 구성이 다르다. 목록·개별 예문·조합 규칙·적용 조건을 구별해야 한다.
이런 틈을 조언자가 적용 조건과 반례를 갖춘 규칙 가설로 제안할 수 있다. 출처는 model_advice_not_documentary_fact로 유지한다. 관련 문헌이 일부 구성요소를 뒷받침해도 모델이 만든 모든 예문과 일반화 전체를 문헌 사실로 승격하지 않는다.

4. 기존 평가의 정정

먼저→앞에와 더라→대를 무조건 의미 오류라고 했던 기존 해석은 정정한다. RYU2014 PDF27에 앞에 가요, NAMU_GRAMMAR_20260908 PDF28에 -더라→-대/-더라/-더래가 실제로 있다. 앞에 갈게요, 맛있대는 적용 문맥·지역·표기·자연스러움을 확인할 대상으로 남긴다. 문헌에 있다는 이유만으로 해당 생성문이 자동 정답이 되는 것도 아니다.

기존 출력·로그는 보존했다. 해당 표현을 확정 오류로 센 이전 정성 평가와 개선 실험 해석은 interpretation_corrections.txt를 함께 읽어야 한다. 예를 들어 먼저 대응을 제거한 실험은 출력에 영향을 준다는 사실을 보여주지만, 제거가 정확도 개선이라는 결론까지 보장하지 않는다. 이번 검토로 A/B/C/D 전체 품질 순위를 새로 확정하지 않는다.

5. 실제 전달량 측정

직전 실험의 jobs.json에서 저장된 실제 생성 입력을 읽고 retrieval.json과 일치하는지 검사했다. 50개 입력(DEV30, LONG8, NEW12)을 각 조건에서 사용했다. 입력 ID 하나에는 여러 문장이 들어갈 수 있다.

구간은 후보가 실제 전달된 고유 input_binding.span이다. 어휘 구간과 절 구간이 겹칠 수 있어 문장을 서로 겹치지 않게 나눈 개수와는 다르다. 후보 없는 입력 3개도 입력당 평균에 포함했다. 문자수는 실제 compact JSON 직렬화 길이이며 키·출처·인용 등을 포함하고 토큰수와는 다르다.

조건 | 입력당 구간 | 구간당 후보 | 구간 후보 묶음 평균자 | 입력별 가장 긴 묶음의 평균자 | 관측 최대자
A 기존 조회/기존 전달 | 3.0000 | 2.7467 | 4133.71 | 7280.86 | 11307
B 의미 검색 추가/기존 전달 | 3.2000 | 2.7437 | 4039.72 | 7190.36 | 11284
C 기존 조회/변환 계획 | 3.0000 | 2.7467 | 2728.07 | 4687.76 | 6492
D 의미 검색 추가/변환 계획 | 3.2000 | 2.7437 | 2742.57 | 4822.26 | 6484

후보 묶음 길이는 같은 구간의 후보 배열 길이이다. 공통 그래프 경로·전체 문장 분석·지시문은 제외한다. C/D 구간 공통 보존 지침까지 포함한 구간 표현 평균 길이는 각각 3206.79자/3221.51자이다. 원래 38개 입력만 따로 집계한 수치도 statistics.txt에 있다.

이전 설명의 정정: 24,000자는 구간별 한도가 아니라 입력 전체 참고 패킷(references+graph_paths)의 한도이다. 후보 선택 중 관계 경로에 2,000자를 유보한다. C/D의 계획 형식 재구성에는 별도 24,000자 제한이 없다. 문장 분석과 지시문을 포함한 전체 모델 입력 한도도 아니다.

6. 개수·분량 제한에서 실제 확인한 점

A/C는 150개 전달 구간 중 35개, B/D는 160개 중 37개가 6개 후보 상한에 도달했다. 개수 제한 탈락 기록이 있는 입력은 A31개/B33개, 패킷 길이 제한 탈락 기록이 있는 입력은 A10개/B12개였다. 탈락 기록은 고유한 유효 규칙이나 필요한 규칙의 누락 개수가 아니다. 후보 평균이 약 2.75개라고 해서 제한이 영향 없다고 결론 내릴 수 없다.

반대로 참고 패킷 평균이 A12499자/B13024.78자이고 C9948.24자/D10636.9자라는 사실만으로 정보 과잉이 원인이라고 확정할 수 없다. 짧은 문장에 상당한 구조화 정보가 들어간다는 관찰까지 가능하다. 전체 user 메시지 평균은 A15942.06자/B16467.84자/C13400.30자/D14088.96자이다.

개수와 분량의 인과효과는 아직 분리 실험하지 않았다. 다음에는 조회된 후보 풀과 Qwen 설정을 고정하고 (1) 후보 상한만 변경, (2) 후보 구성 고정 후 근거 표현 길이만 변경하는 실험을 분리해야 한다. 탈락한 후보가 필요한 지식인지 먼저 표시하고, 필요한 후보 회수·부적절 후보 유입·생성 적용·의미 보존을 각각 본다.

7. 다음 구현에 사용할 순서와 통과 기준

첫째, 현재 결과를 회귀 기준으로 고정하고 기존 오류 판정을 정정한다. 사람이 검토하지 않은 모델 출력을 정답으로 취급하지 않는다.
둘째, 관형형 등의 보존 정보를 조회하는 경로와 파생·복합 서술어/간접질문 분석의 연결을 수정한다. 목표 사례에서 어떤 근거가 누락되어 회수되는지 기록한다.
셋째, 문헌에서 확인한 누락 사례는 버전을 기록하며 추출·구조화한다. 원문 예문, 해석한 결합 조건, 모델 제안 규칙을 분리한다.
넷째, reviewed_advice.json의 조건·반례를 바탕으로 적용 검사와 구간별 변환 계획을 구체화한다. 명사서술·의향·약속처럼 표면형이 겹치는 구성은 구분한다.
다섯째, 새 대조 입력 20개와 기존 사례로 시제·높임·부정·화행·관형절 역할 보존을 검사한다. 미지의 입력에 대한 일반화와 자연스러움은 별도 화자 평가가 필요하다.
여섯째, 후보 개수와 근거 길이의 효과를 따로 비교한다. 조건 통과 후보를 정확히 전달해도 실패한 사례를 생성 모델 측 문제로 분리한다.

이 순서는 후속 구현안이며 이번에 실행한 새 번역 실험이 아니다.
