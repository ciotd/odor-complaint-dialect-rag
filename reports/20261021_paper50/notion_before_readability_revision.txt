## 1. 이번 실험에서 확인한 핵심

- 동일한 Qwen3.8-27B 서버 모델에 원문만(P), 분석만(A), KG 자료 포함(K)을 각각 제공함.
  - 원문만(P), 분석만(A), KG자료포함(K)
- 최초 출력에서 높임 보존에 뚜렷한 문제가 없다고 평가한 사례는 P 23/50, A 18/50, K 49/50이었다. 충분한 방언 표현이 관찰된 사례는 P 3/50, A 2/50, K 41/50이었다. 이는 Codex의 사례 판정이며 공인 정확도나 독립 화자 평가 점수가 아니다.

## 3. 평가 기준과 전체 결과

| 평가 축 | 보는 내용 | 판정 2 / 1 / 0 |
| --- | --- | --- |
| 의미 보존 | 누가 무엇을 하는지, 부정·시제·이동 방향·의도가 유지되는가 | 2: 뚜렷한 문제 없음·충분한 실현 / 1: 부분 보존·부분 실현·우려 / 0: 뚜렷한 손상·미실현 |
| 높임 보존 | 청자 높임·주체 높임·저/제 지칭을 원문 수준대로 유지하는가 | 2: 뚜렷한 문제 없음·충분한 실현 / 1: 부분 보존·부분 실현·우려 / 0: 뚜렷한 손상·미실현 |
| 문장 자연스러움 | 문장 구조와 어미 결합이 읽기 자연스러운가; 지역 표기 확정과 구분 | 2: 뚜렷한 문제 없음·충분한 실현 / 1: 부분 보존·부분 실현·우려 / 0: 뚜렷한 손상·미실현 |
| 방언 표현 실현 | 문맥에 맞는 방언 어휘·종결 표현이 드러나는가; 단순 축약이나 표준어 그대로는 충분한 실현으로 세지 않음 | 2: 뚜렷한 문제 없음·충분한 실현 / 1: 부분 보존·부분 실현·우려 / 0: 뚜렷한 손상·미실현 |

- 원문과 출력을 직접 읽고 의미·높임·문장 연결·방언 실현을 구분했다. 네 축 점수를 합쳐 하나의 성능 점수로 만들지 않았다.
- 평가자는 이 보고서를 작성한 Codex다. 조건을 알고 평가했으며 독립 방언 화자의 눈가림 평가가 아니다. 지역·세대에 따른 자연스러움이 불명확한 형태는 사례 메모에 남겼다.
- 정답 번역이 없으므로 정답 문자열과의 일치율을 계산하지 않았다. -다·-라처럼 표준어에도 있는 형태, 낼·짐 같은 일반 축약만으로 충분한 방언 실현을 인정하지 않았다.
- 최초 출력은 세 조건의 기본 생성 차이를, 최종 출력은 동일 검사와 최대 1회 재검토까지 포함한 운영 결과를 보여 준다. 재검토 후 결과도 같은 기준으로 직접 확인했고, 바뀐 32건의 판정 근거를 별도 기록했다.

최초 출력: 각 판정에 해당하는 건수 — 표의 숫자는 순서대로 2점 / 1점 / 0점 건수이며 각 칸 합계는 50이다.

원문 완전 동일 여부는 공백·문장부호까지 포함한 정확한 비교다. 동일하지 않다는 것만으로 방언 변환 성공은 아니다. 자동 경고는 오류 탐지 결과이고, 위의 수동 정성 판정과 다른 지표다.

- 자동 재검토는 P/A의 높임을 상당 부분 되살렸지만 표준어 원문 또는 표준어 정중체로 되돌리는 경우가 많았다. 보존 검사만으로 방언 표현의 생성을 확보하지 못했다.
- 자동 검사 통과도 충분하지 않았다. P/ADVCE001A의 “기차 지금 정차하고 계신가요?”는 기차에 불필요한 높임을 붙였고, A/QUAL002의 “거라”는 높임이 복원되지 않았지만 최종 강한 경고가 남지 않았다.
- 후보 제공과 적용은 별개다. K/NEW007은 온나를 받았지만 와를 유지했고, P/DEV017은 KG 없이도 K와 같은 주이소를 생성했다. 개별 출력의 자연스러움을 KG만의 효과로 자동 계산하지 않았다.

## 4. 실제 전달량과 후보의 성격

| 측정값 | 평균 | 최소 | 최대 | 계산 대상 |
| --- | --- | --- | --- | --- |
| 입력당 대상 구간 수 | 2.24 | 1 | 9 | 50개 K 요청의 transformation\_plan 그룹 |
| 구간당 후보 수 | 1.69 | 1 | 6 | 실제 전달된 모든 구간; 합계 후보/합계 구간 |
| 구간당 후보 배열 글자 수 | 2248.18 | 825 | 6236 | candidate JSON 전체: 속성명·조건·출처 포함, 압축 직렬화 |
| 입력당 조회 자료 묶음 글자 수 | 7703.02 | 1627 | 22399 | 계획으로 줄이기 전 references+관계+보존 정보 |
| 입력당 변환 계획 글자 수 | 6041.06 | 1231 | 19438 | 생성기에 실제 전달된 transformation\_plan 전체 |
| 입력당 명시 관계 경로 수 | 0.22 | 0 | 3 | 실제 graph\_paths 배열 항목 수 |

| 조건 | 전체 user 메시지 평균 글자 수 | 실제 최초 요청 prompt 토큰 평균 |
| --- | --- | --- |
| P · 원문만 | 26.5 | 86.1 |
| A · 분석만 | 4071.7 | 1524.2 |
| K · KG 사용 | 10292.2 | 3599.5 |

- 입력 1건은 긴 발화에서 여러 문장을 포함할 수 있다. 구간은 단어 하나일 수도, 종결을 가진 절 전체일 수도 있으며 서로 겹칠 수 있다. 따라서 구간 수는 띄어쓰기 단어 수나 문장 수와 다르다.
- 후보는 해당 구간에 쓸 수 있을지 검토하는 대안이다. 모든 후보를 한꺼번에 적용하라는 뜻이 아니다. 같은 후보 ID가 서로 다른 구간에 붙으면 각각 하나로 세었다.
- 구간당 최대 6개 후보. 24,000자는 구간마다가 아니라 입력 한 건의 조회 자료 묶음 전체 제한이다. 관계 경로용 2,000자를 미리 남겨 후보 추가는 22,000자 선에서 제한한다. 이후 분석과 지시를 합친 user 메시지에는 이 제한이 그대로 적용되지 않는다.
- 글자 수는 Python len 기준으로 JSON의 속성명·공백 없는 구분기호까지 포함한다. 토큰 수는 서버의 usage.prompt\_tokens로 system·user·대화 형식이 모두 포함된다. 글자와 토큰은 다른 단위다.
- 최대 6개·글자 제한의 영향은 후보 제외 기록으로 확인할 수 있다. 다만 이번에는 후보 수를 바꿔 재실험하지 않았으므로 너무 많아서/적어서 실패했다고 인과적으로 단정할 수 없다.

| 후보 제외 사유 | 구간·후보 처리 건수 |
| --- | --- |
| 구간당 6개 제한 | 13 |
| 입력당 전체 글자 제한 | 26 |
| 같은 구간의 복합 구성 대안 제한 | 2 |

| 전달 후보의 출처 성격 | 구간에 붙은 후보 건수 |
| --- | --- |
| 문헌 구성요소를 입력에 맞게 조합한 계획 | 55 |
| 문헌에서 구조화한 항목 | 134 |

이번 50건에 실제 전달된 후보는 문헌 항목 134건과 문헌 구성요소를 조합한 계획 55건이었다. 별도 MODEL\_ADVICE 후보는 실제 전달되지 않았다. 모델 조언으로 발전시킨 운영 정책과 문헌 조합 코드의 영향까지 없다는 뜻은 아니다.

| 조회 경로 코드 | 쉬운 설명 | 전달 후보 수 |
| --- | --- | --- |
| function\_bound\_terminal | 원문 끝의 기능·높임에 묶인 종결 계획 | 55 |
| bound\_lexical\_mapping | 원문 단어의 기본형과 뜻에 묶은 어휘 대응 | 72 |
| source\_form | 원문에 나타난 표현 형태와 맞춘 후보 | 33 |
| clause\_function | 평서·질문 등 절의 기능으로 찾은 후보 | 3 |
| source\_bound\_construction | 인용·의도 등 여러 요소가 결합한 원문 구성 후보 | 5 |
| lexical\_to\_inflection | 어휘 대응에서 연결 관계를 따라 찾은 활용 후보 | 21 |

전체 50건 중 5건에서 명시적인 graph\_paths가 전달됐고 경로 항목은 총 11개였다. 대부분은 출처·조건을 포함한 지식 항목과 변환 계획 자체를 사용했다. 따라서 K의 개선을 모두 다단계 관계 탐색의 효과로 설명할 수 없다.

구체적인 추천 표면형이 붙은 후보 55건 중 49건은 그 문자열이 최초 출력에 나타났다. 이는 활용이 달라지면 놓칠 수 있고 짧은 문자열이면 우연히 일치할 수 있는 관찰이다. 지식 사용률·정확도·검색 재현율로 해석하지 않는다.

지식 항목(진술)은 “어떤 표현이 어떤 조건에서 어떻게 쓰이는가”를 기록한 한 묶음이다. JSON은 이 묶음의 저장 형식이고, 그래프는 같은 정보를 연결 구조로 펼친 표현이다.

| 속성 | 뜻 | 쓰임 |
| --- | --- | --- |
| id / source\_id | 지식 항목 번호와 출처 번호 | 어떤 근거를 사용했는지 추적 |
| type | 지식이 설명하는 내용의 종류 | 어휘·종결·활용 등 조회 경로 선택 |
| source\_pattern / target\_pattern | 바꾸기 전 표현과 대응 표현, 기본형·뜻 | 원문과 후보의 형태·의미 대조 |
| functions | 설명·질문·요청 등 표현의 기능 | 기능이 다른 어미의 혼용 제한 |
| conditions | 값으로 검사할 적용 조건 | 기본형·시제 형태·기능 등의 일치 검사 |
| constraints | 글로 적힌 예외·주의 사항 | 모든 항목을 자동 판정하지는 못함 |
| scope | 지역·시대·높임 범위 | 특정 자료의 표현을 모든 화자로 확대하지 않음 |
| evidence | 원문 인용과 PDF 페이지 | 조회 후보의 근거 추적 |
| claim\_status / usability | 확인형·일반화·해석 등의 성격 / 변환 후보 또는 참고용 | 원문 사실과 해석·모델 제안을 구별 |

예: “명사 뒤 예요를 라예로 표현할 수 있다”는 어미 지식 항목 하나다. 중심 노드에서 입력 표현·대응 표현·조건·근거로 연결되고, 근거는 PDF 쪽과 문헌으로 이어진다. 지식 유형 ending은 어미 조회 경로의 후보를 찾는 데 쓰이고, 노드 유형 Evidence는 출처를 따라갈 때 쓰인다. 두 분류는 같은 것을 중복해서 세는 것이 아니다.

실제 지식 JSON 예시는 첨부 HTML의 6절에서 펼칠 수 있다. 항목 ID: NAMU\_GRAMMAR\_20260908\:v2\:ending\_repair:0001.

## 7. Qwen·Kiwi 분석, 조회와 조건 검사

| 단계 | 입력 | 출력 | 누가 판단하는가 |
| --- | --- | --- | --- |
| Qwen 분석 | 표준어 전체 발화 | 절 위치, 평서/질문/요청, 높임, 시제, 서술 유형 등의 JSON 가설 | Qwen. 이번에는 저장 분석 재사용 |
| Kiwi | 동일 표준어 | 형태소·품사·위치. 코드가 기본형과 어미 묶음을 정리 | Kiwi + Python |
| 원문 대조 | 두 분석과 실제 글자 위치 | 원문에 붙인 구간, 기본형, 기능, 높임 등의 조회 조건 | Python. 불확실한 분석은 확정 정답 아님 |
| 후보 찾기 | 조회 조건 | 어휘/활용/종결/복합 구성에 맞는 지식 항목 | Python 로컬 그래프 조회 |
| 조건 확인 | 후보 조건 + 입력/후보 속성 | 충족·불일치·모름, 추가 검토 이유 | Python 규칙 검사 |
| 후보 정렬·묶기 | 조건 검사 후 후보 | 우선순위·구간 균형·최대6개·전체 글자 제한을 적용한 자료 | Python |
| 실제 적용 | 원문·분석·후보·보존 지침 | 방언 발화 텍스트 | Qwen 생성 모델 |

- 조회 코드는 Python이다. JSON은 조회 코드 그 자체가 아니라 코드가 읽는 분석값·후보·생성 요청의 형식이다. Qwen이 임의의 Cypher나 Python을 작성해 실행시키는 구조가 아니다.
- 현재 조회는 기본형/표현 일치와 문장 기능을 함께 사용한다. 예를 들어 먹다의 대응을 찾고 candidate\_has\_inflection 관계로 활용을 따라가거나, 높임 평서문이라는 기능에 맞는 종결 계획을 먼저 만든다.
- Qwen과 Kiwi를 각각 사용하지만, “항상 두 모델이 동시에 병렬 실행된다”는 뜻은 아니다. 이번 실행은 기존 Qwen 분석을 읽고 Kiwi·조회·요청 구성을 순서대로 수행했다. 병렬 실행 2개는 번역 API 요청에 관한 설정이다.
- 시제·높임·화행 등 보존 목표 전체가 하나의 완전한 검사기로 증명되는 것은 아니다. 값으로 적힌 조건은 코드가 검사하지만, 자연어 의미·지역·시대·예외는 검토 지시로 남을 수 있다.

| 조건 판정 | 뜻 | 현재 처리 |
| --- | --- | --- |
| satisfied 충족 | 필요한 값과 실제 값이 같음 | 후보 자격 검토를 계속함. 최종 자연스러움 보증 아님 |
| failed 불일치 | 필요한 값과 실제 값이 다름 | 제외 |
| unknown 모름 | 필요한 값이 없거나 불명확 | 현재 문장 조회에서 제외 |
| 조건 배열이 비어 있음 | 검사할 구조화 조건이 없음 | 아무 조건이나 맞는다는 증거가 아님. 자연어 범위·뜻 검토가 필요 |

## 8. 생성 프롬프트와 실제 한 사례의 전체 흐름

system 메시지는 매 요청에 공통인 역할·목표 지시다. user 메시지도 프롬프트의 일부이며 원문과 해당 입력의 분석·지식 자료가 들어간다. 자연어 지시와 JSON 데이터가 함께 프롬프트를 구성한다.

이번 실험의 정확한 고정 system 지시

```txt
다음 표준어 발화를 자연스러운 경상도 방언으로 바꿔 주세요. 원래 의미, 질문·부탁 등의 발화 의도, 상대를 대하는 높임 수준을 유지하세요. 원문에 없는 내용은 추가하지 말고, 변환한 발화만 출력하세요.
```

분석용 Qwen 지시는 생성 지시와 다르다. “번역하거나 방언 표현을 제안하지 말고 JSON 객체 하나만 출력”하도록 요구하고, 평서/질문/요청·높임·시제의 분석값과 원문 구성을 출력하게 한다. 현재 분석 코드의 요청 기본값은 temperature=0, top\_p=1, max\_tokens=4200이다. 이번 실험은 그 단계의 저장 분석을 재사용했으므로 이 설정으로 새 분석 50건을 호출했다고 보고하지 않는다. 분석 프롬프트와 JSON 출력 규격은 snapshot/current\_kg/experiments/run\_auto\_analysis\_[development.py](http://development.py)의 analysis\_system/raw\_schema에서 확인할 수 있다.

A/K의 정확한 공통 user 지시

```txt
standard를 자연스러운 경상도 방언으로 변환하세요. analysis와 source_morphology는 원문 분석의 가설이며 원문이 우선입니다. transformation_plan 또는 references와 graph_paths는 조건부 참고 자료입니다. 의미·지역·시대·높임·결합 조건이 맞는 자료를 선택하고 관련 없는 자료는 사용하지 마세요. 조건 미확인은 적용 허용이 아니며 연결된 진술끼리 조건을 상속하지 않습니다. 기본형 대응과 완성 활용형을 구별하고 원문의 부정·시제·높임·인용·발화 의도를 유지하세요. preservation의 관형절·겸양·주체와 청자 높임·이동 관점 보존을 어휘 치환보다 우선하세요. 모델 조언 후보는 원문 확인형이 아니며 불확실하면 원문의 구조를 보존하세요. 표에 없는 활용형은 표에 실린 확인형으로 주장하지 마세요. 원문에 없는 내용을 추가하지 말고 변환한 발화만 출력하세요.
```

## 11. 50건 실제 결과와 근거

각 행의 평가는 \[의미, 높임, 자연스러움, 방언 실현\] 순서다. 최초·최종이 같으면 동일로 표시한다. 상세 후보 표의 “표면 관찰”은 추천형이 출력에 글자 그대로 나타났는지만 뜻하며, 모델 내부의 지식 사용 증명이 아니다.

상세표의 검토 표시: textual\_constraints\_require\_review는 글로 적힌 제약 검토, source\_scope\_requires\_review는 지역·시대 범위 검토, claim\_status\_requires\_review는 근거 성격 검토, interpreted\_condition\_requires\_review는 해석해서 만든 조건 검토, sense\_requires\_review는 단어 뜻 검토를 뜻한다. 이 표시는 오류 확정이나 모든 조건 검사 완료를 뜻하지 않는다.

| 의미 회귀와 수정 | DEV002 가는→가던→가는 | KG가 있어도 원문 수식 의미를 바꿀 수 있음. 검사가 이 사례는 복원 | 검사의 놓침·잘못 경고를 독립 평가 |
| 말투 혼용·어휘 범위 | LONG003 맛있소/주이소, LONG004 이빠이, LONG002 올 | 문헌에 존재하는 표현도 동일 화자 맥락의 자연스러움을 보장하지 못함 | 지역·세대 화자 판단으로 후보 범위 보완 |
| 검사 통과와 정답의 차이 | 최종 P/ADVCE001A 계신가요, A/QUAL002 거라 | 표면 패턴 검사의 범위 밖 오류가 남음 | 방언 화자 평가와 의미·높임 항목별 누락 점검 |

- 위 해석은 이번 로그와 출력의 관찰에 근거한 원인 가설이다. 후보 개수·문장 길이·특정 규칙 하나의 인과효과를 별도 실험으로 증명한 것은 아니다.
- 논문에서 가능한 표현: “기존 개발 사례 중 선정한 50개 발화에서, 동일 생성 모델에 조건부 KG 자료와 변환 계획을 제공했을 때 높임과 종결 표현의 보존·실현이 개선되는 양상을 관찰했다.”
- 피해야 할 확대 해석: “임의의 표준어 입력에서 일반 성능이 검증됐다”, “정확도 98%”, “원어민 평가에서 우수했다”, “그래프 구조만의 효과가 입증됐다”.
- 새 평가를 한다면 선택에 쓰지 않은 입력을 먼저 고정하고, 조건을 가린 복수 화자 평가와 의견 불일치 기록을 추가하는 것이 다음 단계다. 이번 요청 범위에서는 새 실험이나 운영 코드 수정을 하지 않았다.

평가 항목을 구분하고 평가자·절차·한계를 공개하는 설계는 자연어 생성 평가 연구의 일반적인 권고를 참고했다. 이 보고서의 자동 모델 평가는 그 논문의 독립 사람 평가를 수행했다는 뜻이 아니다.

[평가 설계 참고 논문](https://aclanthology.org/W19-8643/)

- 문헌 3종과 위키 PDF 4종은 근거의 성격이 다르다. 서로 재인용한 내용은 독립된 증거로 중복 계산하지 않는다.
- 9가지 지식 유형은 항목 내용의 분류, 8가지 노드 유형은 저장 요소의 분류, 19가지 관계 유형은 요소 사이 연결의 분류다. 같은 지식 항목 하나가 여러 노드와 관계로 펼쳐진다.
- 문헌 밖 모델 조언은 advisory\_rules.json의 별도 제안으로 유지하고 원문 직접 확인형으로 쓰지 않는다. 문헌 구성요소를 조합한 PLAN도 완성 문장의 원문 확인을 뜻하지 않는다.
- Neo4j는 이전 시각화·검증에 사용했다. 이번 생성 경로는 facts.jsonl과 graph.json을 읽는 Python이며 Neo4j나 의미 임베딩 검색을 호출하지 않는다.
- 경북40대 이상 별도 페르소나는 이번 고정 지시에 없다. 목표는 자연스러운 경상도 방언이며 출처의 세부 지역·세대 범위가 혼재한다.
- 이 실험은 가중치를 학습하는 방식이 아니다. Qwen의 분석·생성 호출과 외부 지식 제공을 비교한다. Claude API 자동 피드백 시스템은 아직 구현하지 않았다.
- 분석과 조회는 오류를 포함할 수 있다. JSON 형식 검사 통과나 자동 경고0개를 번역 정답으로 취급하지 않는다.
- 이 보고서의 모델 평가는 관찰과 해석이다. 독립 화자 평가, 정답 기반 점수, 통계적 우월성 검정은 수행하지 않았다.
