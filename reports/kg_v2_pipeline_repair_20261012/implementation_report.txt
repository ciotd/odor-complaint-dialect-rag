KG v2 검토 결과의 실제 파이프라인 반영 — 2026-10-12

1. 반영 완료 범위

이번에는 검토 자료 작성에서 멈추지 않고 실제 KG 데이터, 조회 코드, 생성 입력과 보존 검사 경로를 수정했다. 기존 수정 사항을 덮어 초기화하지 않았고, 수정 전 KG·코드와 이전 실험 로그를 보존했다. 모든 방언 번역 오류가 해결되었다는 뜻은 아니다.

KG:
- 높임 문헌 PDF26의 가세예·보실래예·맛있지예를 독립 attested_example 3개로 추가했다. reference_only로 유지하여 예문 하나를 범용 치환 규칙으로 만들지 않았다.
- 관형형 보존 진술 RYU2014:v2:full:0098에 설명 본문 PDF20 근거를 추가했다.
- 3,761→3,764진술, 25,783→25,799노드, 35,358→35,385관계.
- build.py --require-full의 스키마·원문 인용·페이지·기존 KG 보호 검사를 통과했다.

분석과 조회:
- 같은 어절의 NNG/NNP/XR+XSV/XSA를 원문 위치에 결속한 파생 서술어로 복원한다. 명사만 있는 경우나 어절 경계를 넘는 결합은 만들지 않는다.
- 계세요를 계/NNG+이/VCP+세요/EF로 읽는 특정 분석 오류를 실제 계세요 표면형 안에서만 복원한다. 계라는 명사를 전역 치환하지 않는다.
- 종결절의 조회용 서술어는 EF, 연결절은 EC인 실제 호스트에서 고른다. 관형형을 종결절 호스트로 쓰지 않는다.
- 원문의 질문 형식과 요청 의도를 함께 유지하며 간접 요청이라는 이유만으로 모든 기능 후보를 배제하던 경로를 제거했다.
- 원문 형태 일치가 없고 문장 기능만 맞는 후보는 구조화 적용 조건이 없으면 제외한다. JO2018의 -래예 목록처럼 존재 사실만으로 약속 문장에 적용되던 경로를 제한했다. KG 원문 지식 자체는 삭제하지 않았다.
- reference_only 관형형 보존 정보를 preservation 채널로 전달한다. 직접 치환 후보로 승격하지 않는다.

모델 조언:
- kg_v2/advisory_rules.json에 문헌 외 조합 정책을 별도로 기록하고 활성화했다.
- 범위는 원문에 결속한 비격식 높임 종결어미의 제한된 후보 집합이다. 예: 나요→나예, 죠→지예, 세요→세예, ㄹ까요→ㄹ까예, ㄹ게요→ㄹ게예.
- 주절 EF·원문 높임·허용 어미 목록·시제/서술부 보존을 확인한다. 모든 요를 전역 치환하는 규칙이 아니다. 내포 어미와 격식 높임에는 자동 적용하지 않는다.
- 근거 구성요소는 문법 full0702와 높임 full0124 및 새 실제 예문에 연결한다. 완성형의 일반 적용은 model_advice_not_documentary_fact로 표시한다. 이것이 문헌 직접 확인형이나 화자 정답이 된 것은 아니다.
- 검토 제안9건 전체를 각각 완성된 문법 규칙으로 승인한 것이 아니다. 분석·보존 원칙과 범위를 좁힌 조합부터 반영했다. 지역·화용의 모든 조건은 여전히 해결되지 않았다.

생성:
- 실제 make_request 기본 경로에서 구간별 transformation_plan을 사용한다. 원문 분석과 형태소는 함께 전달한다.
- 같은 구간의 후보·조건·범위·근거 페이지·원문/모델 조언 출처를 묶는다. 긴 근거 인용 본문과 행정적 검사 로그는 생성 입력에서 제외하고 조회 로그에 보존한다.
- 문법·높임을 보존하는 제한적 조합 후보에 높은 조회 우선순위를 주었다. 후보수 상한6개는 유지했다.
- 문서화된 24,000자 패킷 예산에는 이번부터 preservation 정보도 포함된다. 생성용 계획 재직렬화와 전체 프롬프트는 별도 길이다.

생성 후 검사:
- 청자 높임의 명확한 소실, 저/제→나/내 겸양 변경, 관형절→종결형 및 일부 관형 시제·상 변경, 가는 길/오는 길의 관점 변경을 검사한다.
- 부정·과거·주체 높임의 분석 불확실성과 질문 문장부호 변경은 검토용 경고로 남긴다. 일반적인 의미 동등성 판정기는 아니다.
- 앞에의 시간 용법과 -대의 회상 용법은 표면형만 보고 오류 처리하지 않는다.
- 강한 보존 경고에만 최대1회 수정을 요청한다. 최초 출력과 수정 결과를 모두 저장한다. 강한 문제가 남거나 새로운 종류의 경고가 생기면 수정 결과를 채택하지 않는다.
- CLI translate 및 배치 generate에 연결했다. 최종 검사 경고가 남으면 CLI는 stderr에 검토 필요 상태를 알린다.

2. 실행한 비교

입력: 기존50개 + 앞서 작성한 새 대조20개 = 70개.
기준선: 기존50개는 고정된 A 결과를 재사용. 새20개는 수정 전 스냅샷으로 생성.
입력 분석: 기존50개 공유, 새20개 Qwen 분석(총22회 시도) 후 수정 전후 동일 분석을 사용.
수정 후: 70개 최초 생성 모두 성공. 5개 입력에 보존 수정 각1회. 수정 결과 채택1개, 미채택4개.
새 번역 호출은 기준선20 + 수정후70 + 보존수정5 = 95개 성공 응답이다. 새 분석22회와 구분한다. 최초 네트워크 제한으로 서버에 도달하지 못한 기록은 blocked_network_attempts에 별도 보존했다.
모델·설정: Qwen3.8-27B, seed20260923, temperature0.3, top_p0.8, top_k20, max_tokens512, thinking=false. 생성 조건은 유지했으나 KG·조회·패킷·검사 변경을 묶은 전후 비교이므로 개별 요소의 인과효과를 분리하지 못한다.

3. 확인된 개선과 잔여 문제

- DEV011: 버스 벌써 출발했나? → 버스가 벌써 출발했나예?
- NEW004: 회의가 벌써 시작했나? → 회의가 벌써 시작했나예?
- DEV013: 낼 몇 시에 만나면 될까? → 낼 몇 시에 만나면 될까예?
- DEV001/003: 좋네예·맵네예가 생성됐다.
- DEV006: 계세요의 계사 오분석을 복원하고 계셔예를 생성했다. 시고 등의 개별 어휘형 자연스러움은 별도 검토 대상이다.
- DEV002: 최초 가던 길을 검사해 한 번 수정한 뒤 원문의 가는 길로 복원됐다. 최종은 표준어와 같은 문장이다. 원문 보존을 위해 같은 표현이 남는 것을 자동 실패로 세지 않는다.
- LONG006: 좋아하노 빵은 좋아하는 빵으로 개선됐지만 가노 길은 남았다. 검사기는 이를 감지했으나 Qwen은 한 번 수정 요청에도 같은 문장을 반환했다.
- NEW002 및 ADVCE007A/B: 저는→나는 변경이 남았다. 검사 후 수정 요청에도 동일 출력이 반복되어 미해결로 기록했다.
- ADVCE004A: 원문 평서 문장부호가 질문으로 바뀌었다. 화행 확인이 필요한 경고로 기록했으며 문장부호만으로 자동 수정을 강제하지 않았다.
- LONG008: -지예 후보를 전달해도 힘드셨죠?로 남는다. 후보 회수와 후보 사용은 다른 문제다. 말씀드릴게예는 생성됐고 이전의 말씀드릴래예는 이 출력에 없다.
- LONG003의 모 묵는데는 부정 표현 분석의 불확실성으로 검토 경고가 남는다. 확정 부정 소실로 판정하지 않는다.
- DEV015, 선택 질문, 청유형 등 자동 검사가 충분히 다루지 못하는 표현의 적합성은 추가 검토가 필요하다.

4. 자동 검사 집계: 번역 정확도가 아님

전체70개 중 강한 보존 경고가 있는 입력: 수정전18 → 수정후 최초5 → 한 번 수정 후4.
전체70개 중 강도와 무관하게 경고가 있는 입력: 수정전19 → 최초7 → 최종6.
기존50개 강한 경고 입력: 9 → 3 → 2.
새20개 강한 경고 입력: 9 → 2 → 2.
수정 전후 최초 출력 문자열이 달라진 입력: 46/70. 차이 수는 개선 수가 아니다.

검사기를 생성 결과 확인 후 두 군데 보완했다. 어제 안의 제를 겸양으로 오인하는 부분 문자열 문제와, 가노를 가+어+노/NNG로 나누는 형태 분석으로 인해 관형절 손상을 놓치던 문제다. 해당 회귀 테스트를 추가하고 모든 기준선·수정후 출력에 최종 검사기를 동일하게 적용했다. 최초 생성은 재실행하지 않았으며 입력별 수정 호출은 검사기 개정 전체에서 최대1회였다. 최초 검사기와 당시 결과는 checker_v1에 보존했다. 이 때문에 위 집계는 독립 사전등록 평가 지표로 주장하지 않는다.

5. 실제 전달량: 수정 후70개 입력

후보가 전달된 고유 구간167개 / 입력당평균2.3857개.
구간당후보평균1.7784개.
구간별 후보 배열 평균2,078.69자.
구간 공통정보를 포함한 표현 평균2,532.81자.
같은 진술이 다른 구간에 전달되면 따로 센다. 어휘 구간과 절 구간은 겹칠 수 있다. 문자수는 실제 생성 입력 JSON 직렬화 길이이며 토큰수가 아니다.
이 수치는70개 기준이다. 이전 A/B/C/D50개 통계와 분모가 다르고 여러 정책도 바뀌었으므로 길이 단독 효과로 해석하지 않는다.
후보0개 입력은 수정전7개에서 수정후2개(DEV002,DEV009)로 달라졌다. 새로운0개는 조건 없는 기능 후보를 제외한 결과이며, 필요한 변환 근거를 완전히 회수했다는 뜻은 아니다. DEV002에는 후보가 없어도 별도 관형절 보존 정보가 전달된다.

6. 검사와 한계

- 로컬 회귀 테스트45개 통과. 문헌 원문 인용·전체 페이지 빌드 검사 통과.
- 기존 factorial 실험 JSON 파일들의 해시 유지 확인.
- 수정 전후 KG와 코드 의존성, 최초 생성 시점 코드 해시, 검사기 개정 사유를 protocol.json에 보존했다.
- 기본 경로에는 기존 A 기반 조회를 보완했다. 의미 검색 B/D를 우수하다고 확정하거나 기본으로 승격하지 않았다.
- 같은 입력을 보며 설계한 개발 실험이며 독립 방언 화자 평가가 아니다. 사례 개선과 자동 경고 감소는 보고할 수 있지만 전체 자연스러움 우열이나 일반화 성능은 확정하지 않는다.
- Neo4j 서버와 기존 PNG는 이번에 재적재·재생성하지 않았다. 실제 번역 조회는 새 facts.jsonl/graph.json을 읽는다.
- 이전 상세 브리핑 DOCX는 보완 전 시점 기록이다. 현재 상태를 보고할 때 이 문서를 후속 반영 결과로 함께 읽어야 한다.
