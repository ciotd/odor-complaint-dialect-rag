2026-10-13 종결 기능별 KG 조회·조합 경로 수정

결론
말투 지시 추가가 아니라 생산 조회·전달 코드를 수정했다. 높임 평서·질문·요청·약속과 반말 평서·질문·요청·허용을 구분해 KG 구성요소를 조회하고, 실제 원문 위치에 결속된 완성형 조합안을 생성기에 전달한다.
기존70개 입력으로 조회와 생성 요청 구성까지 검증했다. Qwen을 새로 호출하지 않았으므로 번역 품질이 개선됐다고 주장하지 않는다. 최신 실제 번역 파일은 이 수정 이전의 경북40대 지시 실험이며, 이번 폴더의 표는 조회·조합안이다.

1. 먼저 확인한 실제 원인
- advisory_rules.json에서 -세요→-세예, -나요→-나예, -ㄹ게요→-ㄹ게예가 등록됐고, 조회 우선순위120으로 다른 문헌 후보보다 먼저 선택됐다.
- -(으)이소는 KG에 있었지만 표준어 대응이 -(으)십시오인 항목이라 -세요와의 글자 매칭에 걸리지 않았다. 문장 기능을 통한 조회보다 위 조언이 우선했다.
- -(느)ㄴ교 역시 문법 기능을 통해 조회할 수 있었지만 좁은 표면 대응 조언이 먼저 선택됐다.
- -(으)(ㄹ)께는 KG에 있으나 높임 요가 붙은 -ㄹ게요와 단독 -ㄹ게를 연결하고 예를 결합하는 경로가 없었다.
- 반말 -다/-ㄴ다 등에는 문헌 기록이 있어도 명시적 적용 조건 없는 기능 전용 후보를 제외하는 정책 때문에 그대로 전달되지 않았다. 그 제한을 전면 해제하면 부적절한 후보도 들어오므로, 실제 종결과 문장 기능이 확인된 별도 경로를 만들었다.
- 온나는 KG의 오다 활용형으로 존재하지만 와의 요청 기능에서 해당 활용형으로 가는 경로가 없었다.

2. KG와 원문 근거의 확인 결과

높임 평서 -예
NAMU_HONORIFICS_20260908 full:0124, PDF26: -어/아예와 해예체.
NAMU_GRAMMAR_20260908 full:0702, PDF28: 요/예.
같은 문법 문헌 ending_repair:0001, PDF28·22: 이에요→이라예.
좋네요→좋네예, 나왔어요→나왔어예, 명사 서술의 친구예요→친구라예에 연결한다.

높임 질문 -ㄴ교/는교
NAMU_HONORIFICS_20260908 full:0033·0034, PDF8: 형용사 -(으)ㄴ교, 동사 -(느)ㄴ교.
full:0038, PDF8: 사람인교 예문. 계사 질문의 구성 근거로만 사용한다.
현재 경로는 이 문헌 표기의 -는교를 사용한다. -능교를 별도의 검증된 표기로 새로 만들어 넣지 않았다. 전체 경북 또는40대 이상 모두의 의무형이라는 주장이 아니다.
시제와 주체 높임은 별도로 보존해 출발했나요→출발했는교, 챙기셨어요→챙기셨는교 조합안을 만든다.
할까요 같은 제안·가능성 질문은 단순 정보 질문으로 일괄 바꾸지 않고 까예 계열로 기능을 보존한다. 죠의 확인 의미도 지예로 남긴다.

높임 요청 -(으)이소
NAMU_HONORIFICS_20260908 full:0006, PDF4: 하이소체 명령 어미.
요청으로 확인된 주세요→주이소, 걸으세요→걸으이소, 쉬세요→쉬이소, 하세요→하이소에 연결한다.
일반 평서의 -세요는 같은 요청 경로로 보내지 않는다. 모호하거나 저장 분석과 원문이 충돌하면 보류한다.

약속 -께예
NAMU_GRAMMAR_20260908 full:0711, PDF28: -(으)ㄹ게→-(으)(ㄹ)께.
full:0702의 예 근거와 PDF21의 가보께예 예문을 함께 사용한다.
이번에 PDF21의 예문을 terminal_review:0001, reference_only로 추가했다. 새 동사 전체의 확인형이라고 주장하지 않는다.
볼게요→보께예, 드릴게요→드리께예, 기다릴게요→기다리께예 등의 조합안을 전달한다.
JO2018에 나오는 -께예 목록·간께예 문장을 곧바로 약속의 대역 예문으로 해석하지 않았다. 기능이 불분명한 목록과 실제 약속·의도 예문을 구분했다.

반말 평서 -다/-ㄴ다
JO2018 declarative:0105·0106, PDF109(인쇄97): 경북 해라체 서술 어미 목록과 설명.
샀어→샀다, 했어→했다, 좋아→좋다로 연결한다. 시제와 주체 높임을 원문 형태에서 보존한다.
표준어와 공유하는 종결형이며 이 형태만으로 경북 방언성을 입증하지 않는다.

반말 질문 -나/-노
JO2018 interrogative:0096·0098, PDF145(인쇄133): 질문 종류와 시상 결합 설명.
판정 질문 했어?→했나?, 의문사 질문 왜 했어?→왜 했노?를 구별한다.
의문 유형이 미확인인 경우에는 어느 쪽도 확정하지 않는다. 명사 서술 질문 등 이번 분기가 지원하지 않는 구성은 기존 별도 경로에 남는다.

반말 허용 해도 돼→해도 된다
직접적인 방언 대역 쌍을 이번 확인 범위에서 찾았다고 주장하지 않는다. 위 평서 어미 근거와 원문의 되다·-어도 허용 구성을 연결하는 분석자 조합이다.
원문의 해도 부분과 부정은 그대로 보존한다. 해도 돼?는 질문 경로에서 해도 되나?로 구별된다. 모든 돼를 허용 표현으로 분류하지 않는다.

반말 요청 온나·-라
JO2018 imperative:0064, PDF169(인쇄157): 오다와 -ㄴ나 결합 및 온나 예문.
imperative:0053, PDF167(인쇄155): 동사 명령의 -라 및 하지 마라 관련 예문.
요청의 천천히 와→천천히 온나를 연결하고, 동생이 와라는 설명이나 동생이 와?라는 질문을 온나로 바꾸지 않는다.

보조 근거 추가
NAMU_HONORIFICS_20260908 PDF9의 할무이 좋아 하시예? 예문도 reference_only로 저장했다. 해당 원문은 하동 예시이며 경북 사용의 직접 증거로 바꾸지 않았다.
KG 지식 항목3765→3767개. 노드25808→25818개, 관계35396→35410개. 새 노드·관계 유형은 만들지 않았다.
문헌의 가세예 기록은 삭제하지 않았다. 이번 운영 정책에서 -세요의 기계적 -세예 변환 후보를 제거한 것이다.

3. 구현한 구조
원문 종결 위치·문장 기능·높임 확인
→ terminal_retrieval.py에서 기능별 KG 근거 선택
→ 원래 지식 항목의 적용 조건 검사
→ 어간·과거·주체 높임을 보존한 조합안 계산
→ source_span/source_text/preferred_surface/supporting_fact_ids를 생성 입력에 포함

선택 후보는 PLAN:terminal:*라는 요청별 조합 기록이다. 실제 문헌 지식의ID와 페이지를 별도로 보존한다. PLAN 기록을 새 문헌 확인형으로 영구 KG에 섞지 않는다.
새 route는 function_bound_terminal, 우선순위150이며 한 종결에 대표 계열을 선택한다. 선택 후 같은 끝에 일반 요→예 조언과 다른 기능의 어미를 중복 전달하지 않는다.
동사의 활용은 원문의 표면형과 Kiwi 결합을 이용한 분석자 조합이다. 새로운 동사의 완성형 전체가 원문에 있다는 뜻이 아니며, 표준어 중심 형태 도구의 한계는 남는다.
인용 구성과 종결 계획이 겹치면 “보고 동사의 어미 어를 그대로 유지”와 “했다로 종결”이 서로 충돌하지 않도록 전달 계획을 연결했다. 카- 축약 전체의 생성 성공을 검증한 것은 아니다.
이전에 채택한 모델 조언에서 세예/으세예/나예/ㄹ게예/을게예의 매핑을 비활성화하고 변경 이유를 남겼다.

4. 실제 검증
기존70개 분석을 재사용하고 현재 코드로 조회와 생성 요청을 다시 작성했다. system과 Qwen 설정은 기존 인용·의도 조회 실험과 동일하며 경북40대 지시를 추가하지 않았다.
선택·전달된 새 종결 구간79개. 세예·게예 계열의 종결 후보0개. 모든 자료 묶음이24000자 예산 이내다.
새로운 동사와 반례, 최초70개 실제 요청까지 포함한72개 테스트를 통과했다. 문헌 전체 빌드의 스키마·인용문 포함 여부 검사를 통과했다.
높임 평서21, 높임 의문8, 높임 요청8, 높임 약속10, 양태·확인 높임7.
반말 평서9, 반말 의문5, 반말 요청8, 반말 허용1, 반말 약속2.
요청70개가 달라진 것은 공통 전달 정책 문구 변경까지 포함한 값이다.70개 모두 새 종결 후보가 생겼다는 뜻이 아니다.

5. 보류·미완료
ADVCE004A의 원문 “선생님은 매일 이 길로 걸으세요.”를 이전 Qwen 분석이 질문으로 분류했다. 자동으로 질문·요청을 강제하지 않고 보류하며, 원문과 분석의 불일치를 생성용 보존 정보에도 남긴다. 이 문장의 분석 오류를 완전히 고친 것은 아니다.
명사 서술·부정 서술·선택 질문 등 모든 반말 종결을 새 경로로 처리한 것은 아니다. 함수가 지원하지 않는 형태에는 기존 경로가 남는다.
까예 등의 제안·추측 질문을 무조건 는교로 치환하지 않았다. 높임 등급·지역 사용의 세밀한 적합성은 별도 검토 대상이다.
현재 계획은 원래 표준어 어간 기준이다. 먹다→묵다 같은 어휘 후보를 함께 선택하면 새 어간에 맞게 적용해야 한다. Qwen이 계획을 무시하거나 계획 밖 구간을 바꾸는 문제가 없어졌다고 보증하지 않는다.
이번 변경은 생성 이전 단계까지 검증했다. 새 Qwen 결과·번역 품질 평가는 아직 없다.
