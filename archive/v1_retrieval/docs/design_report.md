## 1. 서론

### 1.1 연구 배경

- **동기(응용 맥락).** 지자체 악취 민원은 주로 전화로 접수되고, 지역에 따라 방언·구어체가 쓰여
  일반 STT·키워드 추출이 잘 안 될 수 있다. 이를 개선하려면 방언 통화 데이터가 필요하다.
- **데이터 부족.** 실제 방언 악취 민원 데이터는 개인정보·수집 비용 때문에 확보가 어렵다
  → **합성 데이터**가 현실적 대안.
- **본 연구 범위(명확화).** 본 연구는 **방언 대화 "텍스트" 합성과 그 평가**에 한정한다. STT·키워드
  추출 개선은 이 연구의 동기일 뿐 직접 실증 대상이 아니며(downstream=future work), 음성(TTS)
  변환도 범위 밖이다.
- **상용 API의 한계.** 상용 API(예: Claude Opus) + few-shot으로 자연스러운 방언 텍스트 생성은
  가능하나, (a) 비용, (b) 모델 버전 변경 시 동일 프롬프트라도 출력이 달라짐, (c) 정책 변경·서비스
  종료 가능성 → **장기적 재현성**이 낮다.
- **로컬 대체와 열린 가설.** 이에 로컬 오픈소스 LLM으로 대체하고자 하나, 로컬 모델은 방언 내재
  지식이 약해 품질 저하가 예상된다. → **가설:** 웹 자원 기반 방언 지식을 주입(few-shot / RAG DB
  검색)하면 이 결핍을 보완할 수 있는가? (해결책 단정이 아니라 검증 대상)
- **평가 문제.** 방언 화자 인간 평가는 비용·섭외가 어렵다 → 인간 평가 없이 조건을 비교하는
  **자동 진단 지표**가 필요.

### 1.2 기여

1. 상용 API·파인튜닝 없이 로컬 LLM + 방언 지식 주입으로 5권역 방언 악취 민원 대화 합성
   파이프라인(S1 직접생성 / S2 2단계 변환) + 지식 공급 조건 설계.
2. 5권역(경상·전라·충청·강원·제주) 방언 악취 민원 대화 데이터셋.
3. **합성 교란으로 신뢰성을 검증한** reference-free 자동 진단 지표(방언율·누수율).

## 2. 관련 연구

- **한국어 방언 자원/NLP** — 방언 벤치마크에서 한국어 변종이 특히 저조(DialectBench 등).
- **LLM 기반 합성 데이터 생성(저자원·대화)** — DiaSynth, 저자원 LLM 데이터 생성 전략 연구
  (타깃언어 예시 + LLM 수정이 강력하다는 보고 → 본 연구 few-shot 우위와 연결).
- **RAG for controllable generation** — Lewis et al. (2020) 등 지식 주입 생성.
  Bengali 표준→방언 RAG 번역 비교(arXiv 2512.14179) 등 저자원 방언에 RAG 적용 사례.
- **어미/표지 기반 방언 식별·평가** — Stable Lexical Marker Analysis(코퍼스 기반 어휘변이 마커),
  Dialect-robust Evaluation(ACL 2023), CTRLEval(reference-free 제어생성 평가, ACL 2022).
  LLM-as-judge(A단계 독립 참조 근거).

### 2.1 가장 근접한 선행연구 — DIA-REFINE (반드시 인용·차별화)

**DIA-REFINE**(arXiv 2511.06680, "Steering LLMs toward Korean Local Speech")는 한국어 방언을
LLM으로 생성/변환하고, **Dialect Fidelity Score(DFS)**·**Target Dialect Ratio(TDR)**로 방언성을
자동 측정한다. 우리의 방언율/누수율과 목적이 겹친다. → **본 연구의 자동 지표는 신규성으로 주장하지
않으며, DIA-REFINE을 인용하고 도구로만 사용**한다.

**차별점(본 연구가 다루고 그들이 다루지 않은 것):**
1. **과제·도메인:** 그들은 단문 표준→방언 *번역*, 본 연구는 공공 민원(악취) **다중턴 대화 생성**.
2. **지식 주입(KB/RAG) 비교:** 그들은 KB·RAG 없이 BM25 예시 검색만. 본 연구는 **어휘+문법 KB
   검색·주입(C_kb)**을 few-shot과 분리 비교 — "**RAG가 few-shot을 넘는가**"는 그들이 안 던진 질문.
3. **지표 방식:** 그들은 학습된 분류기(라벨 5만)+임베딩. 본 연구는 **학습 불필요 어미 마커**(경량·투명).
4. **범위:** 그들 3권역(전라·경상·제주), 본 연구 **5권역**(+충청·강원) · **로컬 오픈소스 전용**.

*(인용 서지·연도 최종 대조 필요.)*

## 3. 제안 방법

### 3.1 시스템 구조
- **입력:** 시나리오 파라미터 5개 — 냄새 종류, 민원인 위치, 강도 변화, 지속시간, 원인 추정지역.
- **출력:** 5권역(경상/전라/충청/강원/제주) 8~10턴 방언 상담 대화(상담원 표준어 ↔ 민원인 방언).

### 3.2 방언 지식베이스 (RAG DB)
- **어휘(vocab):** 웹 사전 → `{표준, 방언, 품사}` 구조화. 검색=표제어 정확 매칭.
- **문법 규칙(rule):** 문법서·문헌 → `표준형→방언형` + 설명. 검색=형태소 BM25.
- **✅ 5권역 전부 RAG DB 보유(개정):** 제주 RAG DB를 편입해 4권역 → **5권역**으로 확장.
  제주는 어휘 `jeju_vocab_v2` **13,508개**(오염된 final 제외) + 문법 30개 사용.
  ⚠️ 제주 문법은 웹 수집 자료 파생 → 투고 전 학술 근거 보강 필요.
- **평가용 마커 (v3, 2026-08-14):** AI-Hub **1인+2인 발화** 5권역 통합 추출 → (표준꼬리→방언꼬리)
  변환쌍. 채점 마커 78→**287개**로 확대(존댓말 대폭 보강: 경상 니더/심더, 충청 겄슈/시유,
  전라 당께/겄소, 제주 마씸/쿠다, 강원 시래요/래요 — 이전 수동보완이 코퍼스로 확인됨).
  1인발화 노이즈(정렬 오류·말더듬·숫자)는 어절수-동일 정렬+숫자제외+노이즈 블록으로 차단.
  ⚠️ v3 마커로 방언율·누수율 절대값 상승(마커 증가분) → 통계 재검정 필요(핵심 결론 few-shot 지배는 유지).

### 3.3 합성 파이프라인 (핵심)
- **S1 (Single-Stage, 주력):** 조건별 지식 주입 후 방언 대화 직접 생성. 쿼리 없어 엄밀히는
  "지식 주입".
- **S2 (Two-Stage, 대조):** 표준어 생성 → 방언 변환. 쿼리(표준어) 기반 실제 검색 성립.
  변환 압력에 의한 누수·hallucination 대조군.
- **지식 공급 조건:** C0(zero-shot) / C1(고정 few-shot) / C_kb(RAG DB) / C_kb+C1(RAG DB+few-shot).
  C1은 "예시가 있어서"의 효과를 "검색 때문"과 분리하는 필수 대조군.
- **프롬프트:** 한국어 전용(외국어 금지), 민원인 존댓말, 타권역 어미 누수 금지, 발화자 라벨 형식.

### 3.4 자동 진단 지표
- **마커:** (표준꼬리→방언꼬리), 필터(빈도≥8·변별력). 코퍼스 자동추출 + 존댓말 표지 수동 보완
  → 현재 **78개**(전라 당께/랑께·제주 수다/마씸 등 보완 포함).
- **방언율** = 타깃 마커 적중 / 총어절, **누수율** = 타권역 마커 적중 / 총어절.
- S1 표면 접미 매칭 / S2 표준↔방언 정렬 어절쌍 매칭. false positive 방지(1자 마커 받침조건,
  표준어 동형 제외).
- **명시:** 조건 간 **상대 비교용 진단 도구**이며 절대 품질 척도가 아님.

### 3.5 지표 신뢰성 검증 — A단계 (신규)
- 인간 라벨 없이 지표를 검증: 정상 생성문을 **채점기와 독립인 참조 모델(Claude)** 로 오염시켜
  지표 반응 측정.
  - 표준어화(방언 제거) → 방언율 하락해야 함(민감도).
  - 타권역화(다른 권역으로) → 소스 방언율 하락 + 누수율 상승해야 함(특이도).
- 채점기(어미 사전)와 오염기(Claude)가 독립이라 순환성 완화. Claude는 **평가용 독립 도구로만**
  사용(생성은 로컬 Qwen 전용, 요지 불변).

## 4. 실험 (예비 결과)

> ⚠️ 아래는 **예비 결과**다. 권역당 n=10으로 작아 전체 묶은 결론(few-shot 지배)은 유의하나
> 권역별 세부는 경향 수준. RAG DB 검수·n 확대 후 확정 예정(7절).

- **세팅:** (본실험 갱신) Qwen3.8-27B-FP8(로컬 vLLM). **n=100**, 5권역 × 4조건, 시드 고정. S1/S2 동일
  · (아래 수치는 파일럿 n=50/Qwen3.6 기준 — 최신 수치는 research_scope §10 참조)
  시나리오.
- **결과(예비, 전체 평균):** 방언율↑ 좋음, 누수율↓ 좋음(타권역 어미 오염 적을수록).

| 파이프라인·지표 | C0 | C1 | C_kb | C_kb+C1 |
|---|---|---|---|---|
| S1 방언율 | 0.003 | **0.071** | 0.018 | 0.070 |
| S1 누수율 | 0.007 | **0.003** | 0.007 | 0.004 |
| S2 방언율 | 0.032 | **0.157** | 0.044 | 0.098 |
| S2 누수율 | 0.040 | 0.017 | 0.019 | **0.010** |

- **누수율 해석:** few-shot·결합 조건에서 누수율이 낮다(타권역 오염 억제). **S2가 S1보다 누수율이
  전반적으로 높다**(예: C0 S2 0.040 vs S1 0.007) — 표준어→방언 변환 압력이 타권역 어미 혼입을 키움.
- **통계 검정(부트스트랩 CI + 시나리오 짝지은 검정, 신규):**
  - few-shot 우위 유의 — 두 파이프라인 모두 C1 > C0·C_kb (p<0.001).
  - **C1 vs C_kb+C1:** S1 **동률(ns, p=0.54)**, S2 **C1이 유의하게 높음**(RAG DB가 오히려 방해).
  - RAG DB 단독: S1 C_kb>C0 유의 / S2 C_kb≈C0 ns.
- **A단계 지표검증:** 민감도 0.96·특이도 0.96, 타권역화 시 누수 검출(+0.09), 타권역화한 문장을
  타깃권역 방언으로 인식(수렴 타당도).
- **정성 예시(실제 생성 발췌, 민원인 발화):**
  - (성공, S1 충청 C_kb+C1) "…이상헌 냄새가 너무 심해서 못 견딜 겨라 연락해드린 거**라우**. …
    창문을 다 닫아두 밖에서 확 들어오니**께** 참말로 답답**혀유**." → 충청 방언형 자연 실현.
  - (성공, S1 경상 C1) "…도저히 못 견디겠어**예**. … 접착제 냄새 같은 **기라예**." → 경상 종결형.
  - (지표 한계, S1 강원 C_kb+C1) "…거름 냄새가 하도 심해서 전화**했잖소**. … 거름 냄새**래요**. …
    코까지 저리우**니더**." → 강원 방언은 뚜렷하나 방언율 지표는 ~0(어미 지표 맹점).
  - (외국어 혼입, S1 경상 C0) "…한 시간마다 **开窗**해볼까 해도…" → 로컬 모델 code-switching.
  - (누수, S2 경상 C0) "…냄새가 나**소라**. … 그거 맞**소라**." → 경상 대화에 비경상 종결형 혼입.

## 5. 논의

- **핵심 발견(예비 — 기대와 다름):** 원래 가설은 "RAG DB가 방언성을 높인다"였으나, 예비 실측은
  **few-shot(C1)이 주 동력이고 RAG DB를 얹어도 few-shot을 넘는 추가 이득이 없음**(S1 동률, S2 방해).
  즉 로컬 모델 방언 유도에는 검색된 지식 조각보다 **완결된 예시**가 더 강한 신호. 단 이 결과는
  RAG DB 미검수(아래)와 얽혀 있어, 검수 후 재검증이 필요.
- **왜 RAG가 약한가 — 원인은 아직 단정 불가(복수 가설).** RAG 추가 이득이 없다는 결과의 원인은
  하나로 귀결되지 않으며, 최소 아래를 구분해야 한다.
  1. **RAG DB 품질·형식**(검수 미비 → 표준형 오염·빈 폼). ← 현재 가장 유력한 가설.
  2. **정보량 부족**(도메인 커버리지 낮아 검색해도 쓸 항목이 적음).
  3. **검색 방식**(어휘 정확매칭·규칙 BM25·top-k·쿼리 구성이 부적절).
  4. **주입 방식**(검색 결과를 프롬프트에 넣는 형식이 비효율).
  5. **모델 활용 실패**(few-shot이 더 강한 신호라 검색 지식을 무시).
  → 현 단계 데이터로는 이들을 분리 못 함. 다음 단계에서 **①을 검수로 먼저 제거**한 뒤, 그래도
  이득이 없으면 ②~⑤를 점검한다(7절). "자원 문제"는 유력 가설일 뿐 확정 결론이 아니다.
- **강원/제주 구분(재개정):**
  - 제주는 존댓말 표지(-수다/-마씸/-쿠다) 보완 후 정상 측정(0.10대). 지표 맹점이었고 보완으로 해결.
  - 강원 저측정은 **부분적으로 데이터 subset 탓**이었음(2026-08-13 확인). 지금까지 2인발화만 썼는데,
    미사용 **1인발화(질문에답하기)에 강원 어미 방언이 풍부**함 — 재추출 시 -세요→-시래요, -습니다→-니더,
    -다→-데이 등 강한 종결 마커 32k토큰 확보(2인발화의 ~28배). 단 (a) 영동 강원 특징이 경상과 겹쳐
    변별력 재계산 필요, (b) 같애요/엣날 같은 **음운·철자 변이는 여전히 어미 마커로 포착 불가** →
    임베딩 보조 지표 필요(7절).
- **로컬 LLM 한계:** 한국어 전용 지시에도 40~50% 대화에 외국어 혼입(code-switching) → 후처리 필터
  필요. 상용 대비 로컬의 실질 비용.

## 6. 한계

  함 → RAG 가용 형태 아님. 단 검색 약함의 유일 원인으로 단정 불가(정보량·검색·주입·모델 활용과 미분리).

## 7. 다음 단계 (계획)

현재는 예비 결과이며, "RAG 효용 없음"이 **방법 탓인지 자원 품질 탓인지**를 가리는 것이 핵심.
아래 순서로 진행(순서 중요 — 뒤 단계는 앞 단계 선행 필요).

1. **RAG DB 재검수 (근본원인 대응).** 기준을 "문법이냐"가 아니라 **"주입해 모델이 쓸 수 있냐"**로.
   - **어미 규칙 → 유지**: 코퍼스 마커(v3)로 확인되거나 category가 경어법/연결어미인 것.
     (코퍼스 대조 결과 어미 코어는 5권역 합쳐 ~37개뿐 — 나머지는 대부분 음운·어휘.)
   - **어휘성 규칙 → 어휘 DB로 이관**(버리지 말 것): 단어 치환(들어가다→드가다, 어떡해→우야꼬)은
     문법이 아니라 어휘 → `{head, dialect}`로 vocab에 편입.
   - **음운 규칙 → 저효용**: 음운도 문법 체계의 일부지만, 추상 글자치환이라 LLM이 프롬프트로
     적용하기 어렵고 top-3 검색 슬롯만 차지 → 유지 시 어미 규칙을 밀어냄. (단 이는 미검증 가설.)
   - 문법 규칙 빈 폼 제거, 출처를 학술 근거로 보강.
   - **⚠️ C_kb 조건 설계 변경 (확정):** RAG 검색 결과를 **"규칙만"이 아니라 "규칙+예문"으로 주입**
     (actionable). 근거: RAG가 약했던 원인이 "규칙이 앙상해 모델이 못 씀"일 수 있고, 실제 RAG는
     예시도 함께 검색하는 게 자연스러움. 주입 포맷 `표준형→방언형 (설명) [예: 표준→방언]`.
     트레이드오프 명시: (a) "검색 vs 예시" 기여 분리는 포기(질문이 "실용 RAG가 도움되나"라 허용),
     (b) 문법 예문은 LLM 생성 합성물 → 논문에 명시. C1(악취민원 도메인 대화)과는 종류가 달라
     C1↔C_kb 구분은 유지됨. 구현: 현재 분리된 grammar_examples를 규칙에 재결합. (서버 복구 후 재실험)
2. **지표 개선.**
   - (우선) **강원 마커 보강** — 미사용 1인발화(질문에답하기) 재추출로 강원 어미 마커 확보(-시래요 등).
   - 방언율 분모를 전체 어절 → **종결 위치 어절**로(희석 완화), 빈도 컷오프(8) 민감도 분석.
   - (후순위) **임베딩 보조 지표** — 마커(주, 어미·투명)가 못 잡는 음운·철자 변이(같애요/엣날)를
     보완하기 위해 **학습 없는 임베딩 거리**(`cos(생성문, 표준어)`가 작을수록 방언성↑)를 보조로 병기.
     학습 분류기(DIA-REFINE식)는 GPU·파생성 부담으로 제외, 학습 불필요 경량 방식만.
3. **대규모 재실험.** 검수·지표 확정 후 **n=100~150** 단일 실행(권역별 통계 강화).
4. **모델 능력 비교(threshold 가설).** 상용 API + 파라미터 작은 Qwen 여러 개로, **"모델이 약해지면
   RAG가 의미있어지는 지점"** 이 있는지 검증. ⚠️ 검수된 RAG DB(1) 선행 필수 — 안 그러면 "RAG 무효"가
   모델 탓인지 자원 탓인지 구분 불가(confound).
